### ВертикальныйОтступ

Задает вертикальный отступ карточки от ее содержимого. По умолчанию `Авто` — `РазмерОтступа.Одинарный` (в мобильном интерфейсе `РазмерОтступа.Половинный`).

### Групповая

`Авто|Булево`. `Истина` — карточка отображается в виде стопки.

### ОбрабатыватьНажатие

- `Авто`
  
  — значение по умолчанию, поведение при нажатии определяется системой;
- `Истина`
  
  — карточка принимает вид нажимаемой кнопки, обрабатывает нажатие (вызывает событие
  
  [ПриНажатии](custom-card-component-b505ea7a5b7d.md)
  
  ), может принимать фокус;
- `Ложь`
  
  — обычная карточка, не обрабатывает нажатие, не принимает фокус.

### ВыравниваниеВГруппеПоВертикали

Способ вертикального выравнивания этого компонента внутри родительской группы:

- `Авто`
  
  — значение
  
  `ВыравниваниеПоВертикали.ПоБазовойЛинии`
  
  ;
- элементы перечисления
  
  `ВыравниваниеПоВертикали`
  
  —
  
  `Верх`
  
  ,
  
  `Центр`
  
  ,
  
  `Низ`
  
  ,
  
  `ПоБазовойЛинии`
  
  .

Позволяет управлять индивидуальным положением этого компонента в группе, если размер группы больше размера, требуемого всем ее компонентам. Например, если «Элемент» растягивает группу, а компоненты в ней не растягивает.

Для компонента, расположенного внутри вертикальной группы, это свойство имеет смысл только в том случае, если этот компонент крайний. Например, если компоненты группы расположены вверху, то последний компонент можно расположить внизу.

Пример вертикального выравнивания: первые два компонента расположены у верхнего края вертикальной группы, последний — у нижнего. [Описание иллюстрации](../../raw/figures/c9b6e381c8c97fa30e6432d1701f80e520b7716fc134a499fc30ec1b46936b80-d1cae524ff431c82.md)

Если у компонентов внутри группы указаны разные способы вертикального положения, которые входят в конфликт друг с другом, то «Элемент» будет использовать для всех конфликтных компонентов тот способ, который указан у первого из них. Например, если у первого конфликтного компонента в группе указано положение `Низ`, а у второго — `Верх`, то оба компонента окажутся внизу.

Пример конфликта вертикального выравнивания: у второго компонента задано «Низ», у третьего — «Верх». [Описание иллюстрации](../../raw/figures/3ff4b64f82a737d0c02aeba39b29550b97f42ffe1d03d2eb5be1c50cc604b5f2-0bfb279a636f5778.md)

### ТолькоЧтение

Запрет редактирования данных компонента. Если флажок установлен, то компонент может принимать фокус, его данные можно просматривать и копировать. В этом состоянии некоторые компоненты могут сохранять свою интерактивность, которая не влечет за собой изменение каких-либо данных. Состояние `ТолькоЧтение` распространяется на все компоненты содержимого, пока не встретится переопределение этого свойства. Имеет более низкий приоритет, чем свойство `Доступность`.

### Ширина

`Авто|Число`. Ширина компонента в пикселях ([подробнее](arrange-components-on-screen-ebea0719d919.md)).

Если `Авто`, то рассчитывается автоматически. Явно заданное значение ширины применяется, только если оно отлично от 0 и [РастягиватьПоГоризонтали](custom-card-component-b505ea7a5b7d.md) равно `Ложь`.

### ШиринаВКолонках

`Авто|ШиринаВКолонках`. Ширина компонента в [колонках](widthincolumns-ru-f14525640914.md). Если `Авто`, то рассчитывается автоматически.

### <Свойство разработчика>

Собственное свойство компонента, добавленное разработчиком. Описывается следующими свойствами:

#### ЗначениеПоУмолчанию

Стандартное значение свойства. Значение можно не указывать, если у его типа/типов есть значение по умолчанию (в частности, если его тип включает `Неопределено` или `Null`). Если тип свойства составной (включает несколько типов), необходимо указать тип значения. Иначе просто само значение.

В [описании экземпляра](system-and-interface-components-18287074edda.md) этого компонента вы можете установить другое значение этому свойству.

#### Имя

Имя свойства.

#### Контекстное

`Булево`. Признак доступности значения свойства на клиенте и сервере. Значение по умолчанию — `Ложь`. Если `Истина`, то поле **Тип** свойства должно содержать тип, доступный на клиенте и сервере.

«1С:Предприятие.Элемент» генерирует структурный тип [`{ИмяКомпонента}.Контекст`](componentname-context-ru-e40a3f370a75.md), который содержит как собственные контекстные свойства, так и контекстные свойства, наследуемые от базовых системных типов. Этот тип генерируется всегда, даже если контекстные свойства отсутствуют.

Пример:

```yaml
Имя: МойКомпонент
Свойства:
    -
        Имя: КонтекстноеСвойство
        Тип: Строка
        Контекстное: Истина
```

Для работы с контекстными свойствами на сервере вы можете использовать *контекстные серверные методы*. Эти методы должны располагаться в модуле компонента интерфейса и содержать аннотации [`@Контекстный`](../stdlib/contextual-ru-468258bf9c74.md) и [`@НаСервере`](../stdlib/onserver-ru-ff4072dae1ed.md). В теле метода тип объекта `этот` заменяется на [`{ИмяКомпонента}.Контекст`](componentname-context-ru-e40a3f370a75.md). Состояние этого объекта передается с клиента на сервер при каждом вызове метода. На сервере в теле метода вы можете изменить состояние объекта. Измененное состояние будет автоматически передано на клиент, и компонент будет инициализирован заново с учетом внесенных изменений.

Пример изменения значения контекстного свойства на сервере:

```xbsl
@НаСервере @ДоступноСКлиента
@Контекстный
метод КонтекстныйМетод()
    этот.ПолучитьТип() // Вернет "ИмяКомпонента.Контекст"
    // Задание значения контекстного свойства на сервере
    КонтекстноеСвойство = "Значение"
;
```

#### СохраняемыеДанные

`Истина` — при изменении значения этого свойства «Элемент» установит свойство `СобственнаяМодифицированность` компонента в значение `Истина`. После записи данных вы должны самостоятельно присвоить свойству `СобственнаяМодифицированность` значение `Ложь`.

#### Тип

Тип свойства.

### <Событие разработчика>

Собственное событие компонента, добавленное разработчиком. Здесь вы описываете только само событие, обработчик этого события необходимо назначить при [описании экземпляра](system-and-interface-components-18287074edda.md) этого компонента. О вызове и назначении обработчиков собственных событий компонента можно прочитать [здесь](component-example-077c0c8b7fb0.md). Каждое событие описывается следующими свойствами:

- Имя
  
  — имя события.
- Тип
  
  — тип объекта события:
  
  - тип должен быть наследником типа
    
    `СобытиеКомпонента`
    
    ;
  - если значение не указано, то тип события —
    
    `СобытиеКомпонента`
    
    .

## События

### ПриНажатии

Возникает при нажатии на карточку, если свойство [ОбрабатыватьНажатие](custom-card-component-b505ea7a5b7d.md) установлено.

Пример YAML-файла:

```yaml
ВидЭлемента: КомпонентИнтерфейса
ОбластьВидимости: ВПодсистеме
Ид: e7cd96f0-5845-4aaa-b67e-324c1b702c91
Имя: МояСтандартнаяКарточка
Наследует:
    Тип: СтандартнаяКарточка
    ПриНажатии: ОбработчикПриНажатии
```

Сигнатура обработчика события:

```xbsl
метод ОбработчикПриНажатии(Источник: Карточка, Событие: СобытиеПриНажатии)
    // Обработка события...
;
```

### ПослеСоздания

Переопределяемый обработчик. Предназначен для дополнительной инициализации свойств экземпляра компонента на клиенте и вызова прикладной логики инициализации экземпляра компонента. Выполняется после полного конструирования экземпляра компонента, т. е. когда:

- установлены значения свойств экземпляра компонента, указанные при
  
  [описании экземпляра](system-and-interface-components-18287074edda.md)
  
  ;
- созданы свои компоненты данного экземпляра;
- значения свойств своих компонентов установлены из описаний их экземпляров;
- подключены обработчики событий в экземпляре компонента и в экземплярах его внутренних компонентов.

Сигнатура обработчика:

```xbsl
@Обработчик
метод ПослеСоздания()
// Обработка события...
;
```

### ПриНаведении

Назначаемое событие. Вызывается при наведении указателя мыши на область компонента. Особенности вызова события:

- При наведении указателя мыши на вложенные элементы событие
  
  ПриНаведении
  
  сначала вызывается для родительского элемента, а затем для дочернего.
- Событие не поддерживается на мобильных устройствах.

Когда указатель мыши покидает область компонента, вызывается событие **ПриПотереНаведения**.

### ПриПеретаскивании

Назначаемое событие. Возникает по окончании перетаскивания на область компонента. Если в обработчике события свойство `СобытиеПриПеретаскивании.СтандартнаяОбработка` не равно `Ложь`, то происходит системная обработка события, после чего «Элемент» вызывает событие у родительского компонента, вплоть до компонента, унаследованного от `КлиентскоеПриложение`. На данный момент поддерживается только перетаскивание файлов из проводника на область компонента.

### ПриПотереНаведения

Назначаемое событие. Вызывается, когда указатель мыши покидает область компонента. Особенности вызова события:

- Если событие срабатывает для вложенных элементов (курсор смещается за пределы родительского элемента), то сначала оно вызывается для дочернего элемента, а затем для родительского.
- Событие не вызывается при удалении компонента, изменении его видимости или размера (если в результате указатель мыши больше не находится над областью компонента).
- Событие не поддерживается на мобильных устройствах.

При наведении указателя мыши на область компонента вызывается событие **ПриНаведении**.

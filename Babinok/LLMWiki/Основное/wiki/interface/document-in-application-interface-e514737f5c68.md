## Обзор

Во время работы приложения «1С:Предприятие.Элемент» автоматически генерирует все команды и формы, которые требуются для работы с объектами **Документа**.

## Документированный контракт и примеры

Во время работы приложения «1С:Предприятие.Элемент» автоматически генерирует все команды и формы, которые требуются для работы с объектами **Документа**. Однако они могут не подходить вам в каких-то сложных или особенных случаях. Тогда вы можете создать в проекте собственные формы и задать собственные представления команд.

Для этого используйте группу свойств документа — [Интерфейс](../data/document-4eb9c3e92277.md).

## Добавление команд в автоматический интерфейс

«1С:Предприятие.Элемент» добавляет в [автоматический интерфейс](auto-generated-ui-7150689c0714.md) приложения команды открытия списка объектов **Документа** и команду создания объекта **Документа** (например, для документа **Накладная**):

- `Накладная.ОткрытьСписок`
- `Накладная.СоздатьОбъект`

Если вы не хотите, чтобы пользователь мог самостоятельно работать с данными **Документа** (например, это служебный документ), то вы можете отключить добавление этих команд в автоматический интерфейс. Для этого в проекте используйте свойство [ВключатьВАвтоИнтерфейс](../data/document-4eb9c3e92277.md).

## Представление автоматически добавленных команд

Команды, которые «1С:Предприятие.Элемент» автоматически добавляет в интерфейс приложения, в качестве своего представления используют имя документа в проекте. Например, для документа **Накладная** в интерфейсе приложения будет две команды:

- Накладная
  
  — это команда перехода к списку объектов документа
- Накладная
  
  — это команда открытия формы нового объекта документа

Это стандартное поведение «Элемента», но оно, как вы видите, не очень удачное. Команду открытия списка документов хочется назвать в множественном числе — **Накладные**.

Другой пример, когда для автоматически добавленной команды хочется иметь другое представление — это когда название документа в приложении является самостоятельным термином. Например, в проекте есть документ **Накладная**, но в приложении он должен называться **Расходная накладная**.

В этих случаях вы можете в проекте задать свойства документа **Интерфейс.Список.Представление** и **Интерфейс.Объект.Представление**. Представление списка «Элемент» будет использовать в качестве представления команды `имя-документа.ОткрытьСписок()`, а представление объекта — в качестве представления команды `имя-документа.СоздатьОбъект()`.

> [!TIP] совет
> Свойства **Интерфейс.Список.Представление** и **Интерфейс.Объект.Представление** поддерживают [локализацию](../project/app-localization-15f5b1317f82.md). Чтобы задать идентификатор локализованной строки, необходимо вначале использовать символ «$», например: `$МояПодсистема::МоиЛокализованныеСтроки.Строка1`.

## Формы документа

Во время работы приложения «Элемент» автоматически сгенерирует формы для работы с объектами **Документа**: форму объекта и форму списка объектов. Однако эти формы могут быть не всегда удобны. Кроме того, если вы хотите реализовать собственную логику работы формы объекта или формы списка объектов, то изменить работу форм, сгенерированных автоматически, вы не можете.

Поэтому, если автоматические формы вас не устраивают или если вам нужна собственная логика их работы, вы можете создать нужные вам формы в проекте, а затем указать, что **Документ** должен использовать именно эти формы. Для этого используйте свойства **Интерфейс.Объект.Форма** и **Интерфейс.Список.Форма**.

Кроме того, автоматические формы объекта и списка можно создать в коде с помощью приведенных ниже методов.

### СоздатьФормуОбъекта

Сигнатура:

```xbsl
СоздатьФормуОбъекта(Ключ: {ИмяДокумента}.Ссылка? = Неопределено): ФормаОбъекта<ИмяДокумента.Объект, неизвестно>
```

Например:

```xbsl
Накладная.СоздатьФормуОбъекта()
```

Создает форму объекта документа. Если документу назначена форма объекта, то будет создана форма именно этого типа. Иначе будет создана автоматическая форма типа `<ИмяДокумента>.АвтоматическаяФормаОбъекта`.

Возвращает нетипизированную форму объекта.

Опциональный параметр `Ключ` определяет, какой объект будет редактироваться в форме. Если в качестве значения ключа передано `Неопределено`, то будет открыта форма нового объекта.

### СоздатьФормуСписка

Сигнатура:

```xbsl
СоздатьФормуСписка(): ФормаСписка<неизвестно>
```

Например:

```xbsl
Накладная.СоздатьФормуСписка()
```

Создает форму списка документа. Если документу назначена форма списка, то будет создана форма именно этого типа. Иначе будет создана автоматическая форма типа `<ИмяДокумента>.АвтоматическаяФормаСписка`.

Возвращает нетипизированную форму списка.

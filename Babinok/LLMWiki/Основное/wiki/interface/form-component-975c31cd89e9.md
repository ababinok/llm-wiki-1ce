## Обзор

Компонент интерфейса, предназначенный для редактирования объектов сущностей, работы со списками экземпляров сущностей и аналогичных действий.

## Документированный контракт и примеры

Компонент интерфейса, предназначенный для редактирования объектов сущностей, работы со списками экземпляров сущностей и аналогичных действий. Для него определены действия открытия и закрытия.

При открытии формы в модальном или всплывающем окне возвращает значение типа `ТипРезультата`. По умолчанию — `Неопределено`. Если закрыть форму нажатием на крестик или кликом за пределами окна при открытии во всплывающем окне или вызвать метод `Закрыть()` без передачи аргумента, результатом открытия будет `Неопределено`.

Для открытия формы в коде используется метод `Открыть()`. Его поведение зависит от значения свойства [СпособОткрытия](form-component-975c31cd89e9.md). Если свойству присвоено значение `ВМодальномОкне` или `ВоВсплывающемОкне`, то метод ожидает завершения работы с окном и возвращает значение, переданное в метод `Закрыть()`, или `Неопределено`, если форма была закрыта нажатием на крестик. В остальных случаях метод возвращает `Неопределено` и передает управление вызывающему коду сразу после открытия окна. Чтобы узнать, открыта ли форма в данный момент, используйте свойство `Открыта`.

Чтобы закрыть форму, вызовите метод `Закрыть()`. Вы можете проанализировать возвращаемое значение этого метода, чтобы узнать, закрыта форма (`Истина`) или нет (`Ложь`).

### Заголовок

`Авто|Строка`. Заголовок формы.

### ЗаголовокКомандыСоздания

Заголовок кнопки создания на форме списка. Если заголовок задан, то в веб-интерфейсе кнопка отображается в заголовке формы, а в мобильном интерфейсе отображается плавающая кнопка.

### Закрыть

`Команда`. Команда закрытия формы.

### ЗаписыватьВИсториюРаботыПользователяПриОткрытии

`Авто|Булево`. Признак записи в историю открытия формы. Для формы сущности запись в историю происходит в обработчиках `ПослеЧтения` или `ПослеЗаписи`. В других случаях запись происходит при открытии формы до вызова обработчика `ПослеСоздания`.

Экземпляр [ФрагментКомандногоИнтерфейса<ТипКоманды>](command-interface-fragment-f742e5d6797f.md), состоящий из команд. Список основных команд формы. ### ОсновнаяКоманда

[ОбычнаяКоманда](../language/usual-command-5d6bb6c02c99.md). Задает команду, которая определяет главное действие формы. Здесь мы рекомендуем использовать команду, после вызова которой форма будет закрыта. Типичные примеры:

- Сохранить (и закрыть),
- Отправить (письмо),
- Закрыть.

Отображается в нижней панели команд формы. Выглядит как основная кнопка.

В форме сотрудника главная команда «Записать» расположена внизу слева и выделена жёлтым; рядом находится серая команда «Удалить». [Описание иллюстрации](../../raw/figures/75a8495e96968b411eb5ad5c465028d21071476d8052a7852ad81953b3f29def-c8700781f544e02c.md)

### ПовторноеИспользованиеФормы

`Авто|Булево`. Признак повторного использования формы. Возможные значения свойства:

- `Авто`
  
  — (по умолчанию) система сама определяет, может ли форма использоваться повторно. Формы списков по возможности используются повторно, остальные формы — нет.
- `Истина`
  
  — форма используется повторно. Форма, открытая в основной области, при закрытии не удаляется. При повторном открытии формы открывается тот же самый экземпляр.
- `Ложь`
  
  — форма не используется повторно.

### ПодсказкиПриПервомОткрытии

`ПоследовательностьОбучающихПодсказок`. Последовательность подсказок, которая запускается автоматически при первом открытии формы. Если данная последовательность уже была просмотрена пользователем до конца, то больше она запускаться не будет.

Состоит из элементов типа `ОбучающаяПодсказка`. Обучающая подсказка обладает следующими свойствами:

- Заголовок
  
  — заголовок подсказки,
- Описание
  
  — текст внутри подсказки,
- ОпорныйЭлемент
  
  — компонент, около которого появляется подсказка,
- Изображение
  
  — изображение внутри подсказки.

При первом открытии поверх формы списка отображается подсказка. Заголовок «Приветствую!», внутри декоративное изображение приветствия, текст: «Позвольте помочь вам создать новую сделку! Сделка отражает процесс оказания услуги клиенту нашей компании на каждой стадии этого процесса. Для создания сделки выберите команду «Создать» в правом нижнем углу формы». Внизу указано «Шаг 1 из 1» и «Далее», сверху справа крестик закрытия. Кнопка «Создать» действительно находится в правом нижнем углу формы за подсказкой. Состояние одинаково используется в руководстве для формы и формы списка. ### СпособОткрытия

`Авто|СпособОткрытияФормы`. Позволяет указать, в каком окне будет открыта форма при вызове метода `Открыть()`. Может принимать следующие значения:

- `Авто` — для сущностей определяется свойством [`СпособОткрытияФормыСущностей`](clientapplication-ru-b046bbeb06bc.md) приложения. Для остальных — `ВРабочейОбласти`.
- `ВРабочейОбласти` — открывает форму в области содержимого приложения (рекомендуется использовать для списков и форм навигации).
  
  Форма списка, открытая в области содержимого приложения [Описание иллюстрации](../../raw/figures/cda4cffd1cc672dc5d2e5376be6facb37df7821b8cec02dcc5b7603c9a52e697-793a600e128d02f3.md)
- `ВДиалоговомОкне` — открывает форму в диалоговом окне (рекомендуется использовать для форм сущностей). Диалоговое окно блокирует область содержимого, однако его можно свернуть, чтобы вернуться к приложению.
  
  Форма объекта, открытая в диалоговом окне [Описание иллюстрации](../../raw/figures/a60cfbeb36cf2c10007b58b9816619a4c268b1fef7ed75aa3035810e7b01250a-61a97401d62e0667.md)
- `ВМодальномОкне` — открывает форму в модальном окне (рекомендуется использовать, когда требуется получить от пользователя данные, необходимые для продолжения операции). Модальное окно блокирует родительское диалоговое окно (при наличии) или область содержимого приложения. Сворачивается вместе с родительским окном.
  
  Форма объекта, открытая в модальном окне [Описание иллюстрации](../../raw/figures/96c5b036134d2389991b5acaab1921407986b4d447c4befbb2b946466e9a8a2c-245d593984e44a5e.md)
- `ВоВсплывающемОкне` — открывает форму во всплывающем окне (рекомендуется использовать для форм выбора).
  
  Форма «Поиск» открыта поверх списка во всплывающем окне. [Описание иллюстрации](../../raw/figures/707bc4129f9cedde494adaab7f2444d58023c54ff10e8cf65a90a459c23388f0-47bbb8de648fc00e.md)

### <Свойство разработчика>

Собственное свойство компонента, добавленное разработчиком. Описывается следующими свойствами:

#### ЗначениеПоУмолчанию

Стандартное значение свойства. Значение можно не указывать, если у его типа/типов есть значение по умолчанию (в частности, если его тип включает `Неопределено` или `Null`). Если тип свойства составной (включает несколько типов), необходимо указать тип значения. Иначе просто само значение.

В [описании экземпляра](system-and-interface-components-18287074edda.md) этого компонента вы можете установить другое значение этому свойству.

#### Имя

Имя свойства.

#### Контекстное

`Булево`. Признак доступности значения свойства на клиенте и сервере. Значение по умолчанию — `Ложь`. Если `Истина`, то поле **Тип** свойства должно содержать тип, доступный на клиенте и сервере.

«1С:Предприятие.Элемент» генерирует структурный тип [`{ИмяКомпонента}.Контекст`](componentname-context-ru-e40a3f370a75.md), который содержит как собственные контекстные свойства, так и контекстные свойства, наследуемые от базовых системных типов. Этот тип генерируется всегда, даже если контекстные свойства отсутствуют.

Пример:

```yaml
Имя: МойКомпонент
Свойства:
    -
        Имя: КонтекстноеСвойство
        Тип: Строка
        Контекстное: Истина
```

Для работы с контекстными свойствами на сервере вы можете использовать *контекстные серверные методы*. Эти методы должны располагаться в модуле компонента интерфейса и содержать аннотации [`@Контекстный`](../stdlib/contextual-ru-468258bf9c74.md) и [`@НаСервере`](../stdlib/onserver-ru-ff4072dae1ed.md). В теле метода тип объекта `этот` заменяется на [`{ИмяКомпонента}.Контекст`](componentname-context-ru-e40a3f370a75.md). Состояние этого объекта передается с клиента на сервер при каждом вызове метода. На сервере в теле метода вы можете изменить состояние объекта. Измененное состояние будет автоматически передано на клиент, и компонент будет инициализирован заново с учетом внесенных изменений.

Пример изменения значения контекстного свойства на сервере:

```xbsl
@НаСервере @ДоступноСКлиента
@Контекстный
метод КонтекстныйМетод()
    этот.ПолучитьТип() // Вернет "ИмяКомпонента.Контекст"
    // Задание значения контекстного свойства на сервере
    КонтекстноеСвойство = "Значение"
;
```

#### СохраняемыеДанные

`Истина` — при изменении значения этого свойства «Элемент» установит свойство `СобственнаяМодифицированность` компонента в значение `Истина`. После записи данных вы должны самостоятельно присвоить свойству `СобственнаяМодифицированность` значение `Ложь`.

#### Тип

Тип свойства.

## События

### ПередЗакрытием

Вызывается перед закрытием формы. Для обработки закрытия формы используется обработчик `ПередЗакрытием`:

```xbsl
@Обработчик
метод ПередЗакрытием(Событие: ПараметрыЗакрытияФормы)
    // Обработка закрытия формы...
;
```

Свойство `РежимЗакрытияФормы` объекта `ПараметрыЗакрытияФормы` содержит признак отказа от закрытия формы. Возможные значения:

- `Авто`
  
  — выполняется стандартная обработка, закрытие формы зависит от ее результата;
- `РежимЗакрытияФормы.Закрыть`
  
  — стандартная обработка не выполняется, форма закрывается;
- `РежимЗакрытияФормы.НеЗакрывать`
  
  — стандартная обработка не выполняется, форма не закрывается.

### ПослеЗакрытия

Вызывается, когда форма уже закрыта и процесс закрытия нельзя отменить или прервать. Для обработки каких-либо действий используется обработчик `ПослеЗакрытия`:

```xbsl
@Обработчик
метод ПослеЗакрытия()
    // Действия после закрытия формы...
;
```

### ПослеСоздания

Переопределяемый обработчик. Предназначен для дополнительной инициализации свойств экземпляра компонента на клиенте и вызова прикладной логики инициализации экземпляра компонента. Выполняется после полного конструирования экземпляра компонента, т. е. когда:

- установлены значения свойств экземпляра компонента, указанные при
  
  [описании экземпляра](system-and-interface-components-18287074edda.md)
  
  ;
- созданы свои компоненты данного экземпляра;
- значения свойств своих компонентов установлены из описаний их экземпляров;
- подключены обработчики событий в экземпляре компонента и в экземплярах его внутренних компонентов.

Сигнатура обработчика:

```xbsl
@Обработчик
метод ПослеСоздания()
// Обработка события...
;
```

### ПриНаведении

Назначаемое событие. Вызывается при наведении указателя мыши на область компонента. Особенности вызова события:

- При наведении указателя мыши на вложенные элементы событие
  
  ПриНаведении
  
  сначала вызывается для родительского элемента, а затем для дочернего.
- Событие не поддерживается на мобильных устройствах.

Когда указатель мыши покидает область компонента, вызывается событие **ПриПотереНаведения**.

### ПриПеретаскивании

Назначаемое событие. Возникает по окончании перетаскивания на область компонента. Если в обработчике события свойство `СобытиеПриПеретаскивании.СтандартнаяОбработка` не равно `Ложь`, то происходит системная обработка события, после чего «Элемент» вызывает событие у родительского компонента, вплоть до компонента, унаследованного от `КлиентскоеПриложение`. На данный момент поддерживается только перетаскивание файлов из проводника на область компонента.

### ПриПотереНаведения

Назначаемое событие. Вызывается, когда указатель мыши покидает область компонента. Особенности вызова события:

- Если событие срабатывает для вложенных элементов (курсор смещается за пределы родительского элемента), то сначала оно вызывается для дочернего элемента, а затем для родительского.
- Событие не вызывается при удалении компонента, изменении его видимости или размера (если в результате указатель мыши больше не находится над областью компонента).
- Событие не поддерживается на мобильных устройствах.

При наведении указателя мыши на область компонента вызывается событие **ПриНаведении**.

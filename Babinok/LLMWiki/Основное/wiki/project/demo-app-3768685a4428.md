## Документированный контракт и примеры

Для знакомства с основными возможностями и концепциями технологии «1С:Предприятие.Элемент» вы можете использовать демо-приложение, которое представляет собой упрощенную систему управления взаимоотношениями с клиентами.

Демонстрационное приложение [Описание иллюстрации](../../raw/figures/990e094d34f73c808da0a9e83823a1659ce00ed53305be3a785192dfdfe68e06-5ee37a35d4014060.md)

Данное приложение создано исключительно в демонстрационных целях. Оно не является законченным прикладным решением и не предназначено для автоматизации настоящих бизнес-процессов.

## Создание приложения

Для запуска демо-приложения вам необходимо создать новый проект из встроенного шаблона, как показано ниже:

1. [Откройте](https://1cmycloud.com/console/help/element/10.0/docs/topics/open-control-panel/) панель управления.
2. На вкладке **Приложения** нажмите **+ Новое приложение**.
  
  На вкладке «Приложения» панели управления выделена ссылка «Новое приложение» для создания приложения. [Описание иллюстрации](../../raw/figures/dd76e7275eb688227f5548500bc540425036b9b470af5bdc1c34329cfe1624e2-16d0604e154f03ad.md)
3. В открывшемся окне выберите **Из проекта** ⟶ **Новый проект**. В выпадающем меню **Шаблон проекта** выберите пункт **Демо CRM**.
  
  В диалоге «Новое приложение» открыта вкладка «Из проекта». [Описание иллюстрации](../../raw/figures/0265352bf926ca9cce9b9f8adde721c5947b7b7c344a06b4bc9fce28af54d968-3dd1676bdc126907.md)
4. Заполните оставшиеся поля: укажите поставщика, имя, представление и версию проекта, задайте имя приложения. Включите режим разработки для создаваемого приложения, выберите тип СУБД (в данном примере это **Файловая СУБД**) и нажмите **Создать**.
  
  Форма параметров проекта: поставщик, имя, представление и версия, имя и HTTP-путь приложения, часовой пояс и локализация, режим разработки, тип СУБД. В примере выбрана «Файловая СУБД». [Описание иллюстрации](../../raw/figures/54b87c137ab30a89b62bdcb65881d62e642e1e75ccad8905b5ff8ffda4de9626-6fd4e114e46c9903.md)

Когда приложение будет создано, оно появится в общем списке приложений. Для запуска приложения кликните по ссылке в колонке **URL**. Если вы хотите ознакомиться со структурой и содержимым проекта, нажмите **Разработать**, чтобы открыть проект в среде разработки.

Новое приложение в списке приложений [Описание иллюстрации](../../raw/figures/b974dbb70a4ea25bfef079b7f13ec34485ca25963400622ed4bd563fa92ee146-d2796d752202fe6c.md)

## Функциональность приложения

Демонстрационное приложение ориентировано на управление сделками по продажам и клиентами условной компании.

Список сделок демоприложения: таблица с номером, датой, клиентом, ответственным, суммой и стадией; выше доступны поиск и создание сделки. [Описание иллюстрации](../../raw/figures/42f56479ad51f4393fcf1c767c020da254b328be07c3f723fbda4abed34c6170-2e1561bfe5912dd2.md)

Сделка отражает процесс продажи товара клиенту компании на каждой стадии этого процесса.

В системе сделка представляется в виде документа **Сделка**. В сделке указываются клиент, контактное лицо и продаваемые товары.

Форма Сделка в демо CRM: слева поля Номер, Дата создания, Клиент, Контактное лицо, Ответственный, Стадия, Дата закрытия; справа вкладки Товары, Задачи, События, Файлы. На вкладке Товары есть Добавить, Поиск, таблица Номенклатура / Цена / Количество / Скидка / Сумма, действия перемещения строки вверх/вниз и удаления. Внизу показаны итоги: промежуточная сумма 636 645,90, скидка по строкам 91 538,00, итоговая сумма 545 107,90. Верхние действия — Обновить, Создать копию, Удалить; нижние — Готово и Сохранить изменения. Числа — демонстрационные значения, подписи формы не задают API. [Описание иллюстрации](../../raw/figures/c77258fe07c1c04c56c7b737ebca1e4ef99d78af1ee345a97b52ad4d1c160395-106eeee1747c7876.md)

Стадии продажи задаются перечислением **СтадияСделки**. Каждая сделка должна находиться в одной из этих стадий, что указывается в соответствующем реквизите документа сделки.

У сделки поле «Стадия» раскрывает список: «Первичный контакт», «Переговоры», «Принятие решения», «Закрыта успешно», «Закрыта неуспешно». [Описание иллюстрации](../../raw/figures/bc328d028927ebbf9bb138aec7e8a2d5675cc520aba0b832e48cfa565716ec34-bf125c34253a9f2c.md)

В разрезе сделок можно вести учет активностей – задач и событий.

Задача – это запланированная на определенное время работа, которая имеет статус выполнения.

Форма списка задач демоприложения: строки с названием, связанной сделкой, клиентом, исполнителем, датой создания и статусом; доступны поиск и создание. [Описание иллюстрации](../../raw/figures/eccd09dfee4e16a7f28ab1af634e690e2ac2cac1b36d15047fd3a0792f163135-2b3be80d742e3aed.md)

События предназначены для регистрации встреч, звонков, демонстраций и других подобных мероприятий. В отличие от задач, события имеют дату начала и завершения.

Форма списка событий демоприложения: таблица дат регистрации, номеров, тем, ответственных, связанных сделок и клиентов; сверху поиск и создание события. [Описание иллюстрации](../../raw/figures/f2fd3770ad52eb94e75f64509d8cfa8ae9f5f2ca9899333a8867ce538e6168d3-df4ce8dad0f6de4a.md)

Пользователю в приложении может быть назначена роль сотрудника. Роли сотрудников предопределены и делятся на торговых представителей и менеджеров по продажам.

Форма создания/редактирования сотрудника [Описание иллюстрации](../../raw/figures/aa22ef0641b0e636118c7297498b21bf757029fb3e56625f4ea1a4c810ffc9b1-215f388a62a44dde.md)

Роли используются для демонстрации разграничения прав на объекты и не влияют на сценарии работы (для упрощения любой пользователь имеет доступ ко всем сценариям, кроме административных). При подключении пользователя к приложению ему автоматически назначается роль «Менеджер по продажам».

## Администрирование

Администратору приложения также доступен раздел **Администрирование**, в котором расположена [консоль запросов](../queries/query-console-e39bfa4ff80f.md).

Консоль запросов в демоприложении открыта из административного раздела: вкладки запросов, результатов и настроек, список запросов и область редактора, таблица параметров снизу. [Описание иллюстрации](../../raw/figures/f969b77b06becb13e5fe273db47aa1f5beae1ff079a6062945c75d293eed8a30-e1e184f4ff338021.md)

С помощью обработки **Заполнение данных** (**Администрирование** → **Демо данные** → **Заполнение данных**) вы можете заполнить приложение демонстрационными данными или очистить их.

На форме демонстрационного приложения размещены карточки «Заполнение данных» и «Очистка данных» с командами «Заполнить данные» и «Очистить данные». [Описание иллюстрации](../../raw/figures/7591fe8f7c16db741de6d6a95c678afa8deafc0ed4fc9c38da621666858e2f7f-dda85fd3ab042837.md)

## Разграничение прав на данные приложения

Права на все сущности приложения назначаются в разрезе бизнес-региона (хранятся в справочнике «БизнесРегионы»). Пользователь имеет доступ только к тем объектам, которые относятся к его бизнес-региону.

При подключении нового пользователя к приложению создается новый бизнес-регион и генерируются новые данные, относящиеся к этому региону. Настройку **Заполнять данные** можно отключить в разделе **Администрирование** → **Демо данные** → **Служебные настройки**.

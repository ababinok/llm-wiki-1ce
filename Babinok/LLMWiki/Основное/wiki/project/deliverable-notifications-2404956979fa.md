## Обзор

В технологии «1С:Предприятие.Элемент» реализован механизм push-уведомлений.

## Документированный контракт и примеры

В технологии «1С:Предприятие.Элемент» реализован механизм push-уведомлений. Уведомления позволяют проинформировать пользователя о каком-либо событии, а также передать данные (например, команду). При этом пользователь получит уведомление в любом случае, даже если приложение находится в фоновом режиме или не работает.

## Создание и настройка уведомлений

В «Элементе» интерфейс для работы с push-уведомлениями описывается в пространстве имен [`Стд::ДоставляемыеУведомления`](../stdlib/deliverablenotifications-6ff659677735.md). Полное описание уведомления содержится в типе [`ДоставляемоеУведомление`](../stdlib/deliverablenotification-ru-ed2772c45a48.md). С помощью его свойств можно задать, например, заголовок, текст, данные, звуковое оповещение, а также параметры отображения доставляемого уведомления.

Например, создать доставляемое уведомление можно следующие образом:

```xbsl
// Создание доставляемого уведомления
пер Уведомление = новый ДоставляемоеУведомление()
Уведомление.Заголовок = "Поздравление"
Уведомление.Текст = "С праздником!"
```

### Триггеры

Вы можете установить триггер, по которому будет отправляться уведомление. Триггер уведомления определяет сценарий появления уведомления. Если триггер отсутствует, то уведомление отобразится немедленно. В данный момент доступно три варианта: отображение уведомлений через интервал времени или по расписанию и доставка уведомления с сервера. Каждому варианту соответствует собственный триггер.

Триггер указывается напрямую в уведомлении. Для этого в свойство [`Триггер`](../stdlib/deliverablenotification-ru-ed2772c45a48.md) объекта типа [`ДоставляемоеУведомление`](../stdlib/deliverablenotification-ru-ed2772c45a48.md) установите объект одного из следующих типов:

- [`ТриггерДоставляемыхУведомленийПоИнтервалуВремени`](../stdlib/deliverablenotificationtimeintervaltrigger-ru-dc866519df09.md)
  
  — позволяет отображать уведомление через определенный промежуток времени от момента его создания, а затем повторять его с определенной периодичностью;
- [`ТриггерДоставляемыхУведомленийПоКалендарю`](../stdlib/deliverablenotificationcalendartrigger-ru-329496cc419d.md)
  
  — позволяет отображать уведомление в определенную дату и время, а также повторять его с определенной периодичностью;
- [`ТриггерДоставляемыхУведомленийПоСпискуПолучателей`](../stdlib/deliverablenotificationrecipientlisttrigger-ru-5fa954900f3f.md)
  
  — используется на сервере для отправки уведомления в мобильное приложение. Триггеру можно задать сразу несколько адресов получателей, чтобы отправить уведомление всем одновременно. Адрес получателя необходимо заранее передать с клиента на сервер, привязать к пользователю мобильного приложения и сохранить.

Например, создать доставляемое уведомление и установить триггер по интервалу времени можно следующим образом:

```xbsl
// Установка триггера по интервалу времени
пер Уведомление = новый ДоставляемоеУведомление()
Уведомление.Триггер = новый ТриггерДоставляемыхУведомленийПоИнтервалуВремени(60, Ложь)
```

### Каналы

поддерживает создание каналов и многоканальность. Канал — это совокупность настроек отображения уведомлений. Пользователь может настраивать видимость, звук, вибрации и приоритет для различных каналов. Например, если пользователю интересны уведомления о новостях, но неинтересны уведомления о погоде, он может отключить канал о погоде. Каналы устанавливаются при старте приложения до начала использования уведомлений:

```xbsl
пер Каналы = [ новый КаналДоставляемыхУведомлений("ads", "Реклама"),
               новый КаналДоставляемыхУведомлений("news", "Новости") ]
ДоставляемыеУведомления.УстановитьКаналыУведомлений(Каналы)
```

### Действия и категории

Обычно уведомления имеют два стандартных действия: **Открыть** и **Удалить**. Действие **Удалить** удаляет уведомление из списка. **Открыть** — основное действие, которое пользователь вызывает, нажав на уведомление. Основное действие всегда приводит к открытию основного интерфейса приложения и переходу к экрану, связанному с уведомлением.

Кроме стандартных действий, уведомления также могут содержать другие действия, предназначенные для реакции пользователя в системном интерфейсе уведомления. Эти действия могут привести к активации приложения, либо оно может обработать их в фоновом режиме. Действия могут представлять собой как нажатие кнопки, например **Отложить**, **Принять** или **Отклонить**, так и содержать поле для ввода текста и передачи его в приложение вместе с нажатой кнопкой.

Вы можете определить категории — наборы действий, которые содержит уведомление. При отправке уведомления ему назначается категория, после чего система отображает действия, описанные в категории, в своем интерфейсе. При старте приложения создайте все категории и передайте их системе с помощью метода [`УстановитьКатегорииУведомлений()`](../stdlib/deliverablenotifications-ru-0db46eb15403.md) объекта [`ДоставляемыеУведомления`](../stdlib/deliverablenotifications-ru-0db46eb15403.md):

```xbsl
пер Категории = новый Массив<КатегорияДоставляемогоУведомления>()

пер Действия = [
    новый ДействиеДоставляемогоУведомления("allow", "Разрешить", Ложь),
    новый ДействиеДоставляемогоУведомления("deny", "Отказать", Истина)
]

Категории.Добавить(новый КатегорияДоставляемогоУведомления("auth", Действия))

Действия = [ новый ДействиеДоставляемогоУведомления("reply", "Ответить", Ложь) ]
Категории.Добавить(новый КатегорияДоставляемогоУведомления("chat", Действия))

ДоставляемыеУведомления.УстановитьКатегорииУведомлений(Категории)
```

## Отправка уведомлений

Основным объектом для работы с уведомлениями на сервере является тип [`ОтправкаДоставляемыхУведомлений`](../stdlib/deliverablenotificationssender-ru-785afe0b1543.md). Он позволяет отправлять уведомления адресатам, а также получать информацию о том, каким адресатам больше не нужно их отправлять из-за того, что они отключили уведомления или удалили приложение.

Общая схема взаимодействия основного и мобильного приложения выглядит следующим образом:

- Отправитель — основное приложение
  
  «1С:Предприятие.Элемента»
  
  .
- Сервис доставки уведомлений используется для передачи уведомлений от отправителя к получателю. Он отправляет уведомление мобильному устройству, когда оно становится доступным в сети Интернет.
  
  «1С:Предприятие.Элемент»
  
  поддерживает такие сервисы, как:
  
  - Apns (Apple Push Notification Service);
  - Fcm (Firebase Cloud Messaging);
  - Hms (Huawei Messaging Service).
- Получатель — мобильное приложение
  
  «1С:Предприятие.Элемент»
  
  .

Для отправки уведомления необходимо указать список адресов получателей и данные аутентификации в сервисах уведомлений. Адрес получателя — это экземпляр объекта [`ИдПодписчикаДоставляемыхУведомлений`](../stdlib/deliverablenotificationsubscriberid-ru-4e4bc11d207e.md), который необходимо получить в мобильном приложении с помощью метода [`ДоставляемыеУведомления.ПолучитьИдПодписчикаУведомлений()`](../stdlib/deliverablenotifications-ru-0db46eb15403.md) и передать на сервер. На сервере данный объект необходимо привязать к пользователю, аутентифицированному в мобильном приложении, и сохранить, чтобы в дальнейшем отправлять ему уведомления на это устройство.

Данные аутентификации различаются в зависимости от сервиса аутентификации и задаются соответствующим объектом [`ДанныеАутентификацииДоставляемыхУведомлений`](../security/deliverablenotificationauthenticationdata-ru-a04a69680ee1.md):

- [`ДанныеАутентификацииApns`](../security/apnsauthenticationdata-ru-1dbfd318b1a7.md)
  
  — содержит сертификат отправки и его пароль;
- [`ДанныеАутентификацииFcm`](../security/fcmauthenticationdata-ru-3bf1e8aa19bb.md)
  
  — содержит ключ аккаунта в виде JSON-файла;
- [`ДанныеАутентификацииHms`](../security/hmsauthenticationdata-ru-c42cb4fb4e9a.md)
  
  — содержит секретный ключ клиента;
- [`ДанныеАутентификацииЦентраУведомлений1С`](../security/notificationcenter1cauthenticationdata-ru-6023c5c6ac77.md)
  
  — содержит ключ центра уведомлений. Для отправки уведомлений необходимо зарегистрироваться в центре уведомлений, добавить данные для работы со сторонними сервисами (APNS, FCM, HMS) и далее в своем коде использовать только ключ доступа к сервису 1С.

Например:

```xbsl
@НаКлиенте
метод ОтправитьПолучателю()
    пер ИдПолучателя = ДоставляемыеУведомления.ПолучитьИдПодписчикаУведомлений()

    ИдПолучателя.ВидПодписчика = ВидПодписчикаДоставляемыхУведомлений.Fcm
    ИдПолучателя.ИдПриложения = "com.e1c.mobile"
    ИдПолучателя.ИдУстройства = "Hysdskc67dd6G6F5sdks"
    
    Отправить(ИдПолучателя)
;

@НаСервере @ДоступноСКлиента
метод Отправить(ИдПолучателя: ИдПодписчикаДоставляемыхУведомлений)
    пер Получатели = новый Массив<ИдПодписчикаДоставляемыхУведомлений>()
    Получатели.Добавить(ИдПолучателя)

    пер Триггер = новый ТриггерДоставляемыхУведомленийПоСпискуПолучателей()
    Триггер.Получатели = Получатели

    пер Уведомление = новый ДоставляемоеУведомление()

    Уведомление.Ид = "12345"
    Уведомление.Заголовок = "Заголовок"
    Уведомление.Текст = "Текст"
    Уведомление.Триггер = Триггер
    пер ДанныеАутентификацииFcm = новый ДанныеАутентификацииFcm("com.e1c.mobile", "Содержимое файла с ключом".ВБайты())
    пер ДанныеАутентификацииHms =
        новый ДанныеАутентификацииHms("com.e1c.mobile", "push-project", "client_id", "client_secret")
    пер ДанныеАутентификацииApns =
        новый ДанныеАутентификацииApns("com.e1c.mobile", "Содержимое файла с сертификатом".ВБайты(), "Пароль к сертификату")

    ОтправкаДоставляемыхУведомлений.Отправить(Уведомление, [ДанныеАутентификацииFcm, ДанныеАутентификацииHms, ДанныеАутентификацииApns])
;
```

## Управление уведомлениями

Для работы на мобильном клиенте и клиенте мобильного приложения основным объектом является тип [`ДоставляемыеУведомления`](../stdlib/deliverablenotifications-ru-0db46eb15403.md). С его помощью вы можете:

- узнать состояние и объем поддерживаемой функциональности;
- получить идентификатор подписчика уведомлений;
- настроить каналы, категории и обработчики уведомлений;
- добавить уведомление;
- получить список запланированных и доставленных уведомлений;
- удалить уведомления из этих списков;
- получить текущее значение значка и установить новое значение.

Узел этого вида передает файлы в указанный каталог. Тело сообщения записывается в файл.

Узел «ФайлНазначение» показан в палитре и на схеме как назначение для записи тела сообщения в файл указанного каталога. [Описание иллюстрации](../figures/2f87733843acf32be9d09e820a2d2e6df9bb665ec99eb3172f482e90b6c3a6da-d80e2548e2ea67e8.md)

## Свойства узла

### ВыборИмени

Обработчик, который предназначен для того, чтобы вы могли переопределить значение свойства **ИмяФайла** — имя файла, в которое будет записано сообщение. Обработчик должен вернуть имя файла. Если заполнено свойство **ИмяФайла** и указан обработчик **ВыборИмени**, то имя файла будет браться из обработчика. В случае ошибки в обработчике имя файла будет взято из свойства **ИмяФайла**.

Пример:

```xbsl
метод ПриВыбореИмени(Контекст: МойПроцессИнтеграции.КонтекстВызова, Сообщение: МойПроцессИнтеграции.Сообщение): Строка

    возврат Сообщение.АбсолютныйПутьФайла + (Сообщение.ПолучитьПараметр("ВидСодержимого") как Строка)
;
```

### ДействиеНадСуществующимФайлом

Что сделает «Элемент», если уже существует файл, в который нужно записать тело сообщения:

#### ВыдаватьОшибку

Не изменит существующий файл и вызовет исключение. Сообщение не будет считаться доставленным

#### Дописывать

Допишет тело сообщения в конец существующего файла. Такой файл будет содержать тела нескольких сообщений

#### Оставлять

Не изменит существующий файл. Сообщение будет считаться доставленным

#### Перезаписывать

Перезапишет существующий файл

### Длительность хранения доставленных сообщений в формате ДД.ЧЧ

Определяет время, в течение которого будут [храниться сообщения, доставленные в данный узел](../../wiki/project/delivered-messages-d48678a57c96.md). Задается в пользовательском интерфейсе приложения, в карточке процесса интеграции, в свойствах узла. Недоступно в среде разработки.

Длительность задается в формате *ДД:ЧЧ* (например, *10:02* — 10 дней и 2 часа). Если указать длительность равную *00:00*, то доставленные сообщения для данного узла не будут сохраняться в «1С:Предприятие.Элементе». Длительность хранения должна быть равна *00:00* (по умолчанию) либо больше или равна *00:01*.

### Имя

Имя узла, уникальное в рамках процесса интеграции. Используется для обращения к узлу в коде (`УзелСхемыИнтеграции`.`Имя`). Должно начинаться с буквы, за которой следуют буквы, цифры или символы '_' (нижнее подчеркивание). Минимальная длина — 2 символа

### ИмяФайла

Имя файла, в который будет записано сообщение

### ИспользоватьИмяФайлаБезПути

Если значение свойства равно `Истина`, то «Элемент» проигнорирует путь к файлу из сообщения и запишет файл в каталог, указанный в свойстве **Каталог**. Иначе «Элемент» запишет файл в каталог, вложенный в **Каталог**. Имя этого вложенного каталога она определит из сообщения

### Каталог

Имя каталога, в который «Элемент» запишет файл сообщения

### Кодировка

[Кодировка](../../wiki/project/supported-encodings-0f8910737ada.md), в которой «Элемент» запишет содержимое файла сообщения

### ОбновлениеМетрик

Обработчик, внутри которого можно обновлять метрики, добавленные в проект разработчиком. Пример:

```xbsl
// Разработчик добавил в проект метрику «РазмерФайлов». Тогда обновить метрику в узлах можно следующим образом:
метод ОбновлениеМетрик(Контекст: МойПроцессИнтеграции.КонтекстВызова, Сообщение: МойПроцессИнтеграции.Сообщение)
    пер РазмерФайлов = МойПроцессИнтеграции.Метрики["РазмерФайлов"]
    РазмерФайлов.Обновить(Сообщение.УзлыПути.Текущий.Узел.Имя, 1)
;
```

### Описание

Произвольное описание узла для разработчика. Используется при редактировании схемы процесса интеграции. Недоступно из кода

### РазрешитьПустойФайл

Будет ли «Элемент» создавать пустые файлы для сообщений с пустым телом.

Если `Истина`, то она создаст пустой файл сообщения.

Если `Ложь`, то она не создаст файл сообщения и вызовет исключение.

Если `Истина` и **ДействиеНадСуществующимФайлом** равно **Перезаписывать**, то вместо существующего файла она запишет пустой файл.

Если `Истина` и **ДействиеНадСуществующимФайлом** равно **Дописывать**, то существующий файл останется неизменным

## Пример использования

**Контекст:** У системы-отправителя есть каталог, в котором периодически появляются файлы. Из содержимого этих файлов формируются сообщения и передаются системе-получателю, где также записываются в файлы в определенном каталоге.

**Задача:** Записать сообщение из «1С:Предприятие.Элемента» в файл, расположенный в определенном каталоге получателя.

**Решение:** Для того чтобы сформировать сообщения из файлов, появляющихся в каталоге участника интеграции, добавим на схему узел [«ФайлИсточник»](../../wiki/integration/file-source-6a2c5cde7609.md). Свяжем этот узел с [группой участников](../../wiki/project/participant-groups-93f2250d5853.md), чтобы использовать их [реквизиты](../../wiki/project/create-attributes-for-information-system-a64ba148c36c.md) при заполнении свойств узла, например, при указании каталога. Для того чтобы записать сообщение в файл в каталоге получателя, используем узел «ФайлНазначение». Аналогично, свяжем его с группой участников, чтобы использовать их реквизиты при заполнении свойств узла.

Схема файлового обмена: группа «Отправитель» связана с ФайлИсточник, маршрут ведёт в ФайлНазначение, связанное с группой «Получатель». Свойства участников используются для настройки источника и каталога назначения.

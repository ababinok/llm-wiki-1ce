Задания — это механизм, который позволяет выполнять заданный код асинхронно в фоновом режиме (фоновые задания) или по расписанию (запланированные задания). В «1С:Предприятие.Элементе» задания описываются типами из пространства имен [`Стд::Задания`](../../wiki/stdlib/jobs-5034d2d025d7.md).

## Фоновые задания

С помощью фоновых заданий можно выполнять программный код в фоновом режиме.

Фоновые задания описываются типом [`ФоновыеЗадания`](../../wiki/stdlib/backgroundjobs-ru-ce0a20cb1908.md), который позволяет создавать задания и управлять ими.

Запуск фоновых заданий, выполняющих вычисления, с ожиданием завершения всех запущенных заданий

```xbsl
метод ЗапуститьФоновыеЗадания() 
    пер Задания = новый Массив<ФоновоеЗадание>()
    Задания.Добавить(ФоновыеЗадания.Выполнить(&Расчеты.ПервыйРасчет))
    Задания.Добавить(ФоновыеЗадания.Выполнить(&Расчеты.ВторойРасчет))
    Задания.Добавить(ФоновыеЗадания.Выполнить(&Расчеты.ТретийРасчет))
    ФоновыеЗадания.ОжидатьЗавершения(Задания)
;
```

Типичное применение фонового задания — параллельные вычисления.

Фоновое задание запускается при наличии ресурсов, однако результат его работы не гарантирован:

- при выключении сервера или остановке приложения задание может не запуститься;
- при выключении сервера, остановке приложения или прерывании работы выполняемые задания теряются.

Метод `ОжидатьЗавершения()` не выбрасывает исключение, если задание завершилось с ошибкой, было отменено или прервано. В этом случае в свойстве [`ФоновоеЗадание.Исключение`](../../wiki/stdlib/backgroundjob-ru-3eb252bf2162.md) содержится экземпляр одного из исключений:

- [`ИсключениеЗаданиеОтменено`](../../wiki/stdlib/jobcanceledexception-ru-85ca9a9057fc.md)
  
  — задание было отменено методом
  
  `Отменить()`
  
  или прервано,
- [`ИсключениеВнутренняяОшибкаВыполненияЗадания`](../../wiki/stdlib/jobexecutioninternalerrorexception-ru-881eb62ccbab.md)
  
  — задание завершилось из-за внутренней ошибки.

Если задание завершилось успешно, свойство `Исключение` содержит `Неопределено`.

```xbsl
метод ЗапуститьСОбработкойОшибок()
    пер Задание = ФоновыеЗадания.Выполнить(&Расчеты.ПересчитатьИтоги)
    ФоновыеЗадания.ОжидатьЗавершения([Задание])
    если Задание.Исключение != Неопределено
        // задание завершилось с ошибкой, было отменено или прервано
    ;
;
```

## Запланированные задания

С помощью запланированных заданий можно выполнять программный код по расписанию, в том числе с многократными повторами в запланированные моменты времени. Чтобы сервис запланированных заданий запускался автоматически при запуске приложения, включите соответствующую настройку в панели управления в меню **Настройки** приложения:

В настройках приложения рамкой выделено «Автозапуск запланированных заданий»; настройка включает запуск сервиса заданий вместе с приложением. [Описание иллюстрации](../figures/ffb89f6b25f659cd32a47c55f049d9ec33226d7901ae53ba921172290b528e13-cbaf71043159f4db.md)

При включении сервиса в журнал событий записывается событие [`СобытиеЗапланированныеЗаданияВключены`](../../wiki/stdlib/scheduledjobsenabledevent-ru-0fe16ee6deb8.md), а при выключении — [`СобытиеЗапланированныеЗаданияВыключены`](../../wiki/stdlib/scheduledjobsdisabledevent-ru-f61ee1a7291e.md).

Запуск запланированного задания гарантируется в следующих случаях:

- при выключении сервера или остановке приложения, если задание не выполнялось в момент выключения;
- при выключении сервера, остановке приложения или прерывании выполнения работающее задание завершается с ошибкой и обрабатывается в соответствии со стратегией обработки ошибок: например, задание может быть запущено повторно через равные интервалы времени, а также линейно и экспоненциально меняющиеся.

В проекте запланированные задания определяются с помощью специального элемента проекта [ЗапланированноеЗадание](../../wiki/project/scheduled-job-project-element-e47ed37b89ab.md). На его основе при применении проекта можно создавать предопределенные задания. Кроме того, задания можно создавать в коде, используя описанный в проекте элемент в качестве шаблона. Эти задания будут иметь те же значения свойств, что и описанные в элементе проекта (если они явно не переопределены).

Создание запланированных заданий на основе элемента проекта является предпочтительным, потому что при изменении описания элемента **ЗапланированноеЗадание** в следующих версиях проекта все созданные на его основе задания адаптируются к изменениям. [Задания, созданные вручную в коде](../../wiki/project/jobs-81f432f38905.md), необходимо самостоятельно адаптировать к изменениям проекта.

## Создание и планирование заданий

Запланированные задания описываются типом [`ЗапланированныеЗадания`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md), который позволяет создавать запланированные задания и управлять ими. В методе [`Создать()`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md) в качестве параметров указывается имя обработчика, который вызывается для выполнения задания, и параметры, передаваемые в обработчик. Например:

Описание обработчика, который вызывается для выполнения задания

```xbsl
@ВПроекте
метод МойМетод(Ключ: Строка, Период: Число)
    // код выполнения задания
;
```

Создание задания, запускающего метод МойМетод

```xbsl
знч Задание = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод, "Ключ", 500)
```

Метод [`Создать()`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md) возвращает объект типа [`СоздаваемоеЗапланированноеЗадание`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md), который позволяет настроить создаваемое задание с помощью метода [`Настроить()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) и запланировать его выполнение относительно активной [транзакции](../../wiki/data/transactions-and-controlled-locks-fef75789dc76.md) с помощью методов:

- [`Запланировать()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md)
  
  — если нет активной транзакции, задание планируется немедленно, в противном случае задание сохраняется в базу данных и планируется после завершения активной транзакции;
- [`ЗапланироватьБезТранзакции()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md)
  
  — задание планируется немедленно, независимо от наличия активной транзакции;
- [`ЗапланироватьВТранзакции()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md)
  
  — задание сохраняется в базу данных и планируется после завершения активной транзакции. Если активной транзакции нет, выбрасывается исключение.

Если сервис заданий выключен, метод [`ЗапланироватьБезТранзакции()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) выбрасывает исключение. Если сервис заданий выключен и активных транзакций нет, то методы [`Запланировать()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) и [`ЗапланироватьВТранзакции()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) выбрасывают исключение. При наличии активной транзакции методы [`Запланировать()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) и [`ЗапланироватьВТранзакции()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) успешно выполнятся, а задания будут запланированы, когда запустится сервис.

> [!NOTE] примечание
> При [обновлении проекта](../../wiki/project/update-app-data-356eca7811d0.md) сервис запланированных заданий всегда выключен, поэтому в обработчике `@ОбновлениеПроекта` можно планировать задания только с помощью метода [`ЗапланироватьВТранзакции()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md).

## Изменение и настройка заданий

Метод [`Изменить()`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md) типа [`ЗапланированныеЗадания`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md) возвращает объект типа [`ИзменяемоеЗапланированноеЗадание`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md), с помощью которого можно поменять некоторые параметры запуска существующего запланированного задания. Чтобы запланировать измененное задание, используются методы [`Запланировать()`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md), [`ЗапланироватьБезТранзакции()`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md) и [`ЗапланироватьВТранзакции()`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md) по аналогии с одноименными методами типа [`СоздаваемоеЗапланированноеЗадание`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md).

При настройке запланированного задания с помощью метода [`СоздаваемоеЗапланированноеЗадание.Настроить()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md) вы можете задавать параметры, перечисленные ниже.

### Ключ

[`Строка`](../../wiki/stdlib/string-ru-1bac645acacf.md). Ключ служит для идентификации задания. С его помощью вы можете:

- изменить задание;
  
  ```xbsl
  // Создание запланированного задания НовоеЗадание с заданным ключом Ключ
  знч Ключ = "ЗаданиеРассылкиСпама"
  пер НовоеЗадание = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод)
                                           .Настроить(Ключ = Ключ)
                                           .Запланировать()
  
  // Получение объекта типа ИзменяемоеЗапланированноеЗадание,
  // чтобы изменить задание с ключом Ключ
  знч ИзмЗадание = ЗапланированныеЗадания.Изменить(Ключ)
  ```
- отменить выполнение задания — прерывает исполнение задания, если оно выполняется в момент вызова; для задания с расписанием отменяется только текущее исполнение;
  
  ```xbsl
  ЗапланированныеЗадания.Отменить("МоеЗадание")
  ```
- приостановить выполнение задания (только для заданий с расписанием);
  
  ```xbsl
  ЗапланированныеЗадания.Приостановить("МоеЗадание")
  ```
- возобновить выполнение задания (только для заданий с расписанием).
  
  ```xbsl
  ЗапланированныеЗадания.Возобновить("МоеЗадание")
  ```

Ключ, назначенный с помощью метода [`Настроить()`](../../wiki/stdlib/creatingscheduledjob-ru-1812add8a2ef.md), удобно использовать для регулярных заданий. Если задание выполняется однократно, обычно используется уникальный автоматически сгенерированный ключ.

Если в момент вызова метода [`Запланировать()`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md) уже существует задание с таким же ключом, то поведение метода определяется [стратегией публикации](../../wiki/project/jobs-81f432f38905.md).

Параметр нельзя изменить после планирования задания.

### Описание

[`Строка`](../../wiki/stdlib/string-ru-1bac645acacf.md). Описание задания. Поддерживает [локализацию](../../wiki/project/app-localization-15f5b1317f82.md).

Пример получения локализованного описания задания

```xbsl
@НаСервере
метод ПолучитьЛокализованноеОписание(Ключ: Строка, Локаль: Локаль): Строка
  исп Контекст = КонтекстЛокализации.Открыть(Локаль) 
  знч Задание = ЗапланированныеЗадания.ПолучитьПоКлючу(Ключ)
  возврат Задание.Описание
;
```

Пример получения описания задания в разных локалях

```xbsl
@НаСервере
метод ОписанияЗаданийВРазныхЛокалях()
  знч Ключ = "JobKey"
  знч ОписаниеНаРусском = ПолучитьЛокализованноеОписание(Ключ, Локаль{ru-RU})
  знч ОписаниеНаАнглийском = ПолучитьЛокализованноеОписание(Ключ, Локаль{en-US})
;
```

Параметр нельзя изменить после планирования задания.

### Расписание

[`Расписание|Обходимое<Расписание>`](../../wiki/stdlib/schedule-ru-f8ef0f9119e6.md). Задает расписание запуска задания.

Запуск задания в 8 утра 23 февраля и 8 марта

```xbsl
метод ЗапланироватьЗаданияСРасписанием()
    знч Праздничное = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод)
    Праздничное.Настроить(Расписание = [
        Расписание.Ежемесячно(Время{8:00}, {Месяц.Февраль}, {23}),
        Расписание.Ежемесячно(Время{8:00}, {Месяц.Март}, {8})])
    Праздничное.Запланировать()
;
```

### Задержка

[`Длительность`](../../wiki/stdlib/duration-ru-fef7ea46f329.md). Задает задержку начала выполнения относительно времени планирования задания:

- если задание запланировано с помощью метода
  
  [`ЗапланироватьБезТранзакции()`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md)
  
  , то задержка вычисляется от момента вызова этого метода;
- если задание запланировано с помощью метода
  
  [`ЗапланироватьВТранзакции()`](../../wiki/stdlib/updatingscheduledjob-ru-a87c312728b2.md)
  
  , то задержка вычисляется от момента окончания активной транзакции;
- если задано расписание, то задержка игнорируется.

Запуск задания с задержкой в 3 секунды

```xbsl
метод ЗапланироватьЗаданияСЗадержкой()
    знч ЗаданиеСЗадержкой = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод)
    ЗаданиеСЗадержкой.Настроить(Задержка = 3с)
    ЗаданиеСЗадержкой.Запланировать()
;
```

### ПовторыПриОшибке

[`СтратегияПовтораЗадания`](../../wiki/stdlib/jobrepeatstrategy-ru-7324071d3eef.md). Используется, чтобы запланировать повторный запуск задания, если текущий запуск завершается с ошибкой.

### ПовторыПриУспехе

[`СтратегияПовтораЗадания`](../../wiki/stdlib/jobrepeatstrategy-ru-7324071d3eef.md). Используется, чтобы запланировать повторный запуск задания при успешном завершении текущего запуска.

### СтратегияПубликации

[`СтратегияПубликацииЗадания`](../../wiki/stdlib/jobpublicationstrategy-ru-acdb64bb1d73.md). Одновременно может существовать только один экземпляр запланированного задания с определенным ключом. С помощью перечисления [`СтратегияПубликацииЗадания`](../../wiki/stdlib/jobpublicationstrategy-ru-acdb64bb1d73.md) вы можете выбрать стратегию публикации, которая будет действовать при попытке запланировать задание с существующим ключом:

- [`Отбросить`](../../wiki/stdlib/jobpublicationstrategy-ru-acdb64bb1d73.md)
  
  — отбросить новое задание и оставить существующее;
- [`Перезапустить`](../../wiki/stdlib/jobpublicationstrategy-ru-acdb64bb1d73.md)
  
  — отменить или прервать выполнение существующего задания и запустить новое.

Параметр нельзя изменить после планирования задания.

### ХранениеРезультатов

[`СтратегияХраненияРезультатовЗаданий`](../../wiki/data/jobresultsstoragestrategy-ru-60427c68ebdc.md). Задает стратегию хранения результатов выполнения задания. Возможные значения:

- [`Отсутствует`](../../wiki/data/jobresultsstoragestrategy-ru-60427c68ebdc.md)
  
  — результаты выполнения задания не хранятся;
- [`Последний`](../../wiki/data/jobresultsstoragestrategy-ru-60427c68ebdc.md)
  
  — хранится только последний результат выполнения задания, который можно получить с помощью метода
  
  [`ПолучитьПоследнийРезультатПоКлючу()`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md)
  
  типа
  
  [`ЗапланированныеЗадания`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md)
  
  ;
- [`Дней`](../../wiki/data/jobresultsstoragestrategy-ru-60427c68ebdc.md)
  
  — все результаты хранятся заданное число дней, по истечении которых автоматически удаляются;
- [`Все`](../../wiki/data/jobresultsstoragestrategy-ru-60427c68ebdc.md)
  
  — хранятся все результаты выполнения задания. Их можно получить с помощью метода
  
  [`ПолучитьРезультатыПоКлючу()`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md)
  
  типа
  
  [`ЗапланированныеЗадания`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md)
  
  .

Если известно время завершения сохраненного задания, можно воспользоваться методом [`ПолучитьРезультатыПоИнтервалу()`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md) типа [`ЗапланированныеЗадания`](../../wiki/stdlib/scheduledjobs-ru-1081e58e1cbc.md).

Получение всех результатов выполнения задания за месяц

```xbsl
пер РезультатыПоИнтервалу = ЗапланированныеЗадания.ПолучитьРезультатыПоИнтервалу(
    Момент.Сейчас()-30д,
    Момент.Сейчас()
)
```

> [!WARNING] важно
> Будьте внимательны при выборе стратегии хранения результатов [`Все()`](../../wiki/data/jobresultsstoragestrategy-ru-60427c68ebdc.md). Неосторожное использование этой стратегии может привести к переполнению базы данных.

> [!NOTE] примечание
> Не следует сохранять результаты выполнения задания для отслеживания его работы. В этих целях используйте [журнал событий](../../wiki/project/event-log-8a28c1a3e2b6.md).

### ПриОшибкеПоследнегоПовтора

([`РезультатЗадания`](../../wiki/stdlib/jobresult-ru-51de2402401f.md))->`ничто`. Обработчик, который вызывается, если последний запуск задания завершается с ошибкой.

Если для задания указана [стратегия повтора при ошибке](../../wiki/project/jobs-81f432f38905.md), обработчик вызывается после окончания всех повторов. Если стратегия повтора при ошибке не настроена или используется значение по умолчанию [`СтратегияПовтораЗадания.Отсутствует()`](../../wiki/stdlib/jobrepeatstrategy-ru-7324071d3eef.md), то обработчик запускается после первой ошибки.

Параметр нельзя изменить после планирования задания.

Создание задания с обработкой ошибки

```xbsl
метод ЗапланироватьЗаданияСОбработкойОшибки()
    знч СОбработкойОшибки = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод)

    // Метод МойМодуль.МойОбработчикОшибки() вызывается, 
    // если запуск задания СОбработкойОшибки завершится с ошибкой
    СОбработкойОшибки.Настроить(ПриОшибкеПоследнегоПовтора = &МойМодуль.МойОбработчикОшибки)
    СОбработкойОшибки.Запланировать()
;

метод МойОбработчикОшибки(Результат: РезультатЗадания)
    // Код обработчика результата с ошибкой
;
```

### РегистрацияСобытий

[`СтратегияРегистрацииСобытийЗаданий`](../../wiki/data/jobseventregistrationstrategy-ru-59354e38a51f.md). Задает стратегию регистрации событий в журнале событий:

- [`Все`](../../wiki/data/jobseventregistrationstrategy-ru-59354e38a51f.md)
  
  — регистрируются все события запланированного задания:
  
  - в момент запуска задания записывается операция
    
    [`ОперацияЗапланированногоЗадания`](../../wiki/stdlib/scheduledjoboperation-ru-faf09e9de4bd.md)
    
    , и все события, порожденные в процессе выполнения задания, регистрируются в этой операции;
  - когда выполнение задания завершается, в журнал записывается событие
    
    [`СобытиеЗапланированноеЗаданиеЗавершено`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md)
    
    ;
  - если задание завершилось с ошибкой, регистрируется событие
    
    [`СобытиеЗапланированноеЗаданиеЗавершено`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md)
    
    с указанием информации об ошибке в свойстве
    
    [`Ошибка`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md)
    
    ;
- [`Ошибка`](../../wiki/data/jobseventregistrationstrategy-ru-59354e38a51f.md)
  
  — регистрируется только ошибка запланированного задания, т. е. событие
  
  [`СобытиеЗапланированноеЗаданиеЗавершено`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md)
  
  с указанием информации об ошибке в свойстве
  
  [`Ошибка`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md)
  
  ;
- [`СобытиеЗавершения`](../../wiki/data/jobseventregistrationstrategy-ru-59354e38a51f.md)
  
  — регистрируется итоговое событие запланированного задания, т. е. событие
  
  [`СобытиеЗапланированноеЗаданиеЗавершено`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md)
  
  .

[`ОперацияЗапланированногоЗадания`](../../wiki/stdlib/scheduledjoboperation-ru-faf09e9de4bd.md) и [`СобытиеЗапланированноеЗаданиеЗавершено`](../../wiki/stdlib/scheduledjobfinishevent-ru-ac31a93e1372.md) имеют низкую важность, поэтому при очистке журнала событий они удаляются в первую очередь.

Создание задания с регистрацией ошибок

```xbsl
метод СоздатьЗаданиеСРегистрациейОшибок()
    знч Задание = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод)
    Задание.Настроить(
        Ключ = "МоеЗадание",
        ХранениеРезультатов = СтратегияХраненияРезультатовЗаданий.Отсутствует(),
        ПовторыПриУспехе = СтратегияПовтораЗадания.Интервал(1с),
        ПовторыПриОшибке = СтратегияПовтораЗадания.Интервал(1с),
        СтратегияПубликации = СтратегияПубликацииЗадания.Отбросить,
        РегистрацияСобытий = СтратегияРегистрацииСобытийЗаданий.Ошибка
    )
    Задание.Запланировать()
;
```

Обновление задания с регистрацией ошибок

```xbsl
метод ИзменитьРегистрациюСобытийЗадания()
    знч ЗаданиеСЗадержкой = ЗапланированныеЗадания.Изменить("КлючЗадания")
    ЗаданиеСЗадержкой.Настроить(РегистрацияСобытий = СтратегияРегистрацииСобытийЗаданий.Ошибка)
    ЗаданиеСЗадержкой.Запланировать()
;
```

## Примеры работы с заданиями

1. Создание и настройка задания
  
  Создание задания с периодическим запуском
  
  ```xbsl
  метод СозданиеЗаданий()
      знч Задание = ЗапланированныеЗадания.Создать(&МойМодуль.ОбработчикСозданияЗадания)
      Задание.Настроить(
          Ключ = "МоеЗапланированноеЗадание",
          ХранениеРезультатов = СтратегияХраненияРезультатовЗаданий.Отсутствует(),
          Расписание = Расписание.Периодическое(1с),
          СтратегияПубликации = СтратегияПубликацииЗадания.Отбросить)
      Задание.Запланировать()
  ;
  ```
  
  В этом примере планируется периодический запуск задания с периодом равным одной секунде. Если в момент вызова задание уже выполнялось или ожидало выполнения, то повторно оно не планируется. Результаты выполнения не сохраняются.
  
  По такому принципу можно организовать обработку очереди на основе справочника:
  
  - вызывать этот код при добавлении нового элемента справочника;
  - в обработчике задания обрабатывать записи, накопленные в справочнике на момент вызова;
  - за счет повторов реализуется обработка записей, добавленных во время работы предыдущей итерации.
2. Запуск задания и изменение расписания существующего задания
  
  Создание задания и изменение его расписания
  
  ```xbsl
  метод СозданиеИНастройкаЗадания()
      знч Ключ = "ЗаданиеПраздничнойРассылки"
  
      пер НовоеЗадание = ЗапланированныеЗадания.Создать(&МойМодуль.МойМетод)
      НовоеЗадание.Настроить(
          Расписание = Расписание.Ежемесячно(Время{18:00}, {Месяц.Февраль}, {23}),
          Ключ = Ключ,
          Описание = "Праздничная рассылка"
      )
      НовоеЗадание.Запланировать()
  ;
  
  метод ИзменениеЗаданияПоКлючу(Ключ: Строка)
      знч ИзмЗадание = ЗапланированныеЗадания.Изменить(Ключ)
      если ИзмЗадание == Неопределено
          выбросить новый ИсключениеВыполнения("Нет задания с ключом %{Ключ}")
      ;
  
      ИзмЗадание.Настроить(Расписание = Расписание.Ежемесячно(Время{8:00}, {Месяц.Март}, {8}))
      ИзмЗадание.Запланировать()
  ;
  ```
3. Планирование задания для реализации асинхронной подготовки состояния взаиморасчетов для внешних систем
  
  Внешние системы обращаются к приложению с помощью специального HTTP-сервиса. Они хотят получить состояние взаиморасчетов, подготовка которого занимает значительное время. Чтобы подготовка происходила асинхронно, реализуем ее с помощью запланированного задания, которое запускается в обработчике `ЗапроситьДанные()` HTTP-сервиса. Результаты по мере готовности отдаются в обработчике `ЗапроситьРезультат()`.
  
  Результат описывается хранимой структурой `СостояниеВзаиморасчетов`. Логика вычисления возвращаемого набора данных описывается в методе `ПодготовитьДанныеВзаиморасчетов()` общего модуля `МодульПодготовкиДанных`.
  
  Общий модуль «МодульПодготовкиДанных»
  
  ```xbsl
  @ВПодсистеме
  метод ПодготовитьДанныеВзаиморасчетов(Контрагент: Контрагент.Ссылка): СостояниеВзаиморасчетов
      // Вычисление возвращаемого набора данных
      возврат новый СостояниеВзаиморасчетов()
  ;
  ```
  
  Модуль HTTP-сервиса
  
  ```xbsl
  метод ЗапроситьДанные(Запрос: HttpServiceRequest)
      // Каждая внешняя система проходит аутентификацию,
      // обработчик выполняется от имени пользователя, соответствующего контрагенту
      знч СсылкаКонтрагента = ПолучитьКонтрагента(Пользователи.ТекущийПользователь)
      если СсылкаКонтрагента == Неопределено
          выбросить новый ИсключениеНедопустимыйАргумент()
      ;
  
      // Чтобы не выполнять одновременно несколько вычислений для одного контрагента,
      // формируем ключ задания из идентификатора контрагента и используем стратегию Отбросить.
      // Определяем предельный срок хранения результатов 1 день
      знч Задание = ЗапланированныеЗадания.Создать(&МодульПодготовкиДанных.ПодготовитьДанныеВзаиморасчетов, СсылкаКонтрагента)
          .Настроить(
              СтратегияПубликации=СтратегияПубликацииЗадания.Отбросить,
              Ключ = "BAL-%{СсылкаКонтрагента.Ид}",
              ХранениеРезультатов=СтратегияХраненияРезультатовЗаданий.Дней(1)
          )
          .Запланировать()
      Запрос.Ответ.УстановитьКодСтатуса(202)
  
      // Отдаем ключ задания, чтобы внешняя система могла узнать по нему результат,
      // и ожидаемый момент завершения
      пер ОтветСервиса = {"key": Задание.Ключ, "estimated-time": Момент.Сейчас() + 5м}
      Запрос.Ответ.УстановитьТело(СериализацияJson.ЗаписатьОбъект(ОтветСервиса))
  ;
  
  метод ЗапроситьРезультат(Запрос: HttpServiceRequest)
      // Получаем ключ из параметра запроса
      знч Ключ = Запрос.Параметры.ПолучитьПервый("key")
      если Ключ == Неопределено
          выбросить новый ИсключениеНедопустимыйАргумент()
      ;
  
      // По ключу получаем последний результат задания
      знч Результат = ЗапланированныеЗадания.ПолучитьПоследнийРезультатПоКлючу(Ключ)
  
      // Если результата еще нет, пробуем получить описание задания
      // и устанавливаем соответствующий код статуса
      если Результат == Неопределено
          знч Задание = ЗапланированныеЗадания.ПолучитьПоКлючу(Ключ)
          Запрос.Ответ.УстановитьКодСтатуса(Задание == Неопределено ? 404 : 202)
          возврат
      ;
  
      // Если задание завершилось с ошибкой, записываем ее описание в ответ запроса,
      // если нет — записываем в ответ результат выполнения
      если Результат.Ошибка != Неопределено
          Запрос.Ответ.УстановитьКодСтатуса(500)
          Запрос.Ответ.УстановитьТело(Результат.Ошибка)
      иначе
          Запрос.Ответ.УстановитьТело(СериализацияJson.ЗаписатьОбъект(Результат.Результат))
      ;
  ;
  ```

## Форма для управления заданиями

Для управления запланированными заданиями используется специальная форма [`ФормаЗаданий`](../../wiki/interface/jobsform-ru-a640c24a627c.md). Форма позволяет выполнять следующие действия:

- просматривать список запланированных заданий приложения;
- находить задание по ключу;
- фильтровать задания по статусу;
- просматривать данные запланированного задания с детализацией следующей информации:
  
  - ключ,
  - статус,
  - момент запуска или следующего исполнения,
  - описание,
  - длительность последнего исполнения,
  - число неуспешных попыток,
  - число успешных повторов,
  - расписание;
- переходить в журнал событий, чтобы просмотреть события выбранного задания;
- приостанавливать, возобновлять, отменять и удалять запланированное задание;
- изменять расписание запланированного задания;
- программно настраивать фильтр отображаемых в форме заданий.

Форма управления заданиями показана в двух областях: слева список заданий с поиском, фильтрами Все, Выполняются, Ожидают, Остановлены и кнопками действий у строк; справа подробности выбранного задания, ссылка «Перейти в журнал событий» и раздел Расписание. [Описание иллюстрации](../figures/219b010594e2dfd22992a3684cb1fc69773186d612e8970be718dd7c23f0d1eb-290b1b44a3645ede.md)

Вид и поведение формы [`ФормаЗаданий`](../../wiki/interface/jobsform-ru-a640c24a627c.md) можно настроить, указав требуемые значения параметров при создании. Например:

Форма открывается с параметрами по умолчанию

```xbsl
новый ФормаЗаданий().Открыть()
```

Форма открывается с настроенными параметрами

```xbsl
новый ФормаЗаданий(ТолькоЧтение = Истина).Открыть()
```

Форма открывается с отображением заданий, ключ которых начинается на MyJob

```xbsl
новый ФормаЗаданий(ФильтрЗаданий = Задание -> Задание.Ключ.НачинаетсяС("MyJob")).Открыть()
```

### Редактирование расписания

Чтобы открыть форму [`ФормаЗаданий`](../../wiki/interface/jobsform-ru-a640c24a627c.md) с возможностью редактирования расписания запланированных заданий, необходимо задать свойству [`РазрешеноИзменение`](../../wiki/interface/jobsform-ru-a640c24a627c.md) значение `Истина`:

```xbsl
новый ФормаЗаданий(РазрешеноИзменение = Истина).Открыть()
```

В разделе **Расписание** формы [`ФормаЗаданий`](../../wiki/interface/jobsform-ru-a640c24a627c.md) появится возможность добавлять, изменять и удалять элементы расписания:

В секции «Расписание» формы заданий показаны кнопка «Добавить» с меню и строка «Ежедневно в 12:00:00». [Описание иллюстрации](../figures/0173866859e6037a563f3025d0ccd87e7816533723650a5bf8e01e08dbbbe6c8-416550bdc852d010.md)

Вы можете добавить такие элементы расписания, как:

- Однократно
  
  ,
- Ежедневно
  
  ,
- Еженедельно
  
  ,
- Ежемесячно
  
  ,
- Постоянно
  
  .

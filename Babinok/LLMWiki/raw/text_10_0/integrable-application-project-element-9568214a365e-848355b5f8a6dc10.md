Элемент проекта **ИнтегрируемоеПриложение** предназначен для удобной передачи сообщений обмена данными между планами обмена двух приложений «1С:Предприятие.Элемента».

Чтобы создать интегрируемое приложение, [добавьте в проект](../../wiki/project/add-project-element-9c25777c6bb1.md) элемент вида **ИнтегрируемоеПриложение**. Каждый элемент проекта описывает подключение к одному внешнему приложению.

## Настройки подключения

После добавления элемента проекта в режиме разработки необходимо настроить подключение к внешнему приложению в запущенном приложении. Для этого необходимо создать запись в форме объекта интегрируемого приложения, в которой будут указаны параметры, по которым текущее приложение будет устанавливать соединение с внешним:

Пример создания экземпляра приложения [Описание иллюстрации](../figures/cc858ee839201cece4561bdf0010e97c5a24c5e8526b3b618c771630b4cf2fbf-42c4eb8e39b51b9f.md)

Параметры подключения хранятся в стандартном системном реквизите **НастройкиПрямогоПодключения** типа [`НастройкиПрямогоПодключенияИнтегрируемогоПриложения`](../../wiki/stdlib/integrableapplicationdirectconnectionsettings-ru-be451c16a3f9.md). Реквизит является системным и добавляется автоматически, этот реквизит не отображается в среде разработки и его нельзя изменить.

Структура `НастройкиПрямогоПодключенияИнтегрируемогоПриложения` содержит три поля:

- `Адрес`
  
  — адрес подключения, по которому доступно внешнее приложение. Соответствует адресу приложения.
- `ИдКлиента`
  
  — идентификатор клиента, выдаваемый администратором внешнего приложения.
  
  Client-ID
  
  ключа доступа к приложению.
- `СекретКлиента`
  
  — секрет клиента, выдаваемый администратором внешнего приложения.
  
  Client-Secret
  
  ключа доступа к приложению.

Идентификатор клиента и секрет клиента соответствуют специальному пользователю-сервису. Такой пользователь может подключаться только как сервис и не может подключаться как обычный клиент.

[Подробнее о получении ключей доступа пользователя](../../wiki/security/get-user-key-9b77ae83ecbb.md)

## Связь с планом обмена

Чтобы начать автоматический периодический обмен данными текущего приложения с внешним, необходимо настроить передачу данных в плане обмена. Свойство [ПередачаДанных](../../wiki/integration/exchangeplan-47d882fe414b.md) плана обмена описывает обмен данными между текущим и внешним приложениями и позволяет:

- включить использование передачи данных,
- указать допустимые интегрируемые приложения для обмена данными,
- указать имя плана обмена во внешнем проекте.

В массиве **ИнтегрируемыеПриложения** свойства **ПередачаДанных** перечисляются интегрируемые приложения, которые могут использоваться для обмена данными. Для каждого интегрируемого приложения указывается имя плана обмена во внешнем проекте.

В настройках ПередачаДанных показаны ВидПакетаПередачиДанных — ВсеИзменения; элемент ИнтегрируемыеПриложения: Имя — ПриложениеСклад, ИмяПланаОбменаВИнтегрируемомПриложении — УдаленныеСклады; Использовать — Истина. [Описание иллюстрации](../figures/bc18e7c8b78a8274dfbfdfa9461056afb9dd24ffbf13feab7df7fd5cdb924421-4bcec51f6690da5e.md)

Если передача данных не настроена в элементе проекта, активировать ее в узле плана обмена нельзя. В этом случае разработчик проекта реализует обмен данными самостоятельно.

Когда в элементе проекта настроена передача данных (свойство **ПередачаДанных.Использовать** равно **Истина**), «1С:Предприятие.Элемент» порождает тип [`{ИмяПланаОбмена}.НастройкиПередачиДанных`](../../wiki/integration/exchangeplanname-datatransfersettings-ru-c6f454de020a.md). Тип порождается отдельно для каждого плана обмена, так как содержит ссылку на интегрируемое приложение, заданное в элементе проекта. Свойства типа позволяют указать экземпляр интегрируемого приложения, соответствующего внешнему приложению, и активировать передачу данных узла плана обмена.

## Запланированное задание

Чтобы обмен выполнялся автоматически по расписанию, «1С:Предприятие.Элемент» создает [запланированное задание](../../wiki/project/jobs-81f432f38905.md) для каждого узла плана обмена с активированной передачей данных. Одно запланированное задание обрабатывает один узел плана обмена. Ключ задания формируется по шаблону `DataExchange-{ИдПланаОбмена}-{ИдУзлаПланаОбмена}`. Идентификаторы кодируются в формате `Base64 UrlEncode`. Пример: `DataExchange-ktpX4AgKSkqGaeC47q_k5g-AZ5DvCZ0cLCUSBybPUAUJQ`.

Пример запланированного задания [Описание иллюстрации](../figures/b1787e8113ddc4e5405f186fbc38f827ab44862ca69574282d32970b3cf3f73c-9a3583f5e9ad6ffd.md)

Расписание по умолчанию — один раз в минуту. Ключ созданного задания записывается в свойстве [`КлючЗапланированногоЗадания`](../../wiki/integration/exchangeplanname-datatransfersettings-ru-c6f454de020a.md) настроек передачи данных узла плана обмена.

Запланированное задание создается при активации передачи данных. Задание удаляется, если:

- удален узел плана обмена с активированной передачей данных,
- удален элемент проекта плана обмена,
- деактивирована передача данных.

## Настройки обмена между приложениями

Между двумя приложениями «1С:Предприятие.Элемента» возможны два варианта настройки обмена данными. Обмен данными в обоих вариантах всегда выполняется в две стороны, разница только в том, какое приложение может инициировать обмен.

В первом варианте элемент проекта **ИнтегрируемоеПриложение** добавляется только в одном проекте — в том, который будет устанавливать подключение и инициировать обмен. Второй проект содержит только план обмена, без интегрируемого приложения, и для сопоставления плана обмена в этом проекте с планом обмена во внешнем проекте используется свойство [ИмяПланаОбменаВИнтегрируемомПриложении](../../wiki/integration/exchangeplan-47d882fe414b.md). Обмен в обе стороны запускается только из приложения, в котором добавлено интегрируемое приложение (см. [пример](../../wiki/integration/exchange-example-4841fbdc5790.md)).

Во втором варианте элемент проекта **ИнтегрируемоеПриложение** добавляется в оба проекта, и в обоих приложениях активна передача данных. Каждое приложение по своему расписанию может установить соединение с другим и инициировать обмен.

## Обмен данными

Когда в запущенном приложении настроены параметры подключения и активна передача данных, «1С:Предприятие.Элемент» устанавливает соединение с внешним приложением и выполняет обмен данными в потоковом режиме.

Проекты приложений, между которыми выполняется обмен, могут отличаться именами элементов. В этом случае используются свойства [ИмяПланаОбменаВИнтегрируемомПриложении](../../wiki/integration/exchangeplan-47d882fe414b.md) и [ИмяВИнтегрируемомПриложении](../../wiki/project/integrableapplication-6b34fc19cb72.md) — поиск во внешнем приложении выполняется по значению свойства вместо имени текущего элемента. Соответствие устанавливается по совпадению значений свойств в обоих проектах. Например, если в текущем проекте есть план обмена **ПланОбмена1** со свойством **ИмяПланаОбменаВИнтегрируемомПриложении = ПО**, а во внешнем — **ПланОбмена2** с таким же значением свойства, соответствие будет найдено.

### Установка соединения

При необходимости выполнить обмен данными приложение устанавливает соединение с внешним приложением по адресу, указанному в [настройках прямого подключения](../../wiki/project/integrable-application-project-element-9568214a365e.md) в поле **Адрес**. Сначала приложение получает токен, затем запрашивает метаданные внешнего приложения: доступные механизмы и способы подключения. После этого устанавливается долговременное соединение для передачи данных.

Если в настройках адреса указан протокол `https`, соединение устанавливается по защищенному каналу, если `http` — по открытому. Соединение закрывается сразу после завершения обмена.

### Потоковая передача данных

После установки соединения «1С:Предприятие.Элемент» выполняет обмен данными в потоковом режиме. Изменения данных обрабатываются параллельно и асинхронно, по одному изменению за раз, без ожидания завершения обработки всего сообщения.

В приложении-отправителе выполняются два этапа:

- Выгрузка
  
  в отдельном потоке создает обработку исходящего сообщения, выбирает изменения из БД и для каждого изменения вызывает конвертацию. Полученные данные передаются на этап
  
  отправки
  
  .
- Отправка
  
  в отдельном потоке устанавливает соединение и при получении изменения от этапа выгрузки передает его через установленное соединение.

В приложении-получателе выполняются два этапа:

- Получение
  
  в отдельном потоке принимает изменение через установленное соединение и передает его в загрузку.
- Загрузка
  
  в отдельном потоке создает обработку входящего сообщения, загружает изменение и ожидает уведомления от отправителя о завершении выгрузки всего сообщения, после чего закрывает обработку и фиксирует транзакцию.

### Обработка сбоев

Когда между приложениями выполняется обмен данными, важно гарантировать их целостность: после завершения транзакции на одной стороне не должно быть ситуации, когда отправитель считает данные загруженными получателем, но получатель их не загрузил, или наоборот.

Чтобы добиться этого, получатель фиксирует транзакцию загрузки только после получения уведомления от отправителя о фиксации транзакции выгрузки. Если после фиксации транзакции в отправителе в получателе происходит сбой, отправитель повторит выгрузку изменений: регистрация изменений в отправителе удаляется только тогда, когда от получателя принимается сообщение обмена данными с указанием номера последнего принятого сообщения.

Любой сбой приводит к прерыванию обработки и откату транзакции. Сбой в одном участнике приводит к сбою в другом: участник после обработки сбоя уведомляет другого. Сбой сетевого подключения приводит к сбою в обоих участниках. Если сбой в получателе происходит после того, как отправитель уже зафиксировал транзакцию выгрузки, получатель не отправляет уведомление о сбое, откатывает свою транзакцию и завершает загрузку. Во всех сценариях сбоя регистрация изменений в отправителе не удаляется, изменения данных будут отправлены при следующей выгрузке.

#### Вид пакета передачи данных

Поведение при сбоях зависит от значения свойства [ВидПакетаПередачиДанных](../../wiki/integration/exchangeplan-47d882fe414b.md) в настройке **ПередачаДанных** плана обмена.

При значении **ВсеИзменения** (по умолчанию) выгрузка и загрузка сообщения выполняются в транзакции, в сообщение включаются все изменения данных на момент обработки. При сбое обработки одного изменения остальные изменения не обрабатываются, ранее обработанные изменения не сохраняются.

При значении **ОдноИзменение** выгрузка и загрузка сообщения выполняются вне транзакции. Сбой обработки одного изменения не прерывает обработку сообщения: вместо этого регистрация изменения исключается из сообщения, чтобы при фиксации успешной обработки сообщения регистрация изменений не была удалена и обработка изменения была выполнена повторно. Для этого номер сообщения в регистрации изменения устанавливается равным `Null`, изменение будет отправлено в следующем сообщении.

## Параллельная работа и доступ

В варианте с настройками в обоих приложениях при совпадении расписания возможны взаимные блокировки при параллельной загрузке в разные приложения. Чтобы этого избежать, блокировки упорядочиваются по коду узла: если код узла текущего приложения меньше кода узла внешнего приложения, блокировка устанавливается до блокировки во внешнем приложении, если больше — после. Поскольку коды узлов одинаковы в обоих приложениях, этого достаточно для предотвращения взаимных блокировок.

Приложение, устанавливающее соединение, выполняет действия в рамках запланированного задания под системным пользователем без ограничения прав. Приложение, принимающее соединение, выполняет действия в рамках фонового задания, созданного для пользователя, под которым подключается внешнее приложение. Этот пользователь должен иметь права на чтение и запись элементов проекта, входящих в состав плана обмена. Удаление регистрации изменений в рамках метода `ВыгрузитьСообщение()` и в рамках взаимодействия выполняется без права администрирования.

## Дополнительные пространства управляемых блокировок

Если вам недостаточно стандартных пространств блокировок интегрируемого приложения, вы можете создать одно или несколько дополнительных пространств. Для каждого дополнительного пространства укажите имя, идентификатор и список реквизитов, которые входят в это пространство. Можно использовать все реквизиты, кроме стандартного реквизита **Ссылка**.

При записи экземпляра интегрируемого приложения «1С:Предприятие.Элемент» устанавливает блокировки:

- на пространство ссылки,
- на все дополнительные пространства (стандартные и пользовательские) с актуальными (новыми) значениями реквизитов,
- на все дополнительные пространства (стандартные и пользовательские) со старыми значениями реквизитов, если записывается существующий объект.

Дополнительные пространства управляемых блокировок [автоматически используются](../../wiki/data/transactions-and-controlled-locks-fef75789dc76.md) «1С:Предприятие.Элементом». Кроме того, вы можете [использовать](../../wiki/data/transactions-and-controlled-locks-fef75789dc76.md) их самостоятельно.

## Язык запросов

Для интегрируемого приложения «1С:Предприятие.Элемент» формирует в языке запросов соответствующую таблицу [`{ИмяИнтегрируемогоПриложения}`](../../wiki/queries/integrableapplicationname-ru-6017dac8a70c.md). Таблица содержит записи, соответствующие экземплярам интегрируемого приложения. Одна запись таблицы — один экземпляр интегрируемого приложения.

Пример запроса к таблице приложения «ПриложениеСклад»

```xbql
ВЫБРАТЬ
    ПриложениеСклад.Ссылка КАК Ссылка,
    ПриложениеСклад.НастройкиПрямогоПодключения КАК НастройкиПрямогоПодключения,
    ПриложениеСклад.Наименование КАК Наименование,
    ПриложениеСклад.Представление КАК Представление
ИЗ
    ПриложениеСклад КАК ПриложениеСклад
```

Проект — это описание логики приложения, которое может быть исполнено сервером, например: **Личный кабинет** или **Мобильная касса**.

Проект состоит из:

- подсистем
  
  и
  
  пакетов
  
  , которые описывают его структуру;
- элементов
  
  , в том числе
  
  компонентов интерфейса
  
  , и
  
  модулей
  
  , которые описывают функциональные возможности приложения;
- ресурсов
  
  , которые содержат произвольные файлы (картинки, иконки, аудиофайлы и т. д.).

## Виды элементов проекта

Чтобы описать логику приложения, вы добавляете в проект элементы того или иного вида. В «1С:Предприятие.Элементе» определено большое количество элементов проекта для решения различных задач ([подробнее](../../wiki/interface/all-project-elements-5977d6a645f5.md)).

Если вы хотите узнать, какие элементы проекта нужны для решения интересующей вас задачи, перейдите в раздел **Функциональность приложения**.

## Библиотеки

При разработке программных продуктов часто возникает задача повторного использования общего кода и элементов проекта. Для решения этой задачи рекомендуется использовать [библиотеки](../../wiki/project/create-and-use-libraries-38193c200df0.md). Как правило, они представляют собой набор готовых универсальных механизмов для решения различных задач. Также их можно применять для разбиения большого проекта на части и распределения этих частей между командами разработчиков. Использование библиотек помогает избежать дублирования кода и ускорить разработку приложений.

## Жизненный цикл

Любой проект имеет определенный [жизненный цикл](../../wiki/project/project-life-cycle-edbde650e053.md), который включает в себя создание проекта, его модификацию и использование.

## Элемент проекта

[Элементы проекта](../../wiki/project/project-element-e0f54b4a4951.md) определяют функциональность приложения, описывают структуры хранения данных, наборы прав и другую информацию, необходимую «Элементу» для построения приложения.

## Иерархическая структура проекта

Проект имеет [иерархическую структуру](../../wiki/project/hierarchical-project-structure-397ba5e7f9df.md), которая разделяет приложение на изолированные части — подсистемы.

## Ресурсы

[Ресурсы](../../wiki/project/resource-in-project-b42041684d83.md) — это произвольные файлы, которые требуются для работы приложения. У каждой подсистемы может быть собственный набор ресурсов со своей областью видимости.

## Модульная разработка

В функциональном смысле проект разделен на изолированные части, каждая из которых может использоваться в других частях проекта ([подробнее](../../wiki/language/modular-development-80166cfecf93.md)).

## Модуль

[Модуль](../../wiki/language/module-f92cc205e14d.md) — это элемент проекта, который содержит текст на языке «1С:Элемент». Каждый модуль относится к тому или иному типу языка. Модуль расширяет [контракт](../../wiki/language/types-and-their-hierarchy-282f6415d4e1.md) этого типа.

## Реквизиты

[Реквизит](../../wiki/data/attribute-1a18bd4e7979.md) — это составная часть элемента проекта, описывающая одно поле таблицы базы данных.

## Реквизиты-коллекции

[Реквизит-коллекция](../../wiki/data/collection-type-attribute-55d55dbeb248.md) — это реквизит, который имеет тип `Массив`. С помощью такого реквизита для одного экземпляра сущности можно хранить набор значений.

Если в проекте есть компонент, унаследованный от типа [`СтандартноеКлиентскоеПриложениеСРазделами`](../../wiki/interface/standardclientapplicationwithsections-ru-2bf3e285c484.md), то «1С:Предприятие.Элемент» будет использовать для приложения автоматический интерфейс, содержащий следующие области:

- Панель навигации
  
  — основная панель для общей навигации по приложению. Отображается либо слева, либо сверху, в зависимости от свойства
  
  [ОриентацияПанелиНавигации](../../wiki/interface/standard-client-application-with-sections-component-49da52beb720.md)
  
  . В мобильном варианте трансформируется в мобильную нижнюю панель навигации.
- Область содержимого — основная часть интерфейса приложения, в которой открываются
  
  формы
  
  .
- Панель действий
  
  — позволяет выполнять основные действия над приложением, такие как смена цветовой схемы и языка приложения, перемещение по ранее открытым вкладкам, получение информации о приложении, работа с уведомлениями. Расположена справа. В мобильном варианте перемещается наверх.
- [ДополнительныйКомандныйИнтерфейс](../../wiki/interface/standard-client-application-with-sections-component-49da52beb720.md)
  
  — нижняя часть панели действий, обычно содержит команды профиля или завершения работы с приложением.

Размеченный интерфейс приложения: панель навигации слева, область содержимого в центре, панель действий справа и дополнительный командный интерфейс в нижней части правой панели. [Описание иллюстрации](../figures/55c4e71078c29dd238752e9c5b0636a819ddc8304241661ab8886b410c727dd9-52288e70e0391469.md)

Для наполнения областей интерфейса командами вы можете использовать следующие элементы в [редакторе компонента](../../wiki/interface/ide-overview-and-basic-actions-969a6e6501a6.md) [`СтандартноеКлиентскоеПриложениеСРазделами`](../../wiki/interface/standardclientapplicationwithsections-ru-2bf3e285c484.md):

- [КомандныйИнтерфейсПанелиНавигации](../../wiki/interface/standard-client-application-with-sections-component-49da52beb720.md)
  
  ,
- [КомандныйИнтерфейсПанелиДействий](../../wiki/interface/standard-client-application-with-sections-component-49da52beb720.md)
  
  ,
- [ДополнительныйКомандныйИнтерфейс](../../wiki/interface/standard-client-application-with-sections-component-49da52beb720.md)
  
  .



Свойства компонента позволяют вам выбрать горизонтальную или вертикальную ориентацию командного интерфейса, настроить отображение логотипа и названия приложения, видимость [центра уведомлений](../../wiki/project/notifications-cd338f518620.md) и информации о приложении, а также другие параметры визуального отображения приложения.

Если вы не описали **КомандныйИнтерфейсПанелиНавигации** или не создали формы для каких-то элементов проекта, то «1С:Предприятие.Элемент» будет использовать автоматические команды и формы так же, как и для [автоматического интерфейса](../../wiki/interface/auto-generated-ui-7150689c0714.md).

### ОриентацияПанелиНавигации

`Авто|ОриентацияПанелиНавигации`. Определяет ориентацию панели навигации приложения. Возможные значения:

- `Авто`
  
  — значение
  
  `ОриентацияПанелиНавигации.Вертикальная`
  
  ;
- `ОриентацияПанелиНавигации.Вертикальная`
  
  — вертикально слева (слева от области содержимого);
- `ОриентацияПанелиНавигации.Горизонтальная`
  
  — горизонтально сверху (над областью содержимого).

Сравнение ориентаций панели навигации: в верхнем примере меню разделов расположено вертикально слева от содержимого, панель действий — справа. [Описание иллюстрации](../figures/80e4f95e7fa95089468e21e15a18fe4883c4148c0327d43a97649cac11dbd40a-6c7dfa16e82dc3a5.md)

Пример YAML-файла:

```yaml
ВидЭлемента: КомпонентИнтерфейса
ОбластьВидимости: ВПодсистеме
Ид: 8e6c16f6-a3f8-4a63-a53d-d48aa146a3c9
Имя: МоеПриложение
Наследует:
    Тип: СтандартноеКлиентскоеПриложениеСРазделами
    ОриентацияПанелиНавигации: Горизонтальная
```

### РасположениеЗаголовка

`Авто|РасположениеЗаголовкаПриложения`. Способ совместного отображения логотипа и заголовка приложения. Возможные значения:

- `Авто`
  
  —
  
  «Элемент»
  
  использует вариант
  
  `РасположениеЗаголовкаПриложения.Горизонтально`
  
  ;
- элементы перечисления
  
  `РасположениеЗаголовкаПриложения`
  
  :
  
  - `Горизонтально`
    
    —
    
    «Элемент»
    
    отображает заголовок справа от логотипа;
  - `Вертикально`
    
    —
    
    «Элемент»
    
    отображает заголовок под логотипом;
  - `НеОтображать`
    
    —
    
    «Элемент»
    
    отображает только логотип, заголовок не отображается.

Три варианта расположения заголовка приложения рядом с логотипом: «Горизонтально» — справа от логотипа, «Вертикально» — под логотипом, «НеОтображать» — виден только логотип. [Описание иллюстрации](../figures/58131a0ad74e331d1ffa2dfb60bbf7353d5755b90cd8b99f8f467d461a1a5b8b-a2da0c7d16daf346.md)


### ИспользоватьВебЧат

`Авто|Булево`. Включить/отключить использование веб-чата в приложении.

### Путь

Путь публикации данного приложения ([подробнее](../../wiki/interface/selecting-interface-at-application-startup-8bfc6b427dba.md)). Должен содержать один сегмент пути или пустую строку. Не должен содержать следующие зарезервированные пути:

- api,
- stdapi,
- sys,
- ui.

Если содержит пустую строку, то входом в приложение является точка публикации проекта. Если путь указан, то входом в приложение является путь публикации проекта плюс данный путь. Пример YAML-файла:

```yaml
ВидЭлемента: КомпонентИнтерфейса
ОбластьВидимости: ВПодсистеме
Ид: 8e6c16f6-a3f8-4a63-a53d-d48aa146a3c9
Имя: МоеПриложение
Наследует:
    Тип: СтандартноеКлиентскоеПриложениеСРазделами
    Путь: back-office
```

### ПараметрыКаноническогоUrl

`Массив<Строка>|Авто`. Указывает, какие дополнительные параметры URL (при их наличии) необходимо использовать при составлении *канонической ссылки*. Данная ссылка будет использоваться поисковыми системам, чтобы определить, какую версию страницы считать основной среди одинаковых или похожих страниц. Это позволит избежать проблем с индексацией и улучшить качество поиска ([подробнее](../../wiki/project/seo-optimization-27876869518e.md)).

Параметры URL чувствительны к регистру.

При `Авто` все дополнительные параметры отбрасываются.

Независимо от значения свойства, для приложения, унаследованного от типа [`СтандартноеКлиентскоеПриложениеСРазделами`](../../wiki/interface/standardclientapplicationwithsections-ru-2bf3e285c484.md), в каноническую ссылку включаются параметры **state** и **navLink** (при их наличии).

### SeoОписание

`Авто|Строка`. Задает описание приложения, которое сохраняется в HTML-разметке страницы как значение мета-тега `description`. Используется поисковыми системами для создания краткого описания страницы приложения в поисковой выдаче ([подробнее](../../wiki/project/seo-optimization-27876869518e.md)).

При `Авто` используется значение свойства [SeoОписание](../../wiki/interface/form-component-975c31cd89e9.md) активной формы, иначе — пустая строка.

### РежимАутентификации

Необходимость аутентификации пользователя при входе в приложение:

- Аутентифицированный
  
  — пользователь будет автоматически перенаправлен на страницу аутентификации;
- НеАутентифицированный
  
  — может работать анонимный пользователь. Стандартно это свойство имеет значение
  
  Аутентифицированный
  
  , но вы можете установить его в значение
  
  НеАутентифицированный
  
  и тогда пользователь не будет перенаправлен на страницу аутентификации при входе в приложение. Такого пользователя не будет в списке подключенных пользователей и
  
  `Пользователи.ТекущийПользователь`
  
  будет возвращать
  
  `Неопределено`
  
  . Пример YAML-файла:

```yaml
ВидЭлемента: КомпонентИнтерфейса
ОбластьВидимости: ВПодсистеме
Ид: 8e6c16f6-a3f8-4a63-a53d-d48aa146a3c9
Имя: МоеПриложение
Наследует:
    Тип: СтандартноеКлиентскоеПриложениеСРазделами
    РежимАутентификации: НеАутентифицированный
```

Список [импортированных пространств имен](../../wiki/language/modular-development-80166cfecf93.md).

Имя компонента интерфейса.

### ОбластьВидимости

[Область видимости](../../wiki/language/modular-development-80166cfecf93.md) компонента интерфейса. Возможные значения:

- ВПодсистеме

- Глобально

Тип наследуемого компонента.

### НастройкиТипа

`Массив<Тип>`. Имена [контрактов типа](../../wiki/language/type-contract-ab9f0932850d.md), которые реализует данный компонент.

### ВесПриРастягивании

Значимость данного компонента по сравнению с другими растягиваемыми компонентами. Например, если у данного компонента `ВесПриРастягивании` = 1, а у другого `ВесПриРастягивании` = 2, то другой компонент будет в 2 раза больше данного ([подробнее](../../wiki/interface/arrange-components-on-screen-ebea0719d919.md)).

### Видимость

Показать или скрыть компонент. Фактическая видимость компонента зависит от видимости его родительских компонентов.

### ВыравниваниеВГруппеПоВертикали

Способ вертикального выравнивания этого компонента внутри родительской группы:

- `Авто`
  
  — значение
  
  `ВыравниваниеПоВертикали.ПоБазовойЛинии`
  
  ;
- элементы перечисления
  
  `ВыравниваниеПоВертикали`
  
  —
  
  `Верх`
  
  ,
  
  `Центр`
  
  ,
  
  `Низ`
  
  ,
  
  `ПоБазовойЛинии`
  
  .

Позволяет управлять индивидуальным положением этого компонента в группе, если размер группы больше размера, требуемого всем ее компонентам. Например, если «Элемент» растягивает группу, а компоненты в ней не растягивает.

Для компонента, расположенного внутри вертикальной группы, это свойство имеет смысл только в том случае, если этот компонент крайний. Например, если компоненты группы расположены вверху, то последний компонент можно расположить внизу.

Пример конфликта вертикального выравнивания: у второго компонента задано «Низ», у третьего — «Верх». [Описание иллюстрации](../figures/3ff4b64f82a737d0c02aeba39b29550b97f42ffe1d03d2eb5be1c50cc604b5f2-0bfb279a636f5778.md)

### <Свойство разработчика>

Собственное свойство компонента, добавленное разработчиком. Описывается следующими свойствами:

#### ЗначениеПоУмолчанию

Стандартное значение свойства. Значение можно не указывать, если у его типа/типов есть значение по умолчанию (в частности, если его тип включает `Неопределено` или `Null`). Если тип свойства составной (включает несколько типов), необходимо указать тип значения. Иначе просто само значение.

В [описании экземпляра](../../wiki/interface/system-and-interface-components-18287074edda.md) этого компонента вы можете установить другое значение этому свойству.

#### Имя

Имя свойства.

#### Контекстное

`Булево`. Признак доступности значения свойства на клиенте и сервере. Значение по умолчанию — `Ложь`. Если `Истина`, то поле **Тип** свойства должно содержать тип, доступный на клиенте и сервере.

«1С:Предприятие.Элемент» генерирует структурный тип [`{ИмяКомпонента}.Контекст`](../../wiki/interface/componentname-context-ru-e40a3f370a75.md), который содержит как собственные контекстные свойства, так и контекстные свойства, наследуемые от базовых системных типов. Этот тип генерируется всегда, даже если контекстные свойства отсутствуют.

Пример:

```yaml
Имя: МойКомпонент
Свойства:
    -
        Имя: КонтекстноеСвойство
        Тип: Строка
        Контекстное: Истина
```

Для работы с контекстными свойствами на сервере вы можете использовать *контекстные серверные методы*. Эти методы должны располагаться в модуле компонента интерфейса и содержать аннотации [`@Контекстный`](../../wiki/stdlib/contextual-ru-468258bf9c74.md) и [`@НаСервере`](../../wiki/stdlib/onserver-ru-ff4072dae1ed.md). В теле метода тип объекта `этот` заменяется на [`{ИмяКомпонента}.Контекст`](../../wiki/interface/componentname-context-ru-e40a3f370a75.md). Состояние этого объекта передается с клиента на сервер при каждом вызове метода. На сервере в теле метода вы можете изменить состояние объекта. Измененное состояние будет автоматически передано на клиент, и компонент будет инициализирован заново с учетом внесенных изменений.

Пример изменения значения контекстного свойства на сервере:

```xbsl
@НаСервере @ДоступноСКлиента
@Контекстный
метод КонтекстныйМетод()
    этот.ПолучитьТип() // Вернет "ИмяКомпонента.Контекст"
    // Задание значения контекстного свойства на сервере
    КонтекстноеСвойство = "Значение"
;
```

#### СохраняемыеДанные

`Истина` — при изменении значения этого свойства «Элемент» установит свойство `СобственнаяМодифицированность` компонента в значение `Истина`. После записи данных вы должны самостоятельно присвоить свойству `СобственнаяМодифицированность` значение `Ложь`.

#### Тип

Тип свойства.

### <Событие разработчика>

Собственное событие компонента, добавленное разработчиком. Здесь вы описываете только само событие, обработчик этого события необходимо назначить при [описании экземпляра](../../wiki/interface/system-and-interface-components-18287074edda.md) этого компонента. О вызове и назначении обработчиков собственных событий компонента можно прочитать [здесь](../../wiki/interface/component-example-077c0c8b7fb0.md). Каждое событие описывается следующими свойствами:

- Имя
  
  — имя события.
- Тип
  
  — тип объекта события:
  
  - тип должен быть наследником типа
    
    `СобытиеКомпонента`
    
    ;
  - если значение не указано, то тип события —
    
    `СобытиеКомпонента`

## События

### ПриИзмененииИсторииПереходов

Переопределяемый обработчик. Выполняется при прохождении по истории переходов. В браузере при нажатии на стрелки назад/вперед. Сигнатура обработчика:

```xbsl
@Обработчик
метод ПриИзмененииИсторииПереходов(Событие: СобытиеСДанными<Строка>)
    // Обработка события...
;
```

### ПриОткрытииПоСсылке

Переопределяемый обработчик. Выполняется при переходе по ссылке в приложении. Сигнатура обработчика:

```xbsl
@Обработчик
метод ПриОткрытииПоСсылке(Событие: СобытиеПриОткрытииПоСсылке)
    // Обработка события...
;
```

### ПослеСоздания

Переопределяемый обработчик. Предназначен для дополнительной инициализации свойств экземпляра компонента на клиенте и вызова прикладной логики инициализации экземпляра компонента. Выполняется после полного конструирования экземпляра компонента, т. е. когда:

- установлены значения свойств экземпляра компонента, указанные при
  
  [описании экземпляра](../../wiki/interface/system-and-interface-components-18287074edda.md)
  
  ;
- созданы свои компоненты данного экземпляра;
- значения свойств своих компонентов установлены из описаний их экземпляров;
- подключены обработчики событий в экземпляре компонента и в экземплярах его внутренних компонентов.

Сигнатура обработчика:

```xbsl
@Обработчик
метод ПослеСоздания()
// Обработка события...
;
```

### ПриНаведении

Назначаемое событие. Вызывается при наведении указателя мыши на область компонента. Особенности вызова события:

- При наведении указателя мыши на вложенные элементы событие
  
  ПриНаведении
  
  сначала вызывается для родительского элемента, а затем для дочернего.
- Событие не поддерживается на мобильных устройствах.

Когда указатель мыши покидает область компонента, вызывается событие **ПриПотереНаведения**.

### ПриПеретаскивании

Назначаемое событие. Возникает по окончании перетаскивания на область компонента. Если в обработчике события свойство `СобытиеПриПеретаскивании.СтандартнаяОбработка` не равно `Ложь`, то происходит системная обработка события, после чего «Элемент» вызывает событие у родительского компонента, вплоть до компонента, унаследованного от `КлиентскоеПриложение`. На данный момент поддерживается только перетаскивание файлов из проводника на область компонента.

### ПриПотереНаведения

Назначаемое событие. Вызывается, когда указатель мыши покидает область компонента. Особенности вызова события:

- Если событие срабатывает для вложенных элементов (курсор смещается за пределы родительского элемента), то сначала оно вызывается для дочернего элемента, а затем для родительского.
- Событие не вызывается при удалении компонента, изменении его видимости или размера (если в результате указатель мыши больше не находится над областью компонента).
- Событие не поддерживается на мобильных устройствах.

При наведении указателя мыши на область компонента вызывается событие **ПриНаведении**.

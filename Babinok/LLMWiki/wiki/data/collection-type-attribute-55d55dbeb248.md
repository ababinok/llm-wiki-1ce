## Обзор

Элементы проекта могут содержать реквизиты-коллекции.

## Документированный контракт и примеры

Элементы проекта могут содержать реквизиты-коллекции. Данные реквизиты имеют тип `Массив`, что позволяет хранить набор значений для одного экземпляра сущности.

Например, справочник **Сотрудники** может иметь реквизит-коллекцию **Телефоны**. Тогда для каждого сотрудника (экземпляра сущности) можно указать несколько телефонов.

Каждый реквизит-коллекция порождает отдельную таблицу в базе данных. Ее имя формируется по принципу **имя-элемента-проекта.имя-реквизита**. Эта таблица содержит поле **Владелец**, связанное с полем **Ссылка** основной таблицы.

Пример таблицы реквизита-коллекции [Описание иллюстрации](../../raw/figures/8d30024acba1e608820375668756dca1dd4aed6047da350c449e693c8795446a-e0076e45de543a9c.md)

В коде вы можете добавлять значения реквизита-коллекции следующим образом:

```xbsl
метод ДобавитьСотрудника()
    пер СотрудникОбъект = новый Сотрудники.Объект()
    СотрудникОбъект.ФИО = "Герасимов"
    СотрудникОбъект.Телефоны.Добавить("454-45-54")
    СотрудникОбъект.Записать()
;
```

В языке запросов вы можете обращаться непосредственно к таблице реквизита-коллекции. При этом нужно учитывать, что в основной таблице нельзя обратиться к полю **Телефоны** как ко вложенной таблице. Если такая необходимость возникает, используйте соединение таблиц в запросе.

Правильно. [Описание иллюстрации](../../raw/figures/e84cee6e0d7036af176153092a96bb7ffe5f858bf23d616f7cfc983a97a2de5f-ba77891b83aec8c5.md)

```xbql
ВЫБРАТЬ
  Индекс,
  Элемент КАК Телефон
ИЗ
  Сотрудники.Телефоны
ГДЕ
  Владелец == %Сотрудник
```

Неправильно. [Описание иллюстрации](../../raw/figures/603d54fd2915a5d2131847b25291afd1287a94423523671c5d183e102fd7c34e-e876f584ea679688.md)

```xbql
ВЫБРАТЬ
  Телефоны
ИЗ
  Сотрудники
```

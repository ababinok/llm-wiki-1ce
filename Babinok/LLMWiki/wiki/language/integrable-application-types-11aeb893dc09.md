## Документированный контракт и примеры

После того как вы добавили в проект интегрируемое приложение, «1С:Предприятие.Элемент» создаст несколько типов, имена которых в общем случае выглядят следующим образом:

- [`{ИмяИнтегрируемогоПриложения}`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md)
  
  ,
- [`{ИмяИнтегрируемогоПриложения}.Ссылка`](../stdlib/integrableapplicationname-reference-ru-50f4d2136947.md)
  
  ,
- [`{ИмяИнтегрируемогоПриложения}.Объект`](../stdlib/integrableapplicationname-object-ru-2facace672c0.md)
  
  ,
- [`{ИмяИнтегрируемогоПриложения}.Данные`](../stdlib/integrableapplicationname-data-ru-422d789b469d.md)
  
  .

Например, если в проекте есть интегрируемое приложение **ПриложениеСклад**, то будут созданы следующие типы:

- `ПриложениеСклад`
  
  ,
- `ПриложениеСклад.Ссылка`
  
  ,
- `ПриложениеСклад.Объект`
  
  ,
- `ПриложениеСклад.Данные`
  
  .

## Тип «ИмяИнтегрируемогоПриложения»

Это тип-одиночка.

Тип [`{ИмяИнтегрируемогоПриложения}`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md) содержит методы для работы с экземплярами интегрируемого приложения и ссылками на них. Например, `НайтиПоКоду()`, `ПолучитьСсылку()`.

Этот тип не имеет конструктора и имеет единственный экземпляр, обращение к которому выполняется по имени типа:

```xbsl
// Получить менеджера интегрируемого приложения «ПриложениеСклад»
пер МенеджерПриложения = ПриложениеСклад
```

### Модуль интегрируемого приложения

В проекте модуль, расширяющий тип [`{ИмяИнтегрируемогоПриложения}`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md), называется **модулем интегрируемого приложения** и имеет имя `ИмяИнтегрируемогоПриложения.xbsl`.

В этом модуле вы можете обработать событие [`ПолучитьЗначенияВыбора()`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md) для того, чтобы изменить стандартный алгоритм подбора экземпляров интегрируемого приложения при вводе по строке.

Также в модуле интегрируемого приложения можно обработать события вычисления разрешений доступа: [`ВычислитьРазрешенияДоступа()`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md), [`ВычислитьРазрешенияДоступаДляОбъектов()`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md) ([подробнее](../security/manage-access-control-2ec0764ce511.md)).

Вы можете расширить тип [`{ИмяИнтегрируемогоПриложения}`](../stdlib/integrableapplicationname-ru-dded7fda26a0.md), добавив в модуль интегрируемого приложения собственные публичные методы. Например, метод для создания экземпляра приложения:

```xbsl
// Создает экземпляр интегрируемого приложения «ПриложениеСклад»
@ВПроекте
метод СоздатьСклад(Наименование: Строка, Адрес: Строка): ПриложениеСклад.Ссылка
    пер Склад = новый ПриложениеСклад.Объект()
    Склад.Наименование = Наименование
    Склад.НастройкиПрямогоПодключения.Адрес = Адрес
    Склад.Записать()
    возврат Склад.Ссылка
;
```

Этот метод будет доступен в других модулях:

```xbsl
// Вызов метода разработчика у менеджера интегрируемого приложения
пер НовоеПриложение = ПриложениеСклад.СоздатьСклад("Север", "https://sklad1.ru")
```

## Тип «ИмяИнтегрируемогоПриложения.Объект»

Тип [`{ИмяИнтегрируемогоПриложения}.Объект`](../stdlib/integrableapplicationname-object-ru-2facace672c0.md) доступен в окружении **КлиентИСервер**.

Экземпляр этого типа содержит данные одного экземпляра интегрируемого приложения и предназначен для создания, изменения или удаления экземпляра.

Этот тип имеет конструкторы, которые позволяют создать новый экземпляр интегрируемого приложения. Заполнив этот экземпляр данными, вы можете затем сохранить его в базе данных.

### Модуль объекта интегрируемого приложения

В проекте модуль, расширяющий тип [`{ИмяИнтегрируемогоПриложения}.Объект`](../stdlib/integrableapplicationname-object-ru-2facace672c0.md), называется **модулем объекта интегрируемого приложения**. В нем вы можете обработать такие события, как:

- `ПриЗаполнении()`
  
  ,
- `ПередЗаписью()`
  
  ,
- `ПослеЗаписи()`
  
  ,
- `ПередУдалением()`
  
  .

Например:

```xbsl
@Обработчик
метод ПередУдалением(ПараметрыУдаления: ПриложениеСклад.ПараметрыУдаления)
    // Действия, которые выполняются перед удалением экземпляра интегрируемого приложения
;
```

Вы можете расширить тип [`{ИмяИнтегрируемогоПриложения}.Объект`](../stdlib/integrableapplicationname-object-ru-2facace672c0.md), добавив в модуль объекта собственные публичные методы. Например, метод для проверки настроек подключения:

```xbsl
@ВПроекте
метод ПроверитьНастройкиПодключения(): Булево
    возврат НастройкиПрямогоПодключения.Адрес != ""
;
```

Этот метод будет доступен в других модулях:

```xbsl
// Вызов собственного метода объекта интегрируемого приложения «ПриложениеСклад»
// В переменной Склад находится значение типа ПриложениеСклад.Объект
пер Склад: ПриложениеСклад.Объект
если Склад.ПроверитьНастройкиПодключения()
    // ...
;
```

## Тип «ИмяИнтегрируемогоПриложения.Ссылка»

Тип [`{ИмяИнтегрируемогоПриложения}.Ссылка`](../stdlib/integrableapplicationname-reference-ru-50f4d2136947.md) доступен в окружении **КлиентИСервер**.

Он предназначен для описания ссылки на один экземпляр интегрируемого приложения.

Он имеет конструктор `новый ИмяИнтегрируемогоПриложения.Ссылка()`, который позволяет создать новую ссылку по `Ууид`, и серверный метод [`ЗагрузитьОбъект()`](../stdlib/integrableapplicationname-reference-ru-50f4d2136947.md), который позволяет получить экземпляр (`{ИмяИнтегрируемогоПриложения}.Объект`) из ссылки (`{ИмяИнтегрируемогоПриложения}.Ссылка`).

Чтобы узнать, является ли какое-либо значение ссылкой на экземпляр интегрируемого приложения, можно использовать операцию [это](is-e12cbcb44c3d.md), например:

```xbsl
метод ЯвляетсяСсылкойНаИнтегрируемоеПриложение(Элемент: Объект): Булево
    возврат Элемент это ПриложениеСклад.Ссылка
;
```

## Тип «ИмяИнтегрируемогоПриложения.Данные»

Тип структуры с реквизитами, соответствующими реквизитам интегрируемого приложения. Тип [`{ИмяИнтегрируемогоПриложения}.Данные`](../stdlib/integrableapplicationname-data-ru-422d789b469d.md) доступен в окружении **Сервер**.

Используется в обработчиках событий `ПередЗаписью()`, `ПослеЗаписи()` и `ПриСозданииКопии()`.

Не имеет конструктора. «Элемент» сам создает экземпляр этого типа при наступлении упомянутого события. Он передает в обработчик события экземпляр этого типа, наполненный «старыми» значениями.

## Обзор

Виртуальная таблица не имеет физического табличного представления в базе данных.

## Документированный контракт и примеры

Виртуальная таблица не имеет физического табличного представления в базе данных. Ее данные формируются в момент выполнения запроса на основе других реальных таблиц базы данных.

Виртуальные таблицы позволяют использовать произвольные запросы в [отчетах](create-report-b99954f7595c.md). Вы создаете виртуальную таблицу с запросом и используете ее как источник данных для отчета. Более подробную информацию вы можете найти в данном примере: [Создание отчета на основе виртуальной таблицы](use-virtual-table-to-create-report-89c726b4186d.md).

С помощью [ключевых полей записей](virtual-table-b6d396b92d20.md), которые позволяют обращаться к записям виртуальной таблицы, вы можете использовать виртуальную таблицу в динамических списках.

За счет того, что в виртуальные таблицы выносится часть логики запросов, разработка приложения упрощается.

В этой статье приводится пример создания виртуальной таблицы в [демонстрационном приложении](demo-app-3768685a4428.md). В рамках примера:

- создадим простую виртуальную таблицу;
- добавим для нее
  
  [параметр](virtual-table-b6d396b92d20.md)
  
  и
  
  [ключевое поле](virtual-table-b6d396b92d20.md)
  
  ;
- напишем
  
  [запрос](virtual-table-b6d396b92d20.md)
  
  для заполнения таблицы данными;
- покажем, как обращаться к виртуальным таблицам в
  
  [языке запросов](../queries/query-language-ea5bc0e9fecd.md)
  
  .

## Элемент проекта «Виртуальная таблица»

Чтобы создать виртуальную таблицу в среде разработки, в представлении **Проект** щелкните правой кнопкой мыши по имени подсистемы и нажмите **Новый** в контекстном меню. В открывшемся окне выберите элемент **Виртуальная таблица** и укажите имя виртуальной таблицы.



[Подробнее о добавлении элемента проекта](example-3-create-project-e939e343a8f8.md)

Автоматически генерируются два файла:

- ИмяВиртуальнойТаблицы.yaml
  
  с описанием свойств виртуальной таблицы;
- ИмяВиртуальнойТаблицы.xbql
  
  с запросом виртуальной таблицы (создается пустой файл).

Новая виртуальная таблица в представлении **Проект** будет выделена красным из-за пустого файла запроса.

Новая виртуальная таблица в дереве проекта выделена красным из-за пустого файла запроса; справа открыта её панель свойств. [Описание иллюстрации](../../raw/figures/4ec8350604707f648a5fa6c4f3f393f33eab2d1159415bef2bf7500c351c8663-29b863d6c465c559.md)

Если выбрать **виртуальную таблицу** в дереве элементов проекта, справа отобразится панель **Свойства**, в которой можно задать область видимости виртуальной таблицы, отметить импортируемые подсистемы, а также добавить ключевые поля.

## Параметры

В виртуальную таблицу можно передавать параметры. Свойство **Параметры** имеет тип `Массив<ПараметрВиртуальнойТаблицы>` и является необязательным, т. е. может быть пустым.

Параметры описываются в файле **ИмяВиртуальнойТаблицы.yaml**. В нем должны быть объявлены все параметры, использованные в запросе виртуальной таблицы. Параметры, отсутствующие в тексте запроса, указывать нельзя.

Если виртуальная таблица является источником данных в отчете, для параметра должно быть установлено значение по умолчанию.

### Свойства параметров виртуальной таблицы

Виртуальная таблица имеет следующие свойства:

- **Имя**. `Строка`. Имя параметра виртуальной таблицы. Должно быть корректным идентификатором с точки зрения языка запросов.
- **Тип**. `Множество<Тип>`. Тип параметра. Не может быть пустым. Допускаются только типы, поддерживаемые в языке запросов, или коллекция таких типов. Если используется коллекция, то это должен быть единственный тип. Тип `Байты` не поддерживается.
  
  Для некоторых типов необходимо указать ограничения:
  
  - `Строка`
    
    —
    
    `МаксимальнаяДлина`
    
    ,
  - `Число`
    
    —
    
    `ДлинаЦелойЧасти`
    
    и
    
    `ДлинаДробнойЧасти`
    
    .
  
  Другие ограничения не поддерживаются.
- **ЗначениеПоУмолчанию**. `Объект?`. Значение параметра по умолчанию. Если значение по умолчанию не указано, параметр обязателен для заполнения.

### Добавление параметра

Чтобы добавить параметр в среде разработки, в представлении проекта выберите компонент **Параметры** виртуальной таблицы и щелкните на значок плюса.

В представлении проекта выбраны «Параметры» виртуальной таблицы; кнопка плюса добавляет новый параметр таблицы. [Описание иллюстрации](../../raw/figures/4c892bcdae3e5e150b90f9aed01d5b41b5f69da236511f67f49c3bf9de6f37af-b5b3af6db68fe30b.md)

Укажите имя **Должность**.

В дереве проекта выберите новый параметр и укажите его тип и значение по умолчанию в панели **Свойства** справа.

Для параметра виртуальной таблицы заданы: Имя — Должность; Тип — РольСотрудника. В раскрытом ЗначениеПоУмолчанию: Тип — РольСотрудника, Значение — МенеджерПоПродажам. НезаполненноеЗначение — Разрешить. Это пример настройки параметра в панели Свойства. [Описание иллюстрации](../../raw/figures/c6e59868c34492a737dd4c726d3f908026a08fd5a8f7284ef1d6610182cf7a94-63b4cd40438307cc.md)

Теперь свойства параметра будут отображаться в yaml-файле виртуальной таблицы.

### Пример

Содержимое yaml-файла виртуальной таблицы **ВиртуальнаяТаблицаСотрудники** с параметром **Должность** типа `РольСотрудника`:

```yaml
ВидЭлемента: ВиртуальнаяТаблица
Ид: bcac968d-4752-4879-8efb-6f9659796967
Имя: ВиртуальнаяТаблицаСотрудники
ОбластьВидимости: ВПроекте
Импорт:
    - Основное
КлючевыеПоля:
    - Наименование
Параметры:
    -
        Имя: Должность
        Тип: РольСотрудника
        ЗначениеПоУмолчанию: МенеджерПоПродажам
```

## Запрос виртуальной таблицы

Текст запроса виртуальной таблицы располагается в отдельном файле с именем **ИмяВиртуальнойТаблицы.xbql**. Запрос не может быть пустым, поэтому наличие файла и запроса в нем обязательно.

### Ограничения и особенности запроса

- Запрос должен соответствовать ограничениям для подзапросов:
  
  - это должен быть запрос на выборку данных (а не создание временной таблицы);
  - предложение
    
    `УПОРЯДОЧИТЬ ПО`
    
    можно использовать только с предложениями
    
    `ПЕРВЫЕ`
    
    или
    
    `ПОЛУЧИТЬ`
    
    /
    
    `СО СМЕЩЕНИЕМ`
    
    и наоборот.
- В запросе запрещено использовать конструкцию
  
  `ВЫБРАТЬ *`
  
  .
- Для всех выражений в списке выборки должны быть указаны псевдонимы или это должны быть просто выражения выборки поля. При этом использовать два и более выражения выборки поля с одинаковым именем поля (не важно из одной таблицы или разных) без псевдонима не допускается.
- В запросе используется синтаксис параметров аналогично произвольным запросам (
  
  `&ИмяПараметра`
  
  ). Все параметры должны быть указаны в свойстве
  
  Параметры
  
  .
- Не поддерживается использование источников данных на основе коллекций.

### Пример

Содержимое xbql-файла виртуальной таблицы **ВиртуальнаяТаблицаСотрудники** с запросом, который возвращает поля **Наименование**, **Пользователь**, **БизнесРегион** и **Роль** сотрудников, для которых **Роль** соответствует значению параметра **Должность**.

```xbql
ВЫБРАТЬ
    Наименование КАК Наименование,
    Пользователь КАК Пользователь,
    БизнесРегион  КАК БизнесРегион ,
    Роль КАК Роль
ИЗ
    Сотрудники
ГДЕ
    Роль == &Должность
```

## Ключевые поля записей

Ключевые поля записей используются для адресации записей виртуальной таблицы. Другими словами, с их помощью можно указать на какую-либо конкретную запись. Свойство **КлючевыеПоля** имеет тип `Массив<Строка>` и является необязательным.

Если ключевые поля заполнены:

- на основе элемента проекта дополнительно порождается ссылочный структурный тип
  
  `ИмяВиртуальнойТаблицы.КлючЗаписи`
  
  ;
- в таблице неявно появляется поле с именем
  
  `КлючЗаписи`
  
  , типом
  
  `ИмяВиртуальнойТаблицы.КлючЗаписи`
  
  и значением ключевых полей;
- виртуальная таблица считается ссылочной (т. е. может использоваться в динамическом списке).

Тип `ИмяВиртуальнойТаблицы.КлючЗаписи` доступен на сервере и клиенте. Тип является хранимым, то есть его можно использовать в языке запросов, но его нельзя использовать в типах реквизитов хранимых объектов (например, справочников и регистров). Значение ключевого поля записи получается из поля с именем `КлючЗаписи`.

Ключевые поля добавляются в среде разработки. Для этого в представлении **Проект** выберите **виртуальную таблицу**. В открывшейся панели **Свойства** добавьте элемент **КлючевыеПоля**.

В свойствах ВиртуальнаяТаблицаСотрудники показан раздел КлючевыеПоля. [Описание иллюстрации](../../raw/figures/bdbdafd558eab25204bb4e56c9d70b41adce56c6faec91e0d29363d28463adf5-bdb4a7104e423fb7.md)

### Пример использования ключевых полей в языке запросов

В виртуальную таблицу `ВиртуальнаяТаблицаСотрудники` добавлено ключевое поле **Наименование**. Запрос в методе `ПримерПоискаПоКлючевомуПолю()` возвращает запись с соответствующим значением ключевого поля **Наименование**, которое в данном примере задано константой.

```xbsl
метод ПримерПоискаПоКлючевомуПолю()
    пер Ключ = новый ВиртуальнаяТаблицаСотрудники.КлючЗаписи(Наименование = "Иванов И. И.")

    пер Запрос = Запрос{
        ВЫБРАТЬ
            Наименование,
            Роль
        ИЗ
            ВиртуальнаяТаблицаСотрудники
        ГДЕ
            КлючЗаписи == %Ключ
    }

    для Запись из Запрос.Выполнить()
        // какие-то действия
    ;
;
```

## Пример использования виртуальной таблицы с параметром в динамическом списке

Если в виртуальной таблице заданы ключевые поля, ее можно использовать в качестве источника данных динамического списка. Параметр виртуальной таблицы задается с помощью свойства **Аргументы** основной таблицы, в котором описывается тип, имя и выражение аргументов, передаваемых в динамический список. Например:

Список сотрудников с ролью МенеджерПоПродажам

```yaml
ВидЭлемента: КомпонентИнтерфейса
ОбластьВидимости: ВПодсистеме
Ид: e6ee6df6-99ec-4e25-aeeb-133281d66225
Имя: СотрудникиФормаСписка
Наследует:
    Тип: ФормаСписка
    Заголовок: Список сотрудников
    КомпонентТаблицы: =Компоненты.ОсновнаяТаблица
    Содержимое:
        Тип: ПроизвольныйШаблонФормы
        Содержимое:
            Тип: Таблица<ДинамическийСписок<СотрудникиФормаСписка.ДанныеСтрокиОсновнаяТаблица>>
            Имя: ОсновнаяТаблица
            Источник:
                ИмяТипаДанныхСтроки: ДанныеСтрокиОсновнаяТаблица
                ОсновнаяТаблица:
                    Таблица: Сотрудники
                Поля:
                    -
                        Тип: ПолеДинамическогоСписка
                        Выражение: Наименование
            Колонки:
                -
                    Тип: СтандартнаяКолонкаТаблицы<СтрокаДинамическогоСписка<СотрудникиФормаСписка.ДанныеСтрокиОсновнаяТаблица>>
                    Значение: =ДанныеСтроки.Данные.Наименование
Свойства:
    -
        Имя: Список
        Тип: ДинамическийСписок<СотрудникиФормаСписка.ДанныеСтрокиСписка>
        ЗначениеПоУмолчанию:
            ИмяТипаДанныхСтроки: ДанныеСтрокиСписка
            ОсновнаяТаблица:
                Таблица: ВиртуальнаяТаблицаСотрудники
                Аргументы:
                    -
                        Тип: АргументТаблицыВыражение
                        Имя: Должность
                        Выражение: '&Должность'
            Параметры:
                -
                    Имя: Должность
                    Тип: ПараметрДинамическогоСписка
                    Значение:
                        Тип: РольСотрудника
                        Значение: МенеджерПоПродажам
            Поля:
                -
                    Тип: ПолеДинамическогоСписка
                    Выражение: Наименование
```

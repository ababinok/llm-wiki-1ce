## Общие принципы и виды взаимодействия

Технология поддерживает два вида взаимодействия пользователя с приложением, которые отличаются вариантами использования диалоговых окон. Выбор вида взаимодействия зависит от:

- необходимости параллельных сценариев;
- структуры информационной архитектуры.

### Первый тип взаимодействия (с модальными окнами)

Сценарии взаимодействия начинаются на экране. Далее последовательно открываются наборы диалоговых окон, которые необходимы для прохождения сценария. В результате выполнения сценария пользователь возвращается обратно на экран, с которого началось взаимодействие.

Выбирайте первый тип взаимодействия, если:

- сценарии не требуют выполнения параллельных задач;
- в вашем приложении жесткая иерархическая навигационная структура (с заранее определенной навигационной архитектурой);
- пункты навигации и экраны приложения находятся во взаимно однозначном соответствии.

## Второй тип взаимодействия (с немодальными окнами)

Сценарии взаимодействия могут начинаться и заканчиваться из любой сущности. Пользователь может решать несколько задач одновременно. Взаимодействие разветвляется за счет сворачивания диалоговых окон.

Выбирайте второй тип взаимодействия, если

- целевые сценарии требуют одновременного выполнения нескольких параллельных задач;
- в навигационной архитектуре допускается появление новых команд;
- пункты навигации и экраны приложения находятся в соответствии «один ко многим».

## Примеры и рекомендации

### Как нужно делать

При проектировании соблюдайте правила выбранного варианта использования диалоговых окон:

1. Открывайте
  
  сущности
  
  в диалоговом окне.

Правильно. [Описание иллюстрации](../../raw/figures/e84cee6e0d7036af176153092a96bb7ffe5f858bf23d616f7cfc983a97a2de5f-ba77891b83aec8c5.md)

Форма сущности открыта в отдельном диалоговом окне поверх списка; пример иллюстрирует рекомендацию открывать сущности диалогом. [Описание иллюстрации](../../raw/figures/3329f83b5d03d8362884d9426dca18be0d73a175a28f3e856bf21e1c380cb8c4-9b97c741d6df0818.md)

1. Если сущность открывается в форме, предоставьте пользователю возможность переходить к другим разделам с помощью навигационной цепочки над заголовком.

Правильно. [Описание иллюстрации](../../raw/figures/e84cee6e0d7036af176153092a96bb7ffe5f858bf23d616f7cfc983a97a2de5f-ba77891b83aec8c5.md)

Над заголовком формы показана навигационная цепочка «Инженер/Разработка»; пример демонстрирует путь для перехода к другому разделу из открытой сущности. [Описание иллюстрации](../../raw/figures/45fd2ee60f6bb3714e9cc19fec09fc7d01b732f42f28e079295efa2fe4ce24b8-05e14e4e685932be.md)

### Как не нужно делать

- Не располагайте кнопку «Назад» рядом с заголовком или в виде действия заголовка формы: в мобильной версии пользоваться навигацией будет неудобно.
- Не используйте стандартные возможности браузера в качестве основных функций навигации в сервисе.

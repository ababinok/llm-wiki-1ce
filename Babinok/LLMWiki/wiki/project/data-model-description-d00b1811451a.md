## Обзор

Зачастую при создании собственных алгоритмов вам требуются определенные модели данных, с которыми вам было бы удобно работать.

## Документированный контракт и примеры

Зачастую при создании собственных алгоритмов вам требуются определенные модели данных, с которыми вам было бы удобно работать. Для их создания можно использовать структуры. «1С:Предприятие.Элемент» предлагает три возможности работы со структурами:

- [**Структура**](structure-a95b303918fa.md)
  
  в языке
  
  «1С:Элемент»
  
  ;
- [**Структура**](../language/structure-type-0351a6528924.md)
  
  — элемент проекта;
- [**ХранимаяСтруктура**](../language/storable-structure-09e67153f997.md)
  
  — элемент проекта.

**Структура** в языке «1С:Элемент» — это тип, имеющий фиксированный набор полей и методов, а также конструктор.

Элемент проекта **Структура** отличается от типа **Структура** тем, что:

- элемент проекта
  
  Структура
  
  [удобно использовать](../interface/structure-in-ui-232f5dd0d034.md)
  
  в компонентах интерфейса (экземпляры структуры можно описывать прямо в YAML-описании компонента);
- элемент проекта
  
  Структура
  
  может реализовывать
  
  [контракты типа](../language/type-contract-ab9f0932850d.md)
  
  .

Элемент проекта **Хранимая структура** отличается от элемента проекта **Структура** тем, что:

- хранимую структуру
  
  можно использовать как тип реквизита справочника или тип измерения (ресурса, реквизита) регистра сведений (для хранения данных в базе данных), поэтому:
  
  - окружение
    
    только
    
    КлиентИСервер
    
    ;
  - поля могут быть только таких типов, для которых обеспечивается хранение в базе данных;
  - две структуры не могут иметь поля, ссылающиеся друг на друга;
- хранимую структуру
  
  можно использовать как тип параметра и как тип результата запланированного задания;
- хранимую структуру
  
  можно использовать в полнотекстовом поиске.

Чтобы создать собственную структуру, добавьте в проект элемент вида **Структура**. Например, структура в проекте может выглядеть следующим образом:

Использование структур для описания модели данных [Описание иллюстрации](../../raw/figures/dab9403199657bda2686c16fbb03304d0d1aa9b1396141d5e3e430028d8c88ee-4949622343564d10.md)

Она может иметь такое описание:

```yaml
ВидЭлемента: Структура
ОбластьВидимости: ВПодсистеме
Ид: 3cc44843-e496-4d2e-8360-50d35ec258a8
Имя: ДанныеСотрудника
Окружение: КлиентИСервер
Поля: 
    -
        Тип: Строка
        Имя: ФИО
    -
        Тип: Число
        Имя: Возраст
    -
        Тип: Строка
        Имя: Город
```

> [!TIP] совет
> Поля структуры и хранимой структуры являются реализацией свойств [контракта типа](../language/type-contract-ab9f0932850d.md).

## Использование хранимой структуры в табличной части

[Хранимую структуру](../language/storable-structure-09e67153f997.md) можно использовать в табличной части элемента проекта. Например, справочник **Заказы** вместе с каждым элементом (заказом) может хранить состав заказа: товар, его количество и цену. В одном заказе может быть три товара, в другом — два, а в третьем — четыре товара.

Использование хранимой структуры в табличной части [Описание иллюстрации](../../raw/figures/b93f0f7f5d7b5a993c8c2de020110c2743e7cf55cd71a012d3c4976754c243cf-3e7b7a2efd7a78ab.md)

Справочник **Заказы** имеет реквизит-коллекцию **Состав**, элементами которого являются экземпляры хранимой структуры **СтрокаТаблицы**.

Использование хранимой структуры в табличной части [Описание иллюстрации](../../raw/figures/c88b15d681d4c03762994503b185f98e85ea7ec53c31c5a2cbed9f7e3ffc664c-8b6d20ee81d88341.md)

Описание хранимой структуры **СтрокаТаблицы.yaml** выглядит следующим образом:

```yaml
ВидЭлемента: ХранимаяСтруктура
Ид: 2d187506-7d2b-48a9-9dfd-f05cfeccc9b8
ОбластьВидимости: ВПодсистеме
Имя: СтрокаТаблицы
Поля:
    -
        Имя: Товар
        Ид: f90c625c-dff7-4186-8d4b-91d212ba071b
        Тип: Строка
        ИспользоватьВПолнотекстовомПоиске: Ложь
    -
        Имя: Количество
        Ид: 9ac9970e-33a8-424b-bca8-4a2e8b21b506
        Тип: Число
        ИспользоватьВПолнотекстовомПоиске: Ложь
    -
        Имя: Цена
        Ид: 787d8424-9762-4015-9938-b539d8a5a0db
        Тип: Число
        ИспользоватьВПолнотекстовомПоиске: Ложь
```

В структуре определены три поля: **Товар**, **Количество** и **Цена**.

Описание справочника **Заказы.yaml** выглядит следующим образом:

```yaml
ВидЭлемента: Справочник
Имя: Заказы
Ид: 7fd826d7-2431-4574-acd5-75ab887ba06f
ОбластьВидимости: ВПодсистеме
Реквизиты:
    -
        Имя: Код
        Тип: Строка
        СерииНумерации:
            - Префикс
            - Постфикс
    -
        Ид: f6f80dbe-73f7-4046-9fa5-2107b8d7831e
        Имя: Дата
        Тип: ДатаВремя
        ИспользоватьВПолнотекстовомПоиске: Ложь
    -
        Ид: 30870553-4c11-4518-8630-78c47d7cf48b
        Имя: Состав
        Тип: Массив<СтрокаТаблицы>
        ИспользоватьВПолнотекстовомПоиске: Ложь
```

В справочнике определены три реквизита: **Код**, **Дата** и реквизит-коллекция **Состав**, который содержит экземпляры хранимой структуры **СтрокаТаблицы**.

Создать элемент справочника **Заказы** можно следующим образом:

```xbsl
// Создать заказ с тремя товарами
пер Заказ = новый Заказы.Объект()
Заказ.Код = "1"
Заказ.Дата = ДатаВремя.Сейчас()

// Заполнить состав заказа.
Заказ.Состав.Добавить(новый СтрокаТаблицы("ПервыйТовар", 10, 20000))
Заказ.Состав.Добавить(новый СтрокаТаблицы("ВторойТовар", 15, 45000))
Заказ.Состав.Добавить(новый СтрокаТаблицы("ТретийТовар", 30, 3000))

Заказ.Записать()
```

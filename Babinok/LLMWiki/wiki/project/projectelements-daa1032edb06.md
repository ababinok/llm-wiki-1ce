[Реализует](../integration/http-service-element-20a693318e85.md) функциональность поставщика HTTP-сервиса. Позволяет создать программный интерфейс приложения (API), который будет доступен с помощью HTTP-запросов.

## [SoapСервис](../integration/soapservice-33331940c1db.md)

Реализует функциональность [поставщика SOAP-сервиса](../integration/soap-web-service-6fc6a00d4cc7.md). Позволяет обрабатывать входящие SOAP-запросы, поступающие от внешних информационных систем. Обращение к SOAP-сервису выполняется при помощи HTTP POST-запроса по URL-адресу. При этом само SOAP-сообщение передается в теле запроса.

Функциональность клиента SOAP-сервиса реализует элемент проекта [Клиент SOAP-сервиса](../integration/soap-web-service-client-e79277c8f091.md).

---

## [ВиртуальнаяТаблица](virtualtable-eb862e7a1bd9.md)

Виртуальная таблица не имеет физического табличного представления в базе данных. Ее данные формируются в момент выполнения запроса на основе других реальных таблиц базы данных.

Виртуальные таблицы позволяют использовать произвольные запросы в [отчетах](create-report-b99954f7595c.md). Вы создаете виртуальную таблицу с запросом и используете ее как источник данных для отчета.

С помощью [ключевых полей записей](virtual-table-b6d396b92d20.md), которые позволяют обращаться к записям виртуальной таблицы, вы можете использовать виртуальную таблицу в динамических списках.

За счет того, что в виртуальные таблицы выносится часть логики запросов, разработка приложения упрощается.

## [КонтрактСущности](../data/entitycontract-ef962eb24775.md)

Контракт сущности — элемент проекта, который предназначен для описания общих методов и хранимых свойств, которыми обладают элементы, реализующие данный контракт. Контракт сущности обладает основной таблицей и таблицами множественных свойств, в которых хранятся свойства, описанные в контракте.

Важное отличие контракта сущности от контракта типа состоит в том, что контракт типа определяет только интерфейс, в то время как контракт сущности задает ограничения на данные. Для контракта сущности может создаваться отдельная таблица, которая хранит «общие» данные. Эта таблица доступна в языке запросов. Для контракта сущности также создается ссылочный тип, и его можно использовать в хранимых полях.

Элемент проекта вида «Обработка» — это объект конфигурации, предназначенный для обработки данных на стороне сервера. Он позволяет автоматизировать работу с данными: удалять, сохранять и создавать данные по заданному алгоритму ([подробнее](processing-project-element-acb124c72bfa.md)).

## [РегистрНакопления](../data/accumulationregister-c199835a97cc.md)

[Регистры накопления](../data/accumulation-register-overview-699bd9df5dda.md) используются для хранения информации о наличии и движении средств, например финансов, товаров, материалов и т. д. Они позволяют «накапливать» числовые данные в разрезе нескольких измерений. Например, в регистре можно накапливать данные об остатках товаров на складах или информацию об объемах продаж в подразделениях компании.

Информация в регистре накопления хранится в виде записей, каждая из которых содержит значения **измерений** и соответствующие им значения **ресурсов**. Измерения описывают разрезы, в которых хранится информация, а в ресурсах регистра накапливаются нужные числовые данные.

Вместе с каждой записью в регистре накопления можно хранить дополнительную информацию. Для этого используются **реквизиты** регистра накопления.

## [РегистрСведений](../data/informationregister-10bb0480b19f.md)

[Регистры сведений](../data/information-register-project-element-8932693c91b1.md) используются для хранения произвольных данных в разрезе нескольких измерений, например цен товаров в разрезе номенклатуры и типа цен.

Информацию в регистре можно представить в виде таблицы, имеющей одну или несколько колонок. По своему назначению колонки делятся на три группы:

**Измерения** — это «координаты» или значения, для которых в регистре хранится некоторая информация. Например, в регистре **Цены товаров** измерениями будут товар и покупатель, для которого данный товар имеет некоторую цену. **Ресурсы** — это основная информация, хранимая в регистре. Например, в том же регистре это будет цена товара. **Реквизиты** — это вспомогательная информация, которая относится только к одной строке таблицы. Например, фамилия менеджера, который установил цену на товар.

Регистры могут быть [периодическими](../data/periodic-information-register-2e754cdbda44.md) (хранят историю изменений данных) или непериодическими (хранят только актуальное состояние).

Произвольные файлы, которые требуются для работы [приложения](application-89b2d17b70b1.md). В каждой [подсистеме](subsystem-ed73967ead84.md) и в каждом [пакете](package-8893e32778ef.md) может быть собственный набор ресурсов со своей [областью видимости](scope-2cbe4706e1b7.md). Все файлы хранятся в каталоге **Ресурсы**, внутри которого по умолчанию создается элемент **Описание ресурсов**. С помощью его свойства **ОбластьВидимости** можно ограничить область видимости ресурсов.

## [Справочник](../data/catalog-e0da7d4e8e72.md)

[Справочник](../data/catalog-project-element-b6ca52d114d4.md) содержит однородные данные, которые можно представить в виде таблицы, имеющей одну или несколько колонок. Строки этой таблицы являются элементами справочника. Каждый элемент имеет уникальный идентификатор, называемый [ссылкой](reference-94bfeabd231c.md). На каждый элемент можно сослаться во время работы приложения, например выбрать его при заполнении ведомости учета рабочего времени.

Справочник содержит специальные свойства, которые называются [реквизитами](../data/attribute-e6a1152077c2.md). Реквизит — это описание одной колонки в такой таблице. У справочника есть стандартные реквизиты: **Код**, **Владелец**, **Наименование**, **Родитель** и **Файлы**. В проекте вы можете добавить справочнику один или несколько стандартных реквизитов, а также любое количество собственных реквизитов, чтобы описать дополнительные колонки, например **ФИО**, **Возраст**, **Адрес**, **Должность** и т. д.

## [ФрагментКомандногоИнтерфейса](../interface/commandinterfacefragment-ru-bcf4423e9b4a.md)

Предназначен для объединения команд с целью их совместного отображения в пользовательском интерфейсе. Основное назначение — переиспользование единого набора командных элементов в различных частях интерфейса приложения (например, в различных формах, в панелях навигации или действий в компоненте [СтандартноеКлиентскоеПриложениеСРазделами](../interface/standardclientapplicationwithsections-fd5fbdc63cd1.md)).

Пример фрагмента командного интерфейса в панели навигации: группы и команды «Главная», «Продажи», «Отчёты», «Мероприятия», «Настройки», «Сервис», «Путеводитель». [Описание иллюстрации](../../raw/figures/4c4f58e96798cf7fcb99ec2e7773939599e4a30d67b3536640ea93de36f7c3b1-4761f2f745db6e9d.md)

## [ХранимаяСтруктура](storablestructure-bd9b99a09492.md)

**ХранимаяСтруктура** — это [Структура](structure-6a8548d613f3.md), которая может использоваться как тип реквизита или тип измерения (ресурса, реквизита) элементов проекта [Справочник](../data/catalog-e0da7d4e8e72.md) и [РегистрСведений](../data/informationregister-ru-d15b0965bc15.md) для хранения данных в базе данных. Имеет следующие ограничения:

- окружение только
  
  [КлиентИСервер](environmentkind-ru-8bb797e2f7cc.md)
  
  ;
- поля могут быть только таких типов, для которых обеспечивается хранение в базе данных;
- две структуры не могут иметь поля, ссылающиеся друг на друга.

**ХранимуюСтруктуру** можно использовать как тип параметра и как тип результата [запланированного задания](scheduled-job-project-element-e47ed37b89ab.md) и в [полнотекстовом поиске](full-text-search-99b98022003a.md).

## Обзор

Табличная часть элемента проекта — это вложенная таблица, предназначенная для хранения вместе с каждым элементом данных однородной по своей структуре информации.

## Документированный контракт и примеры

Табличная часть элемента проекта — это вложенная таблица, предназначенная для хранения вместе с каждым элементом данных однородной по своей структуре информации. Количество строк такой информации заранее неизвестно и может быть разным для разных элементов данных.

Например, справочник **Проекты** для каждого проекта может хранить список сведений о задачах: номер задачи, ее описание и срочность. В проектах может быть разное количество задач:

Пример табличной части справочника «Проекты»: для каждого проекта рядом с наименованием и кодом хранится несколько задач с номером, описанием и признаком срочности. Число задач различается между проектами. [Описание иллюстрации](../../raw/figures/dbd00c44a1707954b8c9e36883840c6bbf9df89cd048871f4744160f279e44cc-299042cd738b3027.md)

Чтобы смоделировать это в «1С:Предприятие.Элементе», используется табличная часть.

Схема табличной части: справочник «Проекты» имеет Наименование, Код и Задачи; табличная часть «Задачи» содержит Номер, Описание и Срочность. Стрелки показывают, что задачи являются составной частью проекта. [Описание иллюстрации](../../raw/figures/ecf12f6c297509b062d823c66ee5d31959e6c61cdc4ec80f4627722d16c3fda0-1b2d69f9f064dedf.md)

## Табличные части в элементах проекта

Табличные части поддерживаются в ссылочных сущностях: в элементах проекта [Справочник](../data/catalog-project-element-b6ca52d114d4.md), [Документ](../data/document-element-0c6b898a8b13.md), [ПланОбмена](../integration/exchange-plan-project-element-c0fc3c4bb4ef.md), [ИнтегрируемоеПриложение](integrable-application-project-element-9568214a365e.md), [ХранилищеНастроек](../data/settings-repository-3d8ee27a26de.md), [КонтрактСущности](../data/entity-contract-079bb6be0d9a.md).

Табличные части по сути являются единым целым с объектом, к которому относятся: они считываются и записываются вместе с ним, а также используют его права доступа (в том числе нельзя настроить ограничения доступа к строкам табличных частей).

Табличные части описываются в элементе **ТабличныеЧасти** объекта-владельца. Для каждой табличной части порождается структурный тип `ИмяЭлементаСТабличнойЧастью.ИмяТабличнойЧасти` и соответствующая [таблица](../queries/elementwithtabularpart-tabularpartname-ru-5facd47ef556.md). В примере выше это `Проекты.Задачи`. Тип доступен на клиенте и сервере. Значения этого типа используются в качестве строк табличной части. Тип может иметь модуль.

Табличные части имеют следующие свойства:

- `Ид`
  
  —
  
  `Ууид`
  
  , идентификатор табличной части;
- `Имя`
  
  —
  
  `Строка`
  
  , имя табличной части;
- `Реквизиты`
  
  — обычные хранимые реквизиты; табличные части без явно заданных реквизитов не поддерживаются;
- `Индексы`
  
  — поля, соответствующие явно задаваемым реквизитам, а также стандартные поля
  
  `Контейнер`
  
  и
  
  `Индекс`
  
  .

В таблицах табличной части порождаются поля для всех явно заданных реквизитов табличной части, а также стандартные поля: `Контейнер`, `Индекс`, `НомерСтроки`.

Свойства реквизитов табличной части **Представление**, **НезаполненноеЗначение** и **Многострочная** используются при определении значения [`Авто`](../stdlib/auto-ru-1b14ed166f8e.md) в соответствующих им компонентах интерфейса.

## Табличные части в механизме отражения

Табличные части доступны в механизме отражения (свойство `ТабличныеЧасти: ЧитаемыйМассив<ОтражениеТабличнойЧастиСущности>` типа `ОтражениеОбъектнойСущности`).

Табличную часть сущности описывает тип `ОтражениеТабличнойЧастиСущности`. Тип имеет следующие свойства:

- `Владелец`
  
  —
  
  `ОтражениеСущности`
  
  , сущность, которой принадлежит табличная часть;
- `Ид`
  
  —
  
  `Ууид`
  
  , идентификатор табличной части;
- `Имя`
  
  —
  
  `ДвуязычнаяСтрока`
  
  , имя на двух языках;
- `Реквизиты`
  
  —
  
  `ЧитаемыйМассив<ОтражениеХранимогоСвойства>`
  
  , реквизиты сущности.

Методы типа `ОтражениеТабличнойЧастиСущности`:

- `ПолучитьТаблицу(): ОтражениеТаблицы`
  
  — позволяет получить таблицу, хранящую данные табличной части.

## Примеры работы с табличной частью

Измените видимость справочника **Проекты** на **ВПроекте**.

В демонстрационном приложении в справочник **Сотрудники** добавьте реквизит **Проект** типа `Проекты.Ссылка?` и табличную часть **ЭтапыРазработки** со структурой, аналогичной табличной части **Проекты.ЭтапыРазработки**.

Описание добавленных реквизитов в YAML-файле справочника **Сотрудники**:

```yaml
Реквизиты:
    # ...
    -
        Ид: b549642e-2b26-4b02-a4c0-a01b70a4063c
        Имя: Проект
        Тип: Проекты.Ссылка?
ТабличныеЧасти:
    -
        Ид: 3f563f07-a8c1-4331-94a6-dc449098f871
        Имя: ЭтапыРазработки
        Реквизиты:
            -
                Ид: 3322e6c8-54ea-46a8-bf1e-20ae2d0a2155
                Имя: НомерЭтапа
                Тип: Число
            -
                Ид: 38e28471-b018-47a7-995d-a4d47c2eec69
                Имя: ОписаниеЭтапа
                Тип: Строка
            -
                Ид: 66f0d4e8-43ff-4771-a68b-c844470bd14e
                Имя: ДатаНачала
                Тип: Дата
            -
                Ид: 9796d1fa-bf51-4a9b-8ef9-752e7b35220c
                Имя: ДатаОкончания
                Тип: Дата
```

1. Заполнение табличной части с помощью метода `ДобавитьНовый()` на основе данных другой табличной части:
  
  ```xbsl
  метод ЗаполнитьТабличнуюЧастьСПомощьюМетода()
      пер ТекущийПроект = Проект.ЗагрузитьОбъект()
      для СтрокаПроекта из ТекущийПроект.ЭтапыРазработки
          пер СтрокаЭтапа = ЭтапыРазработки.ДобавитьНовый()
          СтрокаЭтапа.НомерЭтапа = СтрокаПроекта.НомерЭтапа
          СтрокаЭтапа.ОписаниеЭтапа = СтрокаПроекта.ОписаниеЭтапа
          СтрокаЭтапа.ДатаНачала = СтрокаПроекта.ДатаНачала
          СтрокаЭтапа.ДатаОкончания = СтрокаПроекта.ДатаОкончания
      ;
  ;
  ```
2. Заполнение табличной части с помощью конструктора на основе данных другой табличной части:
  
  ```xbsl
  метод ЗаполнитьТабличнуюЧастьСПомощьюКонструктора()
      пер ТекущийПроект = Проект.ЗагрузитьОбъект()
      для СтрокаПроекта из ТекущийПроект.ЭтапыРазработки
          ЭтапыРазработки.Добавить(новый Сотрудники.ЭтапыРазработки(
              НомерЭтапа = СтрокаПроекта.НомерЭтапа,
              ОписаниеЭтапа = СтрокаПроекта.ОписаниеЭтапа,
              ДатаНачала = СтрокаПроекта.ДатаНачала,
              ДатаОкончания = СтрокаПроекта.ДатаОкончания
          ))
      ;
  ;
  ```
3. Изменение данных во всех строках:
  
  ```xbsl
  метод ИзменитьДанныеВоВсехСтроках()
      пер ТекущийПроект = Проект.ЗагрузитьОбъект()
      для СтрокаПроекта из ТекущийПроект.ЭтапыРазработки
          СтрокаПроекта.ОписаниеЭтапа = ""
      ;
  ;
  ```

## Пример обращения к табличной части с помощью языка запросов

Для табличной части порождается таблица языка запросов `ИмяЭлементаПроекта.ИмяТабличнойЧасти`. Таблица содержит следующие поля:

- Владелец
  
  —
  
  `ИмяЭлементаПроекта.Ссылка`
  
  , ссылка на запись, владеющую строками табличной части;
- Индекс
  
  —
  
  `Число`
  
  , индекс строки табличной части в рамках одного владельца;
- НомерСтроки
  
  —
  
  `Число`
  
  , номер строки табличной части в рамках одного владельца (индекс + 1);
- ИмяРеквизитаТабличнойЧасти
  
  —
  
  `ТипРеквизитаТабличнойЧасти`
  
  , поле с данными реквизита табличной части.

Пример использования:

```xbql
ВЫБРАТЬ
    Индекс,
    НомерСтроки,
    НомерЭтапа,
    ОписаниеЭтапа,
```

## Табличные части в контрактах сущностей

В контрактах сущностей поддерживается использование табличных частей. Для каждой табличной части в контракте сущности порождается контракт типа с именем `ИмяКонтрактаСущности.ИмяТабличнойЧасти`. Контракт доступен на клиенте и сервере. В таком контракте типа есть свойства для всех реквизитов табличной части, доступные на чтение и запись (если иное не указано в описании соответствующего реквизита табличной части контракта).

В объектах контрактов сущностей табличные части представлены одноименными свойствами с типом `ИзменяемыйМассив<ИмяКонтрактаСущности.ИмяТабличнойЧасти>`. Свойства доступны только для чтения. Если в контракте сущности есть табличная часть, во всех реализациях должна быть табличная часть с таким же именем и всеми реквизитами контракта.

## Выбор между табличной частью и реквизитом-коллекцией

Вместо табличной части вы можете использовать [реквизит-коллекцию](../data/collection-type-attribute-55d55dbeb248.md) и [хранимую структуру](data-model-description-d00b1811451a.md). Это может быть удобно в следующих случаях:

- нужно хранить множество неизменяемых значений (например, чисел или ссылок), при этом добавление дополнительной информации к значениям не планируется;
- если в проекте есть готовая хранимая структура, к которой не планируется добавление дополнительной информации, и нужно хранить множество таких структур.

Однако, если вам понадобится добавить дополнительную информацию в реквизит-коллекцию, то придется переносить данные и переходить к использованию табличной части. Например, если реквизит-коллекция имеет тип `Массив<МоеПеречисление>`, а вы хотите изменить его на `Массив<МояСтруктура>`, где `МояСтруктура` — это некая структура с двумя полями типа `Строка` и `МоеПеречисление`, то в этом случае «1С:Предприятие.Элемент» не сможет выполнить реструктуризацию таблиц базы данных и вам придется переносить данные самостоятельно.

Также рекомендуется использовать табличную часть в контракте сущности, если в реализациях планируется расширение состава полей. При использовании реквизита-коллекции сделать это не получится.

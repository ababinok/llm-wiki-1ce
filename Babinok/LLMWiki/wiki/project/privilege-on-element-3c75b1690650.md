## Документированный контракт и примеры

Элемент проекта, описывающий права на сущности.

Право на элемент — это право доступа, связанное с элементом проекта или с записью конкретного экземпляра сущности. Наличие права на элемент проверяется вручную разработчиком. После того как вы добавили в проект право на элемент, «1С:Предприятие.Элемент» создаст тип с именем [`{ИмяПраваНаЭлемент}`](../stdlib/privilegeonelementname-ru-6a4f6c8d3e71.md). Например, если в проекте есть право на элемент **ПравоНаКонтрагента**, то будет создан единственный тип — `ПравоНаКонтрагента`.

Данный тип представляет собой перечисление, наследующее базовый тип [`ПравоДоступа`](../security/accessprivilege-ru-ec1f634a9bdc.md). Не имеет модуля.

## Пример введения прав на изменение элементов справочника

Предположим, в проекте есть справочник **Контрагенты**. Требуется установить права таким образом, чтобы:

- изменять основные данные контрагента (имя, контакты и т. д.) имел право только руководитель;
- изменять статус сотрудничества с контрагентом имел право руководитель и менеджер.

Ранее мы добавили в приложение собственный ключ доступа с именем **КлючиГруппСотрудников**. Этот ключ имеет один параметр **Группа** типа **ГруппыСотрудников** (это добавленное нами перечисление с двумя элементами: **Менеджеры** и **Руководители**). Таким образом, мы сможем создать два экземпляра этого ключа, с помощью которых разделим всех пользователей на две группы.

Описание элемента проекта **ПравоНаЭлемент** может выглядеть следующим образом:

```yaml
ВидЭлемента: ПравоНаЭлемент
Имя: ПравоНаКонтрагента
Ид: 790c6e50-88af-4605-adf5-972fd690f217
Элементы:
  - Имя: ИзменениеОсновныхДанных
    Ид: ec7d57d6-ef35-44f6-921e-4eed68885a24
  - Имя: ИзменениеСтатусаСотрудничества
    Ид: d1482df1-b780-4937-9abb-b825ada6cf85
```

В данном примере мы создали у права два элемента — два наименования действий, которые планируется применять по отношению к объектам справочника **Контрагенты** и права на которые необходимо выдать.

В свойстве справочника **КонтрольДоступа** зададим значение **РазрешенияВычисляются**:

```yaml
КонтрольДоступа:
    Разрешения:
        ПравоНаКонтрагента.ИзменениеОсновныхДанных: РазрешенияВычисляются
        ПравоНаКонтрагента.ИзменениеСтатусаСотрудничества: РазрешенияВычисляются
        ПоУмолчанию: РазрешенияВычисляются
```

Выдача прав осуществляется при вычислении разрешений доступа на справочник. В модуле справочника, в обработчике вычисления разрешений, следует написать:

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступа(): Массив<РазрешениеДоступа>

    пер Разрешения: Массив<РазрешениеДоступа>   // массив для возврата разрешений доступа

    // Получить экземпляры ключа доступа
    пер КлючМенеджеров = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Менеджеры)
    пер КлючРуководителей = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Руководители)

    // Создать разрешение доступа
    Разрешения.Добавить(новый РазрешениеДоступа([КлючРуководителей], [ПравоНаКонтрагента.ИзменениеОсновныхДанных]))
    Разрешения.Добавить(новый РазрешениеДоступа([КлючМенеджеров, КлючРуководителей], [ПравоНаКонтрагента.ИзменениеСтатусаСотрудничества]))

    возврат Разрешения
;
```

Проверка прав осуществляется в обработчике **ПередЗаписью** в модуле объекта справочника:

```xbsl
@Обработчик
метод ПередЗаписью(До: Контрагенты.Данные, ПараметрыЗаписи: Контрагенты.ПараметрыЗаписи)
    если До.СтатусСотрудничества != СтатусСотрудничества
         Стд::КонтрольДоступа::КонтрольДоступа.ПроверитьПраво(Ссылка, ПравоНаКонтрагента.ИзменениеСтатусаСотрудничества)
    ;
;
```

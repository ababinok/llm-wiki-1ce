## Обзор

В простейшем случае «1С:Предприятие.Элемент» создает систему прав, которая не требует программирования.

## Документированный контракт и примеры

В простейшем случае «1С:Предприятие.Элемент» создает систему прав, которая не требует программирования. Права контролируются на уровне элементов проекта для нескольких предопределенных категорий пользователей.

> [!NOTE] примечание
> В приложении этот вариант может совмещаться с более сложным вариантом, использующим самостоятельное формирование разрешений и выдачу экземпляров ключей ([подробнее](manage-access-control-2ec0764ce511.md)).

## Предопределенные ключи доступа

В «Элементе» существует два предопределенных [вычисляемых ключа доступа](access-key-c2c3323f14bd.md), каждый из которых имеет единственный экземпляр:

- [`КлючДоступаДляВсех`](accesskeyforeveryone-ru-4a12798615d1.md)
  
  — этот экземпляр ключа
  
  «Элемент»
  
  автоматически выдает всем пользователям, в том числе анонимным;
- [`КлючДоступаДляАутентифицированных`](accesskeyforauthenticated-ru-10a3076a3d4e.md)
  
  — этот экземпляр ключа
  
  «Элемент»
  
  автоматически выдает всем пользователям приложения, кроме анонимных.

> [!NOTE] Кто такой анонимный пользователь
> Компоненты интерфейса [СтандартноеКлиентскоеПриложениеСРазделами](../interface/standard-client-application-with-sections-component-49da52beb720.md) и [ПроизвольноеКлиентскоеПриложение](../interface/custom-client-application-component-a5e093d01cdd.md) имеют свойство **РежимАутентификации**. Стандартно это свойство имеет значение **Аутентифицированный**, но вы можете установить его в значение **НеАутентифицированный**, и тогда пользователь не будет перенаправлен на страницу аутентификации при входе в приложение, то есть будет анонимным. Такого пользователя не будет в списке подключенных пользователей, и `Пользователи.ТекущийПользователь` будет возвращать `Неопределено`.

Перечисленные экземпляры ключей «Элемент» использует самостоятельно, об этом будет рассказано [далее](automatically-grant-permissions-to-user-groups-c39cf49a7075.md).

Кроме перечисленных ключей, в «Элементе» существует еще один предопределенный вычисляемый ключ доступа [`КлючДоступаПользователя`](useraccesskey-ru-3d9e14563e1e.md). Этот класс имеет параметр **Пользователь**. Благодаря этому параметру ключ имеет столько экземпляров (экземпляров класса), сколько существует подключенных пользователей. «Элемент» поддерживает уникальность экземпляров ключей по набору значений их параметров и, значит, для каждого пользователя она будет создавать свой уникальный экземпляр ключа. Например, экземпляр ключа для текущего пользователя:

```xbsl
пер ЭкземплярКлюча = новый КлючДоступаПользователя.Объект(Пользователи.ТекущийПользователь)
```

В отличие от перечисленных выше трех ключей, экземпляры ключа [`КлючДоступаПользователя`](useraccesskey-ru-3d9e14563e1e.md) «Элемент» самостоятельно только выдает пользователям, но никак не связывает с элементами проекта (не создает разрешения доступа). Вы можете самостоятельно создать разрешения, если ваша система прав построена таким образом, что конкретное право нужно ставить в соответствие конкретному пользователю, без промежуточных понятий типа «роль» и т. п. ([подробнее](manage-access-control-2ec0764ce511.md)).

## Построение автоматической системы прав

В автоматической системе прав права контролируются на уровне элементов проекта. Например, если чтение регистра сведений разрешено — значит, можно читать все его записи. Если чтение регистра сведений запрещено — ни одну из записей регистра сведений прочитать нельзя.

### Управление доступом в проекте

Каждый вид элементов проекта, для которого поддерживается управление доступом, имеет фиксированный набор прав, предоставляемый «Элементом». Например, **План обмена** имеет права **Создание**, **Чтение**, **Изменение**, **Удаление**.

Каждый элемент таких видов имеет свойство **КонтрольДоступа**. В этом свойстве вы можете перечислить, каким образом будет контролироваться доступ к тому или иному праву, например:

```yaml
КонтрольДоступа:
    Разрешения:
        Чтение: РазрешеноВсем
        ПоУмолчанию: РазрешеноАутентифицированным
```

Можно указать значение **ПоУмолчанию** — это специальное обозначение, которое подразумевает все права, не перечисленные явно, а также следующие способы контроля доступа:

- РазрешеноАутентифицированным
  
  ,
- РазрешеноВсем
  
  ,
- РазрешеноАдминистраторам
  
  .

### Вычисление разрешений и выдача ключей

Благодаря такому описанию элемента проекта «Элемент» автоматически запишет для него разрешения доступа со следующими экземплярами ключей:

```text
<Чтение: КлючДоступаДляВсех>
<Создание, Изменение, Удаление: КлючДоступаДляАутентифицированных>
```

В дальнейшем эта система прав доступа будет поддерживаться следующим образом:

- При подключении к приложению нового пользователя в обработчике события
  
  `ПослеПодключения`
  
  необходимо самостоятельно вызвать
  
  [пересчет экземпляров вычисляемых ключей доступа](recalculate-access-permissions-and-keys-8fbd0f5252bf.md)
  
  .
  
  «Элемент»
  
  сделает это автоматически только в том случае, если у пользователя заполнено свойство
  
  `Утверждения`
  
  .
- При изменении существующего пользователя также необходимо вызвать
  
  [пересчет экземпляров вычисляемых ключей доступа](recalculate-access-permissions-and-keys-8fbd0f5252bf.md)
  
  в обработчике события
  
  `ПослеИзменения`
  
  .
  
  «Элемент»
  
  сделает это автоматически только при обновлении свойства
  
  `Утверждения`
  
  пользователей.

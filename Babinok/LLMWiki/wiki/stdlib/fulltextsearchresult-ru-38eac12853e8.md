> Updated: 2026-10-05

Версия: `10.0`.

Роль: Программный тип XBSL.

Владелец: Std / FullTextSearch.

Имена для поиска: `РезультатПолнотекстовогоПоиска`, `FullTextSearchResult`, `Стд::ПолнотекстовыйПоиск::РезультатПолнотекстовогоПоиска`, `Std::FullTextSearch::FullTextSearchResult`.

## Обзор

Структура в которой содержится результат поиска.

## Документированный контракт и примеры

`Стд::ПолнотекстовыйПоиск::РезультатПолнотекстовогоПоиска` `Доступность: Сервер`

Структура в которой содержится результат поиска.

**Сравнение**

Структурное

Два экземпляра равны, если попарно равны все свойства.

## Иерархия типа

*Базовые типы:* [Объект](object-ru-9e351f286699.md)

## Свойства

### ВсегоНайдено

`Доступность: Сервер` `ТолькоЧтение`

```
ВсегоНайдено: Число
```

Сколько всего поисковый сервис нашел записей в индексе.

---

### НомерПервогоЭлемента

`Доступность: Сервер` `ТолькоЧтение`

```
НомерПервогоЭлемента: Число
```

Номер первого элемента текущей порции. Например, для второй страницы это значение будет равно значению ([РазмерСтраницы](pagesize-ru-5452a2dcfd84.md) + 1).

---

### НомерСтраницы

`Доступность: Сервер` `ТолькоЧтение`

```
НомерСтраницы: Число
```

Номер страницы (нумерация с единицы).

---

### Порция

`Доступность: Сервер` `ТолькоЧтение`

```
Порция: ЧитаемыйМассив<ЭлементРезультатаПолнотекстовогоПоиска>
```

Порция с результатами поиска. Размер порции не может превышать размера запрашиваемой страницы.

---

### ПорцияКлючей

`Доступность: Сервер` `ТолькоЧтение`

```
ПорцияКлючей: ЧитаемыйМассив<Сущность.Ключ>
```

Порция ключей поэлементно соответствующая порции результатов, то есть порядок и количество ключей, естественно, совпадает с элементами порции [Порция](fulltextsearchresult-ru-38eac12853e8.md).

---

### РазмерСтраницы

`Доступность: Сервер` `ТолькоЧтение`

```
РазмерСтраницы: Число
```

Количество элементов на одной странице.

---

### СлишкомМногоНайдено

`Доступность: Сервер` `ТолькоЧтение`

```
СлишкомМногоНайдено: Булево
```

`Истина`, если найдено больше, чем задано в ограничениях, в этом случае порция с результатами поиска возвращается пустая порция и вы должны сделать поисковый запрос более точным. По умолчанию ограничение установлено в 3 миллиона записей.

---

## Методы

### ПостроитьПредставление

`Доступность: Сервер` `Статический`

```
ПостроитьПредставление(
  ИсточникФрагментов: ФрагментыПолнотекстовогоПоискаПоСвойству|ЭлементРезультатаПолнотекстовогоПоиска|ЧитаемыйМассив<ФрагментПолнотекстовогоПоиска>|ЧитаемыйМассив<ФрагментыПолнотекстовогоПоискаПоСвойству>,
  РазрывТекстаВСередине: Строка = "... ...",
  РазрывТекстаСлева: Строка = "...",
  РазрывТекстаСправа: Строка = "...",
  РазделительСвойств: Строка = " ",
  ВключитьДополнительныеСвойства: Булево = Истина,
  ВключитьПредставленияСвойств: Булево = Истина,
  СокращатьТабличныеЧасти: Булево = Истина
): Строка
```

Строит представление записи в виде в виде цельной строки состоящей из серии фрагментов.

Аргументы:

- `ИсточникФрагментов`
  
  - Объект, откуда можно получить фрагменты. Принимает объекты следующих типов:
  
  - Объект типа
    
    [ЭлементРезультатаПолнотекстовогоПоиска](fulltextsearchresultitem-ru-4768069fde33.md)
    
    .
  - Объект типа
    
    [ФрагментыПолнотекстовогоПоискаПоСвойству](fulltextsearchfragmentsbyproperty-ru-5bbbf7ca692f.md)
    
    . Используется, чтобы построить представление только по одному свойству.
  - Читаемый массив объектов типа
    
    [ФрагментыПолнотекстовогоПоискаПоСвойству](fulltextsearchfragmentsbyproperty-ru-5bbbf7ca692f.md)
    
    . Вы можете передать отдельные, интересующие вас, свойства, выбрав их из объекта
    
    [ЭлементРезультатаПолнотекстовогоПоиска](fulltextsearchresultitem-ru-4768069fde33.md)
    
    .
  - Читаемый массив объектов типа
    
    [ФрагментПолнотекстовогоПоиска](fulltextsearchfragment-ru-a2dd318bc473.md)
    
    . Результирующий текст получится без читабельного названия свойства. Такой вариант подойдёт, если необходимо построить табличный вариант, в котором названия (представления) вынесены в отдельную колонку.
- `РазрывТекстаВСередине`
  
  - Строка для обозначения разрыва между двумя фрагментами одного свойства. Например, если у вас три фрагмента, значит разрывов два. Разрыв можно оформлять по-разному, вот наиболее популярные варианты:
  
  - текст...текст
  - текст… …текст
  - текст
    
    ...
    
    текст
- `РазрывТекстаСлева`
  
  - Строка для обозначения обрыва текста (значения свойства) слева. Даже если у вас всего один фрагмент, он может быть оборван (обрезан) и слева и/или справа.
- `РазрывТекстаСправа`
  
  - Строка для обозначения обрыва текста (значения свойства) справа.
- `РазделительСвойств`
  
  - Строка, которая используется для отделения свойств друг от друга. По умолчанию - это пробел, но это также может быть и текстовый переход на новую строку (\r\n) и переход на новую строку в html-тексте (
  
  ).
- `ВключитьДополнительныеСвойства`
  
  - Истина, если в общее представление необходимо добавить дополнительные свойства для расширения контекста. Также запись может быть найдена не по тексту, тогда будут добавлены несколько первых свойств без подсветки, они все считаются дополнительными и будут показаны.
- `ВключитьПредставленияСвойств`
  
  - Ложь, если требуется скрыть представления свойств и выводить только фрагменты значений.
- `СокращатьТабличныеЧасти`
  
  - Истина, если требуется выводить фрагменты по табличным частям в сокращённом (упрощённом) виде, а именно так: ПредставлениеСвойства: …Слово1… …Слово2… То есть, сокращённый вариант содержит только подсвеченные вхождения и представление свойства. Без сокращения представление результата поиска может быть перегружено значениями соседних ячеек, которые не расширяют контекст и не помогают лучше понять суть найденного.

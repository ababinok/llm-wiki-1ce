## Задача

Нужно выполнить HTTP-запрос, проверить ответ и прочитать JSON. Это маршрут по контрактам для серверной логики: `КлиентHttp`, `ЗапросHttp`, `ОтветHttp` и `СериализацияJson` документированы в серверном окружении. Для вызова из интерфейса отдельно сверяйте передачу исполнения.

## Порядок переходов

1. В `КлиентHttp` выберите фабричный метод вроде `СБазовымUrl()` и метод запроса `ЗапросGet()` или `ЗапросPost()`. В `ЗапросHttp` сверяйте заголовки, перегрузку `УстановитьТело()` и `Выполнить(Контекст: КонтекстHttp? = Неопределено): ОтветHttp`.
2. В полученном `ОтветHttp` используйте актуальное имя `КодСтатуса`. `КодСостояния` указан как прошлое имя. `Заголовки` дают заголовки ответа, а `Тело` имеет тип `ПотокЧтения`.
3. До чтения результата разберите код статуса и ожидаемое содержимое. Руководство HTTP отдельно описывает классы успешных ответов, ошибок клиента и ошибок сервера. Выбор допустимых статусов и схемы JSON определяется контрактом внешнего сервиса.
4. В `СериализацияJson` выберите подходящую перегрузку `ПрочитатьОбъект<ТипОбъекта>()`: источник может быть `ПотокЧтения`, `ЧтениеJson` или `Строка`. В документации рядом есть новая перегрузка «Версия 10.0 и выше» и устаревшая перегрузка «Версия 9.0 и ниже» с `Коллекция<Тип>`; версия страницы не делает старую сигнатуру применимой к 10.0.
5. Настройки чтения и тип результата сверяйте по контракту сериализации. Для потоковой навигации и смешанного режима переходите к руководству «Работа с JSON». Нельзя считать любое тело HTTP-ответа JSON-документом подходящего прикладного типа.

## Короткий пример ответа из справочника

```xbsl
исп Ответ = КлиентHttp.ЗапросGet("http://адрес").Выполнить()
знч КодСтатуса = Ответ.КодСтатуса
знч ContentType = Ответ.Заголовки.ПолучитьПервый("Content-Type")
```

Адрес демонстрационный. Добавление чтения JSON требует выбранного типа результата и настройки соответствующей перегрузки, а не догадки о структуре внешнего сервиса.

## Ошибки и ресурсы

Разделяйте код статуса полученного ответа, `ИсключениеHttp` при ошибке работы с внешним ресурсом и `ИсключениеЧтенияJson` при ошибке чтения JSON. Справочник сериализации, например, документирует исключение неоднозначного чтения; перечень исключений и условия нужно сверять для выбранного метода. Этот маршрут не утверждает, что каждый ошибочный статус автоматически вызывает исключение.

`ОтветHttp` реализует закрываемый ресурс. После конца потока тела он автоматически освобождает внутренние ресурсы; `Закрыть()` также закрывает поток тела. Для используемого способа чтения учитывайте это время жизни.

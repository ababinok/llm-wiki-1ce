## Документированный контракт и примеры

[Процесс интеграции](integration-process-project-element-fe0b29a88e3c.md) — это единица разработки, при помощи которой декларативно описывается взаимодействие информационных систем. Она представляет из себя схему, состоящую из узлов, маршрутов и [групп участников](../project/participant-groups-93f2250d5853.md). Узлы обозначают некое действие: возникновение сообщения, маршрутизацию, трансформацию, доставку. Маршруты обозначают движение сообщения из одного узла в другой. Группы участников представляют из себя одну или более информационных систем, с которыми «1С:Предприятие.Элемент» взаимодействует однотипно.

Чтобы создать элемент проекта, наведите на подсистему, для которой вы хотите создать новый элемент, и нажмите на значок **Новый**.

Создать новый компонент в навигаторе [Описание иллюстрации](../../raw/figures/a9e91b529854f270aff0224dea9a1d28ceec67ff9f85d11f2413a87cca0d0afe-c449cf7d22b470d4.md)

Введите или выберите из списка в появившемся диалоговом окне элемент **Процесс интеграции**.

Выбор элемента «Процесс интеграции» [Описание иллюстрации](../../raw/figures/988b8e43ddbce6fa4ca374839a411ae3988aa06f0c8c4a5113332183a347952f-6f3e3663b922cadc.md)

Задайте ему произвольное имя и нажмите **Ввод**. После создания элемента **Процесс интеграции** откроется окно редактирования схемы.



Если в проекте используется единственный справочник с контрактом [СправочникИнформационныхСистем](../data/information-systems-catalog-bf5a6760a09a.md), то в поле **СправочникУчастников** панели свойств процесса интеграции автоматически подставляется имя этого справочника. Если таких справочников более одного, то вам необходимо выбрать значение вручную из выпадающего списка.

Заполнение поля «СправочникУчастников» [Описание иллюстрации](../../raw/figures/aa4b070c5713d7dbfcab30b45b4ad170f4ead4785e36806b3fae05acdd944b65-3664f3e2d659a41d.md)

Чтобы добавить узел либо группу участников на схему, выберите элемент в палитре узлов и нажмите на произвольную область в окне редактора.

Редактор схемы процесса интеграции: узел выбирается в правой палитре и добавляется нажатием на свободную область схемы. [Описание иллюстрации](../../raw/figures/414e17811b8cf896be99af87b5ca227ffba33e43f25fa5f441bc95f091246328-a47c8957baeeceab.md)

Справа располагается панель **Свойства**. Здесь можно задавать необходимые свойства для каждого элемента схемы. К примеру, для узла **ГруппаУчастников** такими свойствами являются **Имя** и **Описание**.

В свойствах некоторых узлов необходимо указать обработчик. Например, для узла [**Транслятор**](translator-integration-scheme-node-2632b7c61610.md) следует заполнить поле **Преобразование**.



Для узла **Транслятор** в качестве обработчика указывается метод, который будет осуществлять трансформацию сообщений. Чтобы открыть модуль схемы, в котором находится код обработчика, нажмите на значок плюса.

В панели Свойства узла Транслятор доступны поля Имя, Описание и события ОбновлениеМетрик, Преобразование. Кнопка плюс справа от поля Преобразование открывает модуль для создания обработчика. При пустом значении показана красная диагностика «Имя не должно быть пустым». Подписи событий следует сопоставить с контрактом узла, а не считать отдельными методами интерфейса. [Описание иллюстрации](../../raw/figures/d4c7c2097288898230509bf5779dd215ec82f7a085d4621ab72bbb4adda4c588-2bd0ca601b4cbe73.md)

При нажатии на значок плюса открывается модуль процесса интеграции, а также создается метод с нужной сигнатурой, который назначается в качестве обработчика события. Для метода автоматически генерируется название по схеме `ИмяЭлемента + ТипОбработчика`, но при необходимости можно ввести название вручную. Вам останется только написать тело метода.

Среда создала незавершенную заготовку обработчика транслятора; пустой `возврат` подчеркнут как ошибка. [Описание иллюстрации](../../raw/figures/69dac880acb06e412e01279bd4f648645dd1bbd1e417423af1ba3551b52a5ebb-2f624ab3b02747a2.md)

Чтобы соединять узлы между собой, используются два вида коннекторов: **Маршрут** и **Связь**.

В палитре схемы интеграции в разделе «Другие» выделены коннекторы: «Маршрут» с черной сплошной стрелкой вправо и «Связь» с голубой пунктирной стрелкой вправо. [Описание иллюстрации](../../raw/figures/67ae80fa275cfbf0b3960fe1acb69ed5a24ec03f2daf69bdd6a303e73b7a8a16-ea54e6a00efe5b31.md)

Чтобы соединить узлы, воспользуйтесь одним из доступных способов:

- Последовательно выделите порты соединяемых узлов. Линия связи будет построена от выбранного порта к выбранному порту:

<summary>Пример соединения узлов «порт-порт»</summary>

Соединение «порт-порт»: выберите порт узла «JmsИсточник», затем порт узла «JmsНазначение». [Описание иллюстрации](../../raw/figures/d55c8be8069b3addf419865d583f8ba4235b775efa01d94f875395c455e1d32f-8128e6ac4a603e75.md)

</details>

- Последовательно выделите порт узла, который хотите соединить, и соединяемый узел. Линия связи будет построена от выбранного порта к ближайшему доступному порту:

<details>
<summary>Пример соединения узлов «порт-узел»</summary>

Соединение «порт-узел»: выберите порт узла «JmsИсточник», затем сам узел «JmsНазначение». [Описание иллюстрации](../../raw/figures/be9404ececa060cdc3c80d723c4c387b0e9707e6b1167c849e45098178b6ab11-0a8d868f07d26453.md)

</details>

- Выберите вид коннектора и последовательно выделите узлы, которые хотите соединить. Линия связи будет построена между ближайшими доступными портами:

<details>
<summary>Пример соединения узлов «узел-узел»</summary>

Соединение «узел-узел»: в палитре выберите «Маршрут», затем последовательно щёлкните по узлам «JmsИсточник» и «JmsНазначение». [Описание иллюстрации](../../raw/figures/3a131deb56ab4c78716f2e26fc8229ee513dd2a4e0e3010ab277f43c9156e94b-a1952d7b86088a1d.md)

</details>

**Связь** описывает движение сообщения от информационной системы в «1С:Предприятие.Элемент» и из нее. **Маршрут** обозначает движение сообщений между узлами схемы внутри «1С:Предприятие.Элемента». Сообщение может перемещаться строго в определенном направлении и не может вернуться к отправителю.

Пример маршрутизации: группа «ИБ» связана пунктирной стрелкой с «ИзБазы»; далее сплошной маршрут ведёт в «ВыборСпособаДоставки». Из него две ветки: «Xml2Json» → «ВHttp» и «Xml2Zip» → «НаFtp». Обе конечные ветки связаны с группой «Партнеры». Красные подписи различают «Связь» (пунктир между системой и узлом) и «Маршрут» (сплошная стрелка между узлами). В палитре перечислены источники и назначения FTP/JMS/Kafka/RabbitMQ/Канал1С/ОчередьШины, программный и файловый источники, таймер, файловое назначение, маршрутизатор по содержимому, Http, Sql, группа участников и транслятор.

## Обзор

Для описания взаимодействия «1С:Предприятие.Элемента» с информационными системами используется элемент проекта вида **Процесс интеграции**.

## Документированный контракт и примеры

Для описания взаимодействия «1С:Предприятие.Элемента» с информационными системами используется элемент проекта вида **Процесс интеграции**.

> [!WARNING] важно
> Данный элемент проекта недоступен в облачной версии «1С:Предприятие.Элемента».

Основная часть процесса интеграции — **схема** — состоит из узлов и связей. Она наглядно показывает движение сообщений от информационных систем-источников к информационным системам-получателям сообщений.

Схема процесса интеграции [Описание иллюстрации](../../raw/figures/ae870e9008d703960e972b1ded28630f913a765619b9ab04ef22de7631f5316f-077739211bc4969a.md)

Для построения схемы процесса интеграции используются узлы, маршруты между узлами, [группы участников](../project/participant-groups-93f2250d5853.md) и связи между узлами и группами.

Узлы обозначают действия: возникновение сообщения, маршрутизацию, трансформацию, доставку сообщения. Маршруты между узлами обозначают движение сообщения внутри «1С:Предприятие.Элемента». Связи обозначают движение сообщения от внешних информационных систем в «1С:Предприятие.Элемент» и из «1С:Предприятие.Элемента» к внешним информационным системам. Сообщение движется строго в определенном направлении и не может вернуться к отправителю.

Внешние по отношению к «1С:Предприятие.Элементу» информационные системы обозначаются на схеме в виде групп участников. Разные системы объединяются в одну группу, если они взаимодействуют с «1С:Предприятие.Элементом» однотипно. Например, несколько складов получают одинаковые сообщения, после чего сообщения отправляются на сайты партнеров. Для таких систем разработчик может указать на схеме одну группу участников «Склады», а после публикации проекта перейти в панель управления и добавить всех участников в созданную группу.

За одним узлом, созданным на схеме, может стоять множество узлов в режиме исполнения. К примеру, если на схеме есть узел **ФайлНазначение**, который соединен с группой участников, то после запуска процесса интеграции для каждой информационной системы, входящей в группу участников, будет создан свой собственный узел **ФайлНазначение**. Таким образом, сообщения из «1С:Предприятие.Элемента» будут независимо записываться в каталоги участников.

После того как вы создали процесс интеграции и опубликовали приложение на сервере, процесс интеграции не запускается сам по себе. Первоначально все процессы интеграции, существующие в проекте, находятся в остановленном состоянии. Чтобы начался обмен сообщениями, процессы интеграции нужно [запустить](start-and-stop-integration-processes-f21a2e3a6b7a.md).

Это можно сделать интерактивно в панели управления или программно с помощью метода `{ИмяПроцессаИнтеграции}.Запустить()`. Запуск и остановка процесса интеграции могут занять некоторое время.

При [остановке приложения](https://1cmycloud.com/console/help/element/10.0/docs/topics/stop-app/) «1С:Предприятие.Элемент» также останавливает все его процессы интеграции. При следующем запуске приложения все процессы интеграции, которые были запущены в момент остановки приложения, автоматически запустятся вместе с ним. Таким образом, в обычном сценарии работы запустить процесс интеграции нужно всего один раз — в начале.

## Функциональность и логика работы с данными

Элемент проекта **Процесс интеграции** предоставляет следующую функциональность:

- [Взаимодействие с платформой «1С:Предприятие»](collaboration-with-1c-enterprise-ddb3ea8a9b69.md)
  
  В «1С:Предприятии» для взаимодействия с «1С:Предприятие.Элементом» предназначены объекты конфигурации вида [СервисИнтеграции](https://its.1c.ru/db/v83doc#bookmark:dev:TI000002299). В «1С:Предприятие.Элементе» для настройки интеграции используются узлы вида [Канал1СИсточник](channel-1c-source-ddb853b7d45d.md) и [Канал1СНазначение](channel-1c-destination-3c02e5ef031f.md).
- [Взаимодействие с SAP NetWeaver Process Integration (SAP PI)](sap-netweaver-process-integration-46227d6dbc1b.md)
  
  Для настройки асинхронной интеграции с SAP PI в «1С:Предприятие.Элементе» используются узлы [ОчередьШиныИсточник](esb-queue-source-b4517ca0b7f6.md) и [ОчередьШиныНазначение](esb-queue-destination-983a8f6d448b.md).
- [Маршрутизация сообщений](../project/message-routing-0ed0227e2454.md)
  
  Узел вида [МаршрутизаторПоСодержимому](content-based-router-7ec306486ecb.md) определяет, в какие узлы из тех, что идут непосредственно за этим узлом, должны попасть сообщения. Для этого у узла есть событие `ОбработчикОпределенияПолучателей`, в котором вы можете сформировать набор таких узлов. Если обработчик не задан, то сообщение попадет во все узлы, стоящие после маршрутизатора и связанные с ним.
- [Трансформация сообщений](../project/message-transformation-9d32bf730382.md)
  
  Узел вида [Транслятор](translator-integration-scheme-node-2632b7c61610.md) используется для изменения сообщения. Изменение сообщения происходит в обработчике события `ОбработчикПреобразования`.
- [Группы участников](../project/participant-groups-93f2250d5853.md)
  
  Группы участников представляют из себя одну или более информационных систем, с которыми «1С:Предприятие.Элемент» взаимодействует одинаковым образом.
- [Хранение недоставленных сообщений](../project/undelivered-message-channel-54c826eff47a.md)
  
  Сообщения, которые не были доставлены получателям из-за какой-либо ошибки или по причине устаревания, хранятся в [канале недоставленных сообщений](../project/undelivered-message-channel-54c826eff47a.md).
- [Вычисляемые свойства процесса интеграции](computable-properties-4e2a3d4fac9d.md)
  
  Как правило, свойства узлов процесса интеграции задаются в среде разработки. Однако некоторые свойства могут быть заданы только после создания процесса интеграции, уже во время его исполнения. Существует два способа, чтобы задать или переопределить свойства узлов процесса интеграции во время исполнения приложения. Первый — это использовать параметры процесса интеграции, второй — воспользоваться информацией, которая хранится в служебном справочнике [ИнформационныеСистемы](../data/information-systems-catalog-bf5a6760a09a.md).
- [Отправка сообщений в файлы](../project/save-messages-as-files-e575990edc25.md)
  
  Для сохранения тела сообщения в файле используется узел процесса интеграции вида [ФайлНазначение](file-destination-d85acc8e8f96.md). Файл создается в каталоге, который определяется свойством **Каталог**. Имя файла определяется либо свойством **ИмяФайла**, либо в обработчике `ОбработчикОпределенияИмени`.
- [Получение сообщений из файлов](../project/retrieve-message-from-file-6152df025666.md)
  
  Для получения сообщений из файлов в локальной файловой системе или в локальной сети используется узел процесса интеграции вида [ФайлИсточник](file-source-6a2c5cde7609.md). Он порождает сообщения из файлов, расположенных в указанном каталоге. В этом случае в теле сообщения будет находиться сам файл.
- [Подключение AMQP-систем](amqp-connection-3210085a03a8.md)
  
  Чтобы отправлять и получать сообщения, внешние системы должны подключиться к серверу по протоколу AMQP версии 1.0. Для этого используются узлы процесса интеграции вида [Канал1СИсточник](channel-1c-source-ddb853b7d45d.md) и [Канал1СНазначение](channel-1c-destination-3c02e5ef031f.md).
- [Взаимодействие с СУБД](sql-integration-scheme-node-5a40dd42f89e.md)
  
  «1С:Предприятие.Элемент» имеет функциональность для взаимодействия с внешними СУБД. Для подключения к базе данных используется узел процесса интеграции вида [Sql](sql-integration-scheme-node-5a40dd42f89e.md). При помощи этого узла сообщение из «1С:Предприятие.Элемента» может быть записано в базу данных. Кроме того, «1С:Предприятие.Элемент» может отправить запрос в СУБД и из полученного ответа сформировать сообщение.
- [Взаимодействия с JMS-брокером сообщений Apache ActiveMQ](jms-source-bae52122e91b.md)
  
  Для получения сообщений от JMS-брокера Apache ActiveMQ используется узел вида [JmsИсточник](jms-source-bae52122e91b.md). Сообщения получаются из указанной очереди или темы. Для отправки сообщений в указанную очередь или тему JMS-брокера Apache ActiveMQ используется узел [JmsНазначение](jms-destination-98fff5bc1508.md).
- [Взаимодействие с брокером сообщений RabbitMQ](rabbitmq-source-a0583a4c910a.md)
  
  Для получения сообщений из брокера RabbitMQ используется узел вида [RabbitMqИсточник](rabbitmq-source-a0583a4c910a.md). Сообщения получаются из заданной очереди, привязанной к указанному обмену (Exchange). Для отправки сообщений в RabbitMQ используется узел [RabbitMqНазначение](rabbitmq-destination-a1987e89c36f.md).
- [Взаимодействие с брокером сообщений Apache Kafka](collaboration-with-apache-kafka-487d00ac9525.md)
  
  Для получения сообщений из брокера Apache Kafka используется узел вида [KafkaИсточник](kafka-source-9421d1c05319.md). Сообщения получаются из указанного топика. Для отправки сообщений в целевой топик используется узел [KafkaНазначение](kafka-destination-507e7e00fc5c.md).
- [Отправка запросов по протоколу HTTP](http-integration-scheme-node-d9bde3031004.md)
  
  Для выполнения запросов по протоколу HTTP к внешнему ресурсу используется узел вида [Http](http-integration-scheme-node-d9bde3031004.md). Результат запроса может быть обработан следующими узлами на схеме.
- [Программная отправка сообщений](programmatic-source-ca1eb29ad522.md)
  
  Узел [ПрограммныйИсточник](programmatic-source-ca1eb29ad522.md) используется для отправки сообщений в процесс интеграции в коде.
- [Генерация сообщений через равные промежутки времени](timer-integration-scheme-node-2cb64f4f6337.md)
  
  Для создания сообщений через равные интервалы времени используется узел [Таймер](timer-integration-scheme-node-2cb64f4f6337.md).
- [Сохранение сообщений в процессе обмена](../project/channel-that-stores-messages-ec1bd8365d50.md)
  
  В процессе перемещения от одного узла схемы к другому сообщение может быть потеряно в результате ошибки или аварии (выключения питания, обрыва сети и т. п.). Чтобы избежать потери сообщения, в «1С:Предприятие.Элементе» можно использовать узлы, для которых создаются очереди сообщений либо маршрут со свойством [канала, хранящего сообщения](../project/channel-that-stores-messages-ec1bd8365d50.md). В результате все сообщения, которые попадают в данный узел либо проходят по данному маршруту, будут сохранены в специально созданной очереди сообщений. Их копии будут лежать в очереди до тех пор, пока сообщение не достигнет следующего узла схемы.
- [Хранение доставленных сообщений](../project/delivered-messages-d48678a57c96.md)
  
  В «1С:Предприятие.Элементе» для некоторых узлов имеется возможность хранить сообщения, которые были в них доставлены. Длительность хранения доставленных сообщений настраивается в карточке процесса интеграции, в свойствах соответствующего узла.

## Разрешения

Для процессов интеграции действуют разрешения приложения. Задать или изменить их можно в [панели управления](https://1cmycloud.com/console/help/element/10.0/docs/topics/configure-app-permissions/) — изменения вступают в силу сразу после сохранения и применяются ко всем запущенным процессам интеграции.

Если при старте процесса интеграции в каком-либо узле отсутствует необходимое разрешение, узел-источник не создает новых сообщений, а узел-назначение не отправляет сообщения во внешнюю систему — поступившие в него сообщения шины направляются в недоставленные без повторных попыток доставки. В журнале событий регистрируется событие `ОшибкаПроверкиРазрешенийПроцессаИнтеграции` с указанием узла, участника процесса интеграции, разрешения и ресурса, для которого нет разрешения.

Если в процессе обработки сообщения в узле пути маршрута разрешение также отсутствует, сообщение сразу отправляется в недоставленные без повторных попыток доставки с причиной **Нет разрешения**.

> [!NOTE] примечание
> **Нет разрешения** отличается от ошибки **Доступ запрещен**, которая сигнализирует об ошибке аутентификации или авторизации на удаленной стороне соединения.

Для [RabbitMQ](rabbitmq-source-a0583a4c910a.md), [Kafka](collaboration-with-apache-kafka-487d00ac9525.md), [JMS](jms-destination-98fff5bc1508.md) проверка разрешений выполняется в момент установки соединения.

Свои особенности есть у узлов [ФайлИсточник](file-source-6a2c5cde7609.md) и [FtpИсточник](ftp-source-ae3508a82260.md). В них можно выбрать [действие после чтения](afterreadaction-ru-d489572a6de4.md) — удаление или переименование файла. Если у приложения есть разрешение только на чтение файла, но отсутствует разрешение на его удаление или переименование, файл будет прочитан, а сообщение — отправлено один раз. Файл помещается в репозиторий идемпотентных файлов, чтобы при повторном запуске процесса он не читался заново.

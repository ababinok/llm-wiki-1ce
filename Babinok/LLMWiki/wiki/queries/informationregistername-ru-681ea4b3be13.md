## Примеры

В примере ниже показано, как выбрать настройки пользователя из непериодического регистра сведений **НастройкиПользователя** для указанного пользователя (значение поля **Пользователь** равно параметру `%Пользователь`):

```xbql
ВЫБРАТЬ
    НастройкиПользователя.Пользователь Как Пользователь
    НастройкиПользователя.ТемаОформления КАК ТемаОформления,
    НастройкиПользователя.РазрешенияУведомлений КАК РазрешенияУведомлений,
    НастройкиПользователя.ПоказыватьОнлайн КАК ПоказыватьОнлайн,
    НастройкиПользователя.ДатаРегистрации КАК ДатаРегистрации,
    НастройкиПользователя.КлючЗаписи КАК КлючЗаписи
ИЗ
    НастройкиПользователя КАК НастройкиПользователя
ГДЕ
    Пользователь == %Пользователь
УПОРЯДОЧИТЬ ПО
    ДатаРегистрации
```

## Поля

### {ИмяИзмерения}

`Ключевое поле`

```
{ИмяИзмерения}: ТипИзмерения
```

Значение измерения записи регистра сведений.

---

### {ИмяРесурса}

```
{ИмяРесурса}: ТипРесурса
```

Значение ресурса записи регистра сведений.

---

### {ИмяРеквизита}

```
{ИмяРеквизита}: ТипРеквизита
```

Значение реквизита записи регистра сведений.

---

### Период

`Ключевое поле`

```
Период: Дата
```

Период, к которому относится запись регистра. Существует только для периодических регистров сведений.

---

### СледующийПериод

`Вычисляемое поле`

```
СледующийПериод: Дата
```

Значение поля **Период** из следующей записи с такими же значениями измерений или максимальное значение типа поля **Период**, если следующей записи нет. Существует только для периодических регистров сведений с флагом `ХранитьСледующийПериод` = `Истина`.

#### Примеры

В примере ниже показано, как получить курсы валют из регистра сведений **Курсы** вместе с периодом их действия (временным промежутком, в рамках которого они были действительны):

```xbsl
знч Запрос = Запрос{
        ВЫБРАТЬ 
            Период КАК ПериодС,
            ВЫБОР 
                КОГДА СледующийПериод == Дата{Максимум} ТОГДА "По настоящее время"
                ИНАЧЕ СледующийПериод
            КОНЕЦ КАК ПериодПо, // Исключая границу
            Валюта,           
            Курс
        ИЗ
            Курсы
        УПОРЯДОЧИТЬ ПО
            Валюта, 
            Период
        }
```

Чтобы проверить наличие следующей записи в таблице периодического регистра сведений, можно сравнить значение поля **СледующийПериод** с максимальным значением типа поля **Период**. Если они равны — значит, следующей записи не существует.

Получить максимальное значение типа поля **Период** можно с помощью встроенного строкового литерала соответствующего типа: `Тип{Максимум}` (как в запросе выше).

В приведенном примере используется регистр с установленным флагом `ХранитьСледующийПериод` = `Истина`.

### КлючОсновногоФильтра

`Вычисляемое поле`

```
КлючОсновногоФильтра: ИмяРегистраСведений.КлючОсновногоФильтра
```

Структура, описывающая ключ основного фильтра регистра сведений. Добавляется, даже если нет измерений, включаемых в основной фильтр. Имеет тип [ИмяРегистраСведений.КлючОсновногоФильтра](../data/informationregistername-mainfilterkey-ru-b2b91a95f0cf.md).

---

### КлючЗаписи

`Вычисляемое поле`

```
КлючЗаписи: ИмяРегистраСведений.КлючЗаписи
```

Содержит значения измерений записи регистра сведений (и стандартного поля **Период** для периодических регистров сведений). Используется для указания на конкретную запись. Имеет тип [ИмяРегистраСведений.КлючЗаписи](../data/informationregistername-recordkey-ru-2cfab865dace.md).

#### Примеры

В примере ниже показано, как выбрать данные конкретной записи из регистра сведений **Курсы** по её ключу (значение поля **КлючЗаписи** равно параметру `%КлючКурсаРубля`):

```xbql
ВЫБРАТЬ
    Период,
    Курс,
    Валюта,
    СледующийПериод
ИЗ
    Курсы 
ГДЕ
    КлючЗаписи == %КлючКурсаРубля
```

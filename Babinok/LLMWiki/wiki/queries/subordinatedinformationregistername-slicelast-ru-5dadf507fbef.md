## Обзор

Виртуальная таблица, которая возвращает последние внесенные в регистр сведений записи для каждой комбинации измерений.

## Документированный контракт и примеры

`Версия 10.0 и выше`

Виртуальная таблица, которая возвращает последние внесенные в регистр сведений записи для каждой комбинации измерений. Существует только для периодических регистров сведений.

Для расчета таблицы используются только активные записи.

Для регистров, у которых свойство элемента проекта `ХранитьСледующийПериод` = `Ложь`:

- виртуальная таблица имеет более сложную реализацию с использованием подзапроса;
- поле
  
  [СледующийПериод](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md)
  
  вычисляется в момент обращения к виртуальной таблице;
- для параметра
  
  Период
  
  можно использовать только константные выражения;
- добавляется параметр
  
  Фильтр
  
  .

**Параметры:**

- Период:
  
  [Дата](../stdlib/date-ru-d160dc00114c.md)
  
  ?
  
  Дата, на которую будут получаться записи для формирования среза.
  
  Срез будет формироваться на основе активных записей, у которых значение поля
  
  [Период](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md)
  
  меньше или равно указанному значению параметра. При наличии нескольких записей с одинаковыми значениями измерений в результате будет использоваться запись с самым большим значением периода.
  
  Если значение параметра
  
  `Неопределено`
  
  , возвращаются последние актуальные записи (с максимальным значением поля
  
  [Период](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md)
  
  на текущий момент).
  
  Для регистров, у которых свойство элемента проекта
  
  `ХранитьСледующийПериод`
  
  =
  
  `Ложь`
  
  , для значения параметра можно использовать только константные выражения.
  
  Если установлен флаг
  
  `ХранитьСледующийПериод`
  
  =
  
  `Истина`
  
  , то в качестве значения параметра можно также использовать неконстантные выражения, в том числе поля других таблиц, доступные для использования в условии соединения этой таблицы.

## Примеры

В примере ниже показано, как выбрать цены товаров из регистра **Цены**, актуальные на указанный **ПараметрПериод**:

```xbql
ВЫБРАТЬ
    Цены.Товар КАК Товар,
    Цены.Цена КАК Цена,
    Цены.Регистратор КАК Регистратор,
    Цены.СледующийПериод КАК СледующийПериод,
    Цены.РеквизитПользователя КАК РеквизитПользователя
ИЗ
    ЦеныВРублях.СрезПоследних(%ПараметрПериод) КАК Цены
УПОРЯДОЧИТЬ ПО
    Товар,
    Цена
```


Ссылка на документ, которому подчинена запись регистра сведений.

### Индекс

`Вычисляемое поле`

```
Индекс: Число
```

Индекс (начиная с 0) записи регистра сведений в наборе записей, подчиненных документу, указанному в поле [Регистратор](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md).

---

### НомерСтроки

`Вычисляемое поле`

```
НомерСтроки: Число
```

Порядковый номер (начиная с 1) записи регистра сведений в наборе записей, подчиненных документу, указанному в поле [Регистратор](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md).

---

### СледующийПериод

`Вычисляемое поле`

```
СледующийПериод: Дата
```

Значение поля [Период](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md) из следующей записи с такими же значениями измерений или максимальное значение типа поля [Период](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md), если следующей записи нет. Существует только для периодических регистров сведений.

#### Примеры

В примере ниже показано, как получить актуальную позицию работника из регистра сведений с флагом `ХранитьСледующийПериод` = `Ложь` **ПозицииРаботников** на указанную дату `%ДатаСреза` для указанного работника `%РаботникСсылка` (используя виртуальную таблицу `СрезПоследних`) и определить дату снятия с позиции:

```xbsl
метод ПолучитьПозициюРаботника(ДатаСреза: Дата, РаботникСсылка: Работники.Ссылка)
    знч Запрос = Запрос{
            ВЫБРАТЬ
                Период,
                Работник,
                Позиция,
                Регистратор,
                СледующийПериод
                СледующийПериод
            ИЗ
                ПозицииРаботников.СрезПоследних(%ДатаСреза, Работник == %РаботникСсылка)
            }
    знч Результат = Запрос.Выполнить().Единственный()
    знч Позиция = Результат.Позиция
    знч ДокументНазначения = Результат.Регистратор
    знч СледующийПериод = Результат.СледующийПериод
;
```

Чтобы проверить наличие следующей записи в таблице периодического регистра сведений, можно сравнить значение поля [СледующийПериод](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md) с максимальным значением типа поля [Период](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md). Если они равны — значит, следующей записи не существует.

Получить максимальное значение типа поля [Период](subordinatedinformationregistername-slicelast-ru-5dadf507fbef.md) можно с помощью встроенного строкового литерала соответствующего типа: `Тип{Максимум}`.
